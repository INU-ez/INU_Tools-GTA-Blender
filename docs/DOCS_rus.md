## Установка

1. Скачайте папку `INU_tools/` (или zip-архив)
2. Поместите `INU_tools/` в папку аддонов Blender:
   - **Windows:** `%APPDATA%/Blender Foundation/Blender/<версия>/scripts/addons/`
   - **Linux:** `~/.config/blender/<версия>/scripts/addons/`
   - **macOS:** `/Users/<имя>/Library/Application Support/Blender/<версия>/scripts/addons/`
3. Blender → Edit → Preferences → Add-ons → включите **"INU_tools(gta_sa)"**

**Требования:**
- Blender 2.83+ (4.2+ для установки через extensions.blender.org)
- Itera Tools 3 — опционально, для vertex lighting

**Сохранение настроек:** все пути (Game Root, IDE, IPL, IMG, текстуры) и пресеты (профили, пресеты материалов и ID, дефолты флагов пайплайна) лежат в пользовательской папке данных с доступом на запись — `paths.json` плюс подпапки по фичам. По умолчанию это пользовательская папка расширений Blender; можно указать любую свою через **Properties → Scene → INU Tools → Папка пресетов** (см. [Папка пресетов](#папка-пресетов)). Настройки переживают обновления аддона и восстанавливаются автоматически при запуске Blender.

## Быстрый старт

### Экспорт модели в GTA SA

1. Назови объекты так, чтобы тип определялся сам — впиши `LOD` в имя LOD-модели (`LODmybuilding`), а `_DFF` / `_COL` ставь, когда модель и её коллизия делят одно базовое имя (см. [Определение типа модели](#определение-типа-модели-dff--lod--col))
2. Задайте **Model ID**, **TXD Name**, **Draw Distance** в свойствах объекта (`obj.inu`)
3. Выделите все, нажмите **Export All** → выберите папку
4. Результат: `mybuilding.dff`, `mybuilding.col`, `LODmybuilding.dff`, `mybuilding.txd`

### Импорт карты GTA SA

1. Укажите **Game Root** — папку GTA SA (например `D:\GTA San Andreas\`)
2. Нажмите **Извлечь ресурсы** — извлечёт DFF/COL/текстуры из IMG в `.inu_cache/` (один раз, ~8 с на район)
3. Нажмите **Импорт карты** — импорт только из кеша, ~30 с на район размера LA

### Горячие клавиши

| Клавиша | Действие |
|---------|----------|
| `Shift+T` | Открыть/закрыть UV Editor |
| `Shift+A` | Добавить модель GTA SA (Army.dff / Admiral.dff) |

### Плавающие окна

Свободно-плавающее GPU-окно даёт одним кликом доступ к самой частой операции без скролла N-sidebar:

| Окно | Что внутри | Открыть |
|---|---|---|
| **Проверка** | Результаты pre-export проверки (кватернионы, paintjob, UV-аним × ночные vcol, парность _ok/_dam) с one-click фиксами | 🪟 в шапке панели **Проверка** |

Окно можно **таскать** (за любую не-кнопку), **сворачивать** в title bar, **пинить к workspace** (Lock icon — отображается только в пинённом workspace'е), использует палитру текущей темы Blender. Позиция сохраняется в `.blend`.

> Прежде плавающих окон было пять (Info / Import-Export / Освещение / IDE-IPL-IMG + Проверка). Их кнопки-🪟 убраны из шапок панелей Экспорт / Prelight / IDE-IPL-IMG — осталась только кнопка окна **Проверка**. Код самих флоатеров остался в аддоне, из UI убраны только кнопки.

### Сжатые меню

UI сжат — вместо россыпи кнопок теперь dropdown-меню в нескольких местах:

| Где | Что было | Что стало |

## Поддержка нескольких игр (III / VC / SA)

Активная игра выбирается вверху панели **GTA Tools** в N-sidebar — три кнопки **San Andreas / Vice City / GTA III**. Все экспортёры, валидация и lint используют этот выбор. По умолчанию — San Andreas (основная цель аддона). Импорт авто-детектит игру по файлу и либо переключает сцену (если она пустая), либо предупреждает.

### Матрица форматов

| Формат | III (RW 3.3) | VC (RW 3.5) | SA (RW 3.6) |
|---|:-:|:-:|:-:|
| **DFF** чтение | ✅ авто-детект по RW версии | ✅ | ✅ |
| **DFF** запись | ✅ (без SA-only Night vcols, Pipeline, UV anim) | ✅ (без Night, Pipeline) | ✅ |
| **COL** | ✅ `COLL` v1 | ✅ `COL2` v2 | ✅ `COL3` v3 |
| **TXD** | ✅ (RW lib_id под игру) | ✅ | ✅ |
| **IDE** | ✅ (5-полевой OBJS, без `txdp`/`2dfx`) | ✅ (5-полевой, без `2dfx`) | ✅ (multi-mesh, `txdp`, `2dfx`) |
| **IDE cars** | 12 колонок | 13 (+ `anims`) | 15 (+ flags, wheel split) |
| **IDE peds** | 7 колонок | 10 (+ anim_file, radio×2) | 14 (+ flags, voice×3) |
| **IPL inst** | 12 колонок (scale, без interior) | 13 (interior + scale) | 11 (lod_index, без scale) |
| **IPL binary** | — | — | ✅ `bnry` |
| **IMG** | ✅ VER1 (раздельные `.dir` + `.img`) | ✅ VER1 | ✅ VER2 |
| **IFP** | ✅ ANPK chunked | ✅ ANPK | ✅ ANPK + ANP3 сжатый |
| **2DFX хранится** | в IDE `2dfx` секции | в IDE `2dfx` | в DFF chunk 0x253F2F8 |
| **2DFX типы** | Light, Particle, Strobe | + PedAttractor, SunGlare | + Type 5 (IDE-only) |
| **Surface IDs** | 0–84 (clamp на запись) | 0–85 | 0–178 |
| **model_id потолок** | 6500 | 8500 | 19999 |

### Переключение игр

**Вручную:** кликни III / VC / SA в шапке GTA Tools.

**Автоматически при импорте:** в file-browser dialog'ах импорта (DFF/COL/IPL/TXD/IMG) есть дропдаун «Игра» с дефолтом **Авто**. Авто читает заголовки/колонки файла и проставляет правильную игру на импортируемые объекты. Если найденная игра отличается от активной в сцене:

- **Свежая сцена (game=SA + 0 INU-объектов):** scene авто-флипается на найденную.
- **Заполненная сцена:** WARNING — `Импортированный файл = VC, но активная игра сцены = SA. Переключи вкладку GTA Tools на «VC»`. Переключение остаётся ручным чтобы избежать сюрпризов в mixed-game проектах.

**При экспорте:** каждое окно экспорта начинается с блока **«Экспорт в игру:»** в самом верху — ряд PC/Mobile над рядом SA/VC/III — он задаёт RW-версию (III 3.3 / VC 3.4 / SA 3.6) и раскладку колонок IPL/IDE на выходе. По умолчанию = игра проекта (её ставит авто-детект при импорте); можно переопределить прямо перед экспортом.

**Текстуры GTA III (авто R↔B):** III использует палитровые (PAL8) текстуры, палитра которых хранится в BGRA. Импорт авто-свопит R↔B **только** для палитровых D3D8-текстур, поэтому цвета III приходят верными (кора коричневая, а не синяя). VC (16-бит) и SA не трогаются — без ручной галки, признак берётся из `platform_id` каждой текстуры.

### Cross-game перевод данных (lossy)

Когда импортируешь III файл и экспортишь в SA (или наоборот), writer прогоняет данные через канонические категории, чтобы байты соответствовали ожиданиям целевого engine.

- **COL surface IDs** — 12 канонических категорий (TARMAC, GRASS, WOOD, METAL, GLASS, …) через `core/surface_translate.py`. 178 SA-поверхностей схлопываются в ~12 категорий при cross-game; SA → VC → SA теряет под-типы вроде `GRASS_SHORT` vs `GRASS_LONG`. Каждый материал несёт `inu.col_source_game` так что перевод срабатывает только при реальной смене игры.
- **IDE objs.flags** — биты значат разное в разных играх. Пример: бит `0x20` в III/VC = `IGNORE_LIGHTING`, в SA — только для анимированных. `core/ide_flag_translate.py` переводит через 19 канонических категорий. UI показывает только чекбоксы валидные для активной игры (III=6, VC=10, SA=15).
- **PEDS cars_can_drive** — VC вставил `normal` в bit 0, сдвинув позиции III на +1. `core/ped_mask_translate.py` re-mapит через канонические class-имена. `IdePed.source_game` тагает импортированных peds.

### Validate Scene — cross-game предупреждения

Когда сцена нацелена на III/VC, но объекты несут SA-only фичи, **Проверка перед экспортом** их флагает:

- `model_id > vanilla_max` (потребует FLA)
- `has_night_vcols` (SA-only RW extension)
- `has_multi_mesh_lod` (downgradeится в single-mesh)
- `has_uv_anim_material` (III-only; UV anim требует RW 3.5+)
- `fx_2dfx_ids` вне per-game allowlist

### Известные ограничения

- **Full map round-trip — только для SA.** III/VC модеры могут импортить vanilla DFF/COL/TXD/IDE/IPL/IMG по отдельности, но Map Import pipeline (district auto-split, bulk IMG rebuild) изначально написан под SA data layout.
- **Asset Library Builder — SA-only.** Future work — нужны III/VC source parser'ы.
- **IFP** — ANP3 (сжатый int16) родной для SA; III/VC авто-downgradeятся в ANPK с warning'ом если забудешь переключить формат экспорта.
- **2DFX импорт для III/VC IDE** создаёт placeholder Empty'и (позиция + тип + цвет), с raw type_params stashed на Empty для byte-identical re-export. Per-type Blender-prop mapping (corona texture, particle name, attractor behaviour) частичный — Light и Particle wired; PedAttractor / SunGlare / Strobe re-emit'ятся через stashed params.

## Готовые рецепты (workflows)

Каждый рецепт — это конкретная задача от и до: от «что лежит в Blender» до «что появляется в игре».

### Рецепт: Кастомное здание (DFF+COL+LOD+TXD)

**Цель:** добавить статичный объект (дом, прop, забор) в карту GTA SA.

1. **Подготовь меши** в Blender:
   - HD-меш с уникальными UV → переименуй в `myhouse_DFF`
   - LOD (упрощённый, ~30% полигонов) → `myhouse_LOD`
   - Collision (грубый, всё в треугольниках) → `myhouse_COL`
2. **На HD-меше** Properties → Object → INU Tools:
   - Model ID: 18000 (свободный из 18000-19999)
   - TXD Name: `myhouse`
   - Draw Distance: 299
3. **На COL-меше** Properties → Material → COL Surface Type: выбери тип (Asphalt / Concrete / Glass / ...)
4. **Текстуры** на материалах HD — назначь PNG/JPG/TGA как Image Texture (можно перетащить из проводника).
5. **Выдели все три меша** → N → **Экспорт / Импорт** → **Импорт** → **Экспорт** не нажимай (для batch — отдельная кнопка):
   - В секции **«Массовый экспорт»** включи галки `DFF`, `COL`, `LOD`, `TXD`
   - **«В папку»** → выбери папку
6. **Получишь:** `myhouse.dff`, `myhouse.col`, `myhouse_LOD.dff`, `myhouse.txd`
7. **В игру:** скопируй `.dff` и `.col` в `gta3.img` (через IMG Tool / IMG Manager), `.txd` тоже туда.
8. **IDE entry:** добавь в `gta.dat` через панель **IDE / IPL / IMG** → IDE → **Добавить**.
9. **IPL placement:** положи объект в сцене где надо → **IPL** → **Экспорт** в нужный `.ipl` или **Карта** → **Экспорт карты**.

**Подводные камни:**
- LOD ID = HD ID + 1 (auto), либо вручную с суффиксом `LODmyhouse` — IDE flags = 4
- Если `myhouse.txd` не появляется в игре — нажми **IMG Rebuild** (см. memory `IMG Rebuild stale`)

### Рецепт: Кастомная машина с damage variants

**Цель:** машина, у которой при крушении меняются части (`_dam` варианты).

1. **Базовая модель:** `bonnet`, `bumper_lf`, `bumper_rf`, `chassis`, `door_lf`, ...
2. **Создать damage-варианты:** N → **Машины** → **Создать _dam** на выделенной части (например `bonnet`). Получишь `bonnet_dam` — это будет деформированная версия.
3. **Деформируй `_dam`** в Edit Mode (вмятины, гнутый металл).
4. **Проверка пар:** **Машины** → **Проверить пары** — операция выводит отчёт о всех парах `_ok/_dam` в сцене.
5. **Hierarchy:** все части привязаны к `chassis_dummy`. Колёса — к `wheel_*_dummy`. Это критично для физики игры.
6. **Damage states preview:** **Показать: OK / Dam / Оба** — переключает видимость пар в Blender для визуальной проверки.
7. **Экспорт:** выдели всю иерархию (alt+click на корне → выделение детей) → **Экспорт DFF** через menu.
8. **vehicle.txd / vehicle.col:** обычно общие для всех машин. Используй **Общий TXD** toggle в правой панели **Экспорт TXD** диалога.
9. **IDE entry в `vehicles.ide`:** секция `cars` — handling_id, wheel_id и т.д. (см. таблицу в **IDE**).

**Подводные камни:**
- Нужны строго имена `xxx_ok` / `xxx_dam` (разделитель `_dam`, не `_damage`)
- Wheel scale в IDE влияет на физику, не на визуал

#### Paintjob (Pay'n'Spray альтернативные раскраски)

GTA SA умеет менять текстуру кузова машины при покупке paintjob'а в Pay'n'Spray. Технически это **подмена текстуры** на лету: игра берёт текстуру `<vehname>_paintjob1` или `<vehname>_paintjob2` из vehicle.txd и подставляет вместо основной.

**Workflow в INU:**
1. На материале кузова в **Properties → Material → GTA Material → Paintjob (Pay'n'Spray)** заполни оба слота:
   - **Раскраска 1** — изображение для `<base>_paintjob1`
   - **Раскраска 2** — изображение для `<base>_paintjob2`
   где `<base>` — имя основной текстуры (того что назначено как Image на материале).
2. Кнопка **✓** (рядом с заголовком) запускает **Validate Paintjobs**: проверяет что у всех материалов с paintjob'ами заполнены оба слота и есть основная текстура.
3. При экспорте TXD оба альтернативных файла автоматически добавляются в архив с правильными именами.
4. В игре paintjob применяется через скрипт (Pay'n'Spray) — никакого ручного указания имён.

**Подводные камни:**
- Нужны **оба** слота — игра молча игнорирует paintjob если не хватает одного из двух
- Имена альтернатив рассчитываются от **подключённой** Image-ноды материала. Если у материала нет видимой Image — INU пропустит paintjob (валидатор это покажет)
- Размеры альтернативных текстур должны совпадать с основной (иначе игра растянет / обрежет)

### Frame Hierarchy Editor

**Где:** N → GTA Tools → **Иерархия фреймов** (видна когда выделен любой объект)

**Что делает:** показывает дерево детей активного объекта + 6 операторов для безопасного редактирования DFF Frame List:

| Кнопка | Что делает |
|---|---|
| **Rename** | Переименовать активный фрейм (popup). Ставит `dff_frame_write_name=True` чтобы новое имя попало в DFF при экспорте |
| **Set Parent** | Активный объект становится родителем для остальных выделенных. Сохраняет world-transform, сбрасывает `matrix_parent_inverse` в identity (DFF requirement) |
| **Unparent** | Снять parent с выделенных, мировая позиция сохраняется |
| **Validate Vehicle** | Проверка против vanilla SA шаблона машины (`chassis_dummy`, `wheel_lf_dummy` и т.д.). Сообщает о пропущенных и подозрительных именах в System Console |
| **Validate Ped** | Проверка против 31-кости шаблона педа (case-sensitive: `Pelvis`, `R UpperArm`...) |
| **Зеркало L↔R** | Для выделенных с `_lf`/`_lb` в имени создаёт зеркальные `_rf`/`_rb` копии (X отражён). Если зеркало уже существует — пропускает |

**Когда использовать:**
- Делаешь машину с нуля → собрал основу с `_lf` → клик «Зеркало L↔R» → пол-машины готово
- Импортировал DFF из GTA3/VC и переименовываешь под SA-стандарт
- Перед экспортом машины/педа → клик Validate, читаешь System Console чтобы поймать опечатки до игры

**Подводные камни:**
- Validate Vehicle игнорирует регистр (`Wheel_LF`, `wheel_LF` = одно), но игра требует строго `wheel_lf_dummy`. Validate Ped — case-sensitive (там exact match)
- Set Parent работает на любых типах (MESH/EMPTY/ARMATURE) — для DFF-фреймов важно чтобы parent был тоже DFF-фрейм, а не случайный объект сцены

### Рецепт: Скиннутый персонаж (Skinned Ped)

**Цель:** заменить ped на свою модель.

1. **Импорт vanilla `cs_player.dff`** как референс — увидишь иерархию из 31 кости.
2. **Меш одет в Armature** через Object → Parent → With Automatic Weights, либо вручную через Vertex Groups.
3. **Совпадение имён костей** с vanilla скелетом критично — `Pelvis`, `Spine`, `Spine1`, `Neck`, `Head`, `R UpperArm`, ... Проверка: **Проверка** → **Validate Action Bones**.
4. **Vertex weights:** макс 4 кости на вершину (GTA SA limit). Лишние снимаются автоматически при экспорте.
5. **Экспорт:** **Экспорт DFF** → имя `cs_myped.dff`.
6. **IDE peds entry:** `peds.ide` → секция `peds`.
7. **Animations:** все стандартные анимации (`ped.ifp`) применяются автоматически — главное чтобы имена костей совпадали.

**Подводные камни:**
- Если меш «лежит плашмя в игре» — проверь rest_quat (см. memory `IFP export round-trip fix`)
- Если кости не двигаются — это `bl_quat` rotation order, проверь **Validate Action Bones**

### Рецепт: Animated Map Object (мельница, кран, пропеллер)

**Цель:** статичный объект на карте у которого крутится одна или несколько частей (лопасти мельницы, стрела крана, флюгер, дверь ворот, лопасти вентилятора).

INU автоматизирует **три артефакта** которые игре нужны:

| Файл | Что внутри |
|------|------------|
| `<base>.dff` | Frame-иерархия + HAnim PLG + меши |
| `<base>.ifp` | Анимация с tracks-ами на имена кости |
| IDE `anim` запись | `model_id, model_name, txd_name, anim_file, drawdist, flags` |

---

#### Полный пайплайн

**1. Подготовка мешей**

Раздели объект на **статичную часть** (`mill_base`) и **анимированную** (`mill_blades`). Назови коротко (см. правила ниже). На анимированной меше выстави **Model ID** в Object → INU Tools → Model ID.

**2. Создание rig'а через пипетку**

Открой `N → GTA Tools → Анимации → таб «Объекты»`. В боксе **Animated Map Object** работает пипетка.

| Состояние | Действие |
|-----------|----------|
| Rig нет, выделен меш | Подсказка «Статика: `<имя>`». Жми пипетку → клик по **анимированному мешу** в viewport. Rig создаётся: активный меш → root (статика), picked → pivot1 (анимированный). |
| Rig уже есть | Подсказка «Target rig: `<root_name>`» + radio «Куда» (К pivot / К root). Пипетка → клик по следующему мешу → парентится в выбранную ветку. |

Результирующая иерархия:
```
mill_root           Empty (ARROWS)    bone_id=0   ← корень
├── mill_base                                      ← статичный меш
└── mill_pivot1     Empty (SPHERE)    bone_id=1   ← вращается
    └── mill_blades                                ← анимированный меш
```

**3. Настройка pivot'а**

Выдели pivot (`mill_pivot1`) → появится бокс **«Настройки: mill_pivot1»** с live-edit слайдерами:

- **Ось вращения:** Z (лопасти) / Y (пропеллер) / X (шлагбаум)
- **Оборотов за цикл:** 1
- **Длительность:** 60 кадров
- **Цикличность:** ✓

**4. Multi-part rig (опционально)**

Кнопка **«+Pivot»** в том же боксе → создаёт `mill_pivot2`. Пипеткой парентишь к нему второй анимированный меш. В IFP попадут **оба** track'а в одной анимации.

**5. Validate**

Кнопка **«Validate»** в том же боксе — проверяет иерархию, bone_ids, Action'ы, парентинг. Проблемы выводятся в Info area.

**6. Export**

Сверху в табе «Объекты» — кнопка **`DFF+IFP+IDE`**. Откроется диалог:

- **Папка / Базовое имя / TXD / Model ID / Draw distance** — настройки выхода
- **Дописать IDE запись:** ✓ — добавит в `anim`-секцию файла из `Scene → INU Tools → IDE Path`
- **Имя IFP** + **Режим IFP** (Дополнить / Перезаписать) — для бандлинга нескольких rig'ов в один файл

Перед экспортом можно выделить **любой объект rig'а** (Empty / pivot / меш) — экспортёр найдёт rig автоматически.

**7. Размещение в игре**

1. **DFF + TXD + IFP** → все три файла **в `gta3.img`** (НЕ в loose-папку `anim/`!)
2. **Rebuild Archive** в IMG-туле
3. **IPL** — размести через `Object IDE/IPL` → IPL Export. Игра анимирует везде где есть `inst <model_id>` запись.

#### 🚨 Правила и ограничения

**Эти 4 пункта обязательны — нарушение крашит игру или ломает анимацию:**

| Правило | Что будет если нарушить |
|---------|------------------------|
| **Длина имени модели ≤ 12 символов** | Крэш `0x534134` (access violation в HAnim parser) при появлении модели в радиусе draw distance |
| **Имя анимации в IFP = `model_name` в IDE** | Игра не найдёт анимацию → молча не применит (без крэша). INU делает автоматом, но если правишь IDE руками — следи. |
| **IFP должен лежать в `gta3.img`** | Streaming не сканирует loose-файлы в `anim/` для map objects. IFP должен быть **внутри** IMG-архива. |
| **IDE-запись в секции `anim`** (не `objs`) | Игра загрузит как статичный объект, IFP не применит. INU автоматом ставит в `anim`. |

**Прочие важные моменты:**

- **Model ID на статичном меше = `0`** — только анимированный меш получает реальный ID
- **Имя rig'а наследуется от первого меша** при пипетке. Хочешь префикс `mill` — переименуй первый меш в `mill_base` ДО пипетки.
- **Кнопка «Экспорт»** в том же табе — это standalone IFP операция для armature. Для Empty-rig используй **`DFF+IFP+IDE`**.

#### 🛑 Подводные камни (диагностика)

**Crash при появлении модели:**

| Симптом | Что проверить |
|---------|---------------|
| Игра закрывается без сообщения | 1) Длина имени ≤ 12? 2) IDE-запись в `anim`? 3) IFP в `gta3.img` (не в `anim/`)? 4) Rebuild IMG после замены? |
| Crash log говорит `0x534134` | Имя модели/кости слишком длинное — переименуй короче |
| Crash log говорит другой адрес | Проблема не в анимации — изолируй: временно перенеси запись в `objs` (флаг=0). Если стартует → копай в анимации. Если падает → проблема в другом моде. |

**Модель грузится, но анимации нет:**

| Симптом | Что проверить |
|---------|---------------|
| Имя анимации в IFP = `'????????'` (вопросы) | Был Action с кириллицей. INU теперь форсит ASCII имя, переэкспортируй. |
| Animation name ≠ model name | Проверь что 2-е поле IDE (`model_name`) совпадает с именем анимации внутри IFP |
| Дубликат имени в нескольких IDE | Удали одну из записей — один model_name на весь проект |
| Забыл Rebuild Archive | После замены файла в IMG **обязательно** Rebuild |

**DFF stepping (анимация рывками):**
- Кватернионы не нормализованы. В v2.0.0 пофиксено через `bl_quat.normalize()`. Если на старой версии — обнови или переэкспортируй после обновления.

#### 🔬 Технические детали (для разработчиков)

INU автоматически выставляет всё что нужно — обычному пользователю эту секцию читать не обязательно. Но если что-то пошло не так и хочется понять как именно — вот что делается под капотом:

**DFF:**
- HAnim PLG на root с полным bone tree + минимальный HAnim на каждом pivot
- `bone_type` в bone list: `[0, 1]` для 2-х костей, `[0, 3, 0, ..., 1]` для большего числа (точное совпадение с ванильным RW)
- `frame.flags = 0x20003` на root (без этого HAnim hierarchy walker валит игру)
- ATOMIC `flags = 5` (render + collision)
- DFS-сортировка: Empty с `inu_bone_id` идут первыми → pivot становится `idx=1` (как в ванилке)

**IFP:**
- Формат **ANP3** (SA compressed, совпадает с counxref.ifp / airport.ifp)
- `bone_id = -1` для всех костей (игра матчит по имени фрейма, не по ID)
- Первый keyframe нормализуется в `t=0.0` через `(frame - frame_start) / fps`
- Root исключён из IFP — `inu_animobj_empty_root` skip-ится

**Skinned ped'ы:** Empty-rig только для **map-объектов**. Скиннутые персонажи используют armature + IK-rig флоу (`ik_rig.py`).

### Рецепт: Анимация IFP с round-trip проверкой

**Цель:** создать кастомную анимацию для ped и записать в IFP.

1. **Импорт скелета:** `cs_player.dff` или твой кастомный с armature.
2. **Импорт референс-IFP:** **Анимации** → **Импорт IFP** → `ped.ifp`. Получишь все standard действия как Blender Actions.
3. **Создай новое действие:** в Action Editor (Dope Sheet) → New → анимируй keyframes.
4. **Назови действие** так как игра будет вызывать (например `ANIM_DANCE_LOOP`).
5. **Round-trip проверка перед экспортом:** **Проверить round-trip** — экспортирует и читает обратно, сравнивает. Защищает от регрессий типа «лежит плашмя».
6. **Экспорт:** **Экспорт IFP** → отдельный файл, либо **Добавить в IFP** → доклеить в существующий.
7. **Live preview:** включи **Preview ●** — анимация играет в viewport без перехода в режим animation.

**Поддерживаемые форматы:** ANP3 (default GTA SA), ANPK (GTA3/VC), ANP2.

**Подводные камни:**
- Если в игре анимация рывками — проверь `kf.time` единицы (canonical = seconds)
- Source format сохраняется при импорте — экспорт по умолчанию пишет в исходном формате

### Рецепт: IK Rig для SA peds

**Цель:** анимировать персонажа GTA SA в режиме IK (тяни ступни / кисти, всё остальное доводит обратная кинематика) вместо ручной FK-крутки каждой кости.

**Где:** N → GTA Tools → **Анимации** → таб **CHAR** → **Add IK Rig** (на выделенный Armature).

**Что делает Add IK Rig:**
- Создаёт control-кости **внутри той же Armature** (никаких внешних Empty или вспомогательных rig'ов): на запястьях/ступнях — IK target кубики, на локтях/коленях — pole-маркеры, на голове/торсе — control-кости, плюс `Root` master-control в основании.
- Накидывает `IK` constraint на руки/ноги (chain length=2, target — control-куб), `Copy Rotation` на голову/торс/кисть/ступню (нужно для сохранения rest pose).
- **Brute-force pole_angle калибровка**: проходит несколько углов и выбирает тот при котором локоть/колено остаётся в исходном положении — работает с любым `bone roll` (vanilla SA или custom скин).
- **FK → IK bake**: если на armature уже есть Action — все его keyframe'ы конвертируются в ключи на новых control-bones (visual_key bake). Старая анимация играет идентично, но теперь редактируется через IK.
- Custom-shape всех control-bones — wireframe кубики, цветом по теме (по умолчанию зелёный THEME09).

**Размер и видимость кубов:**
- В Анимации → **Дополнительно** есть слайдер **Множитель размера** (общий) и **Смещение куба руки/ноги** (отдельно для конечностей).
- 4 toggle'а: `Руки/ноги`, `Локти/колени`, `Голова/торс`, `Корень` — скрывают/показывают разные группы control-bones (видимость через `bone.hide`, не удаление).

**Floor limiter (`INU_Ground` plane):**
- В **Дополнительно** → **Пол** → `Создать INU_Ground` → появляется dev-текстурированная плоскость 10×10 м с `dev_anim.png`.
- Все foot IK targets автоматически получают `Floor` constraint с offset = `gtatools_floor_offset` (по умолчанию 0.05 м). Ступни не проваливаются под пол.

**Bake & Clear IK** — перед экспортом IFP:
1. Запекает текущий IK-результат обратно в FK keyframes на deform-bones (visual_key).
2. Удаляет все control-bones, IK constraints, Copy Rotation.
3. Action остаётся идентичным визуально, но работает на чистом FK — IFP-экспорт не должен видеть control-bones (иначе игра падает с лишними костями).

**Workflow:**
1. Импорт ped DFF (`cs_player.dff` или свой) → Armature + меш.
2. **Add IK Rig** на Armature → готов к работе.
3. В Pose Mode — двигай только зелёные кубики, не deform-bones.
4. Когда анимация готова → **Bake & Clear IK** → **Экспорт IFP**.

**Подводные камни:**
- POSE vs REST: если делаешь `Add IK Rig` пока armature в pose-position-not-rest — control-кости создадутся не в том месте. Перед Add: Pose → Clear All Transforms.
- Вручную не двигай deform-bones кисти/ступни после Add — это перетрёт IK target положение.
- На скинах с custom bone roll FK→IK bake может «извести» старые ключи — поэтому brute-force pole_angle помогает, но иногда нужна ручная подгонка `pole_angle` после.
- `Bake & Clear IK` визуально не отличается от исходного FK — проверяй scrub'ом таймлайна перед экспортом.

### Рецепт: Профили N-sidebar (наборы видимых панелей)

**Цель:** скрыть лишние панели в зависимости от того что делаешь — **«сейчас работаю над машиной»** не нужны Map Workflow и Water Geometry, а **«делаю карту»** наоборот не нужна Vehicles панель.

**Где:** N → GTA Tools → шапка панели «GTA Tools» — dropdown **Профиль** (по умолчанию `ALL` = все панели видимы).

**Что делает:**
- Профиль = **JSON-файл** в `<addons>/INU_Preset/profiles/<name>.json` со списком `order` (порядок панелей) и `hidden` (что спрятать).
- При выборе профиля → `is_panel_visible(idname, profile)` фильтрует `poll()` каждой панели + `bl_order` устанавливает порядок.
- Состояние профиля живёт на Scene-проперти `gtatools_profile`, сохраняется с .blend.

**Создание своего профиля:**
1. Dropdown **Профиль** → `+` → popup с двумя списками:
   - Слева — все панели аддона
   - Справа — порядок (drag-pick: клик в списке → пункт уехал в порядок)
2. **👁** напротив панели — скрыть/показать.
3. **Имя профиля** + **Описание** → **Создать**.
4. JSON автоматически сохранён → доступен в dropdown.

**Редактирование/удаление:** dropdown → `▾` (edit) или `−` (delete).

**Шаринг между членами команды:** скопируйте JSON из `INU_Preset/profiles/` → друг кладёт к себе → видит профиль в dropdown.

**Built-in профиль `ALL`:** показывает всё, не редактируется/не удаляется. На него происходит fallback если JSON битый или профиль не найден.

**Подводные камни:**
- Профили — **визуальные**, не запрещают использовать панели. Если нужно «скрыть от других» опции — это не инструмент для прав доступа.
- Reorder применяется при следующем рисовании панели — иногда видно «прыжок» при первом клике.
- Имя профиля валидируется: запрещены `/`, `\`, `..`, длина <100 символов (защита от path traversal).

### Рецепт: Vertex Colors / Prelight для здания

**Цель:** статичное освещение «запечь» в vertex colors здания, чтобы интерьеры выглядели атмосферно без real-time света.

1. **Lighting** (N → GTA Tools → **Lighting**) → **Prelight** подпанель.
2. **Создать Day/Night атрибуты:** в секции **Цветовые атрибуты** клик `Day/Night`. Получишь два color attribute layer — для дневного и ночного освещения.
3. **Поставь источники света** в Blender (Sun + Spot для окон).
4. **Запечь:** **Запечение** → **С тенями** (raycast). Запечётся в активный атрибут (Day или Night).
5. **Переключение Day↔Night** — выбираешь активный, пере-запекаешь с другим освещением.
6. **Контроль яркости:** **V offset** — глобальное смещение брайтнес.
7. **Per-layer контроль:** **Слои Vertex Color** — composite из нескольких layers с opacity/contrast/brightness.
8. **Превью в Blender:** **Show preview** (HIDE_OFF icon) — переключает между renderable и flat-show.
9. **Экспорт DFF** автоматически включит Day и Night колора в чанки `prelit` + `extra_vert_colors`.

**Подводные камни:**
- Если в игре вертекс-цвета мерцают «как прилайт» — снять `Modulate Color` в DFF Flags (см. memory `Modulate Color flicker`)
- LightMap через UV2 — отдельная фича, не путать с vertex colors

### Рецепт: Размещение объекта на карте через IPL

**Цель:** разместить кастомный объект в конкретной точке карты GTA SA.

1. **Объект уже в IDE** (см. рецепт «Кастомное здание»).
2. **В Blender** перенеси объект в нужную позицию (loc/rot — мировые координаты GTA SA, Z=up).
3. **Map панель** (или **IDE / IPL / IMG** → IPL) → проверь что у объекта правильный `Model ID` в `obj.inu`.
4. **Экспорт IPL:** **IDE / IPL / IMG** → **IPL** → **Экспорт** → выбери `.ipl` файл.
5. **Map auto-split:** для больших карт включи `auto_split` toggle, `cell_size=256` — экспорт автоматически разделит на районы.
6. **gta.dat:** добавь IPL в `gta.dat` (`IPL gta3\custom\myhood.ipl`).
7. **Binary IPL:** для compiled-карт (gta_int.img) — **Экспорт** → toggle **Binary IPL** в правой панели диалога.

**Подводные камни:**
- Coordinates GTA SA: X=East, Y=North, Z=Up — Blender совпадает по умолчанию
- LOD link: lod_index в IPL — глобальный индекс (не относительный) другого объекта в том же IPL

### DFF (Модели)

| Кнопка | Оператор | Описание |
|--------|----------|----------|
| Импорт DFF | `gtatools.import_dff` | Импорт .dff файла с мешем, материалами, UV |
| Экспорт DFF | `gtatools.export_dff` | Экспорт выделенного меша в .dff (GTA SA v3.6.0.3) |

**Экспорт включает:** геометрию, материалы, vertex colors (Day/Night), UV карты, нормали, 2DFX эффекты, BinMesh PLG.

**Авто TXD:** при импорте DFF автоматически импортирует .txd из той же папки.

**Импортировать 2DFX:** тумблер при импорте DFF (одиночный Импорт, окно Import All и драг-дроп). Создаёт пустышки-эффекты 2DFX, зашитые в DFF — лампы/короны, частицы, ped attractor, sun glare, знаки и т.д. По умолчанию вкл; выключи, чтобы импортировать геометрию без эффектов.

> 💡 **Пример — импорт одной модели:** File → Import → GTA SA DFF → выбери `admiral.dff`. Аддон распарсит геометрию, материалы, UV. Если рядом лежит `admiral.txd` — текстуры применятся автоматически.

> 💡 **Пример — экспорт одного меша:** выдели меш → N → Экспорт / Импорт → **Экспорт DFF** → выбери путь → сохраняется с текущими материалами и vertex colors.

#### Лимиты формата DFF (uint16 / uint8)
RenderWare пакует индексы треугольников и счётчики в маленькие типы — для **одной геометрии (Atomic)** действуют жёсткие лимиты:

| Поле | Тип | Максимум |
|---|---|---|
| Вершин | u16 (индекс в `<4H>` треугольника) | 65 536 |
| Треугольников | — | 65 536 |
| Материалов | u16 (material-индекс в треугольнике) | 65 536 |
| UV-слоёв | u8 (биты 16-23 во флагах) | 255 (SA рендерит макс 2) |
| Костей в Skin PLG | u8 | 255 |

Если экспортируемый меш превышает лимит — экспорт сразу вернёт понятную ошибку, например:
```
admiral.dff: геометрия #0: 78432 вершин — RenderWare хранит индексы треугольников
в uint16 (максимум 65536 вершин). Разбей меш на части или упрости (Decimate).
```

**Обхода нет**: лимит зашит в сам формат и в движок RenderWare. Выходы — разбить меш на несколько `model_id`, либо упростить геометрию.

### COL (Коллизия)

| Кнопка | Оператор | Описание |
|--------|----------|----------|
| Импорт COL | `gtatools.import_col` | Импорт .col с типами поверхностей |
| Экспорт COL | `gtatools.export_col` | Экспорт в формате COL3 |
| Сгенерировать COL | `gtatools.auto_col` | Построить коллизию из выделенной модели — **выпуклая оболочка** или **габаритный бокс** |

**Сгенерировать COL** (`gtatools.auto_col`, кнопка «Сгенерировать COL» в секции Импорт/Экспорт): выделяешь модель — создаётся редактируемый меш `<имя>_COL`, либо **выпуклая оболочка**, либо осевой **габаритный бокс**. Меш помечается `inu.type='COL'` и идёт в обычный COL-экспорт; его можно доработать вручную, как любую COL.

Экспорт COL записывает ID типов поверхностей и держит геометрию в модель-локале. Запекается **масштаб** объекта, но **не поворот** — поворот во вьюпорте это размещение (оно уходит в IPL), в геометрию коллизии он не пишется, и COL совпадает с DFF под одним размещением IPL.

> 💡 **Пример:** создай куб, назови `mybuilding_COL`, назначь материал с `col_mat_index = 0` (дефолтный асфальт) в Properties → Material → **COL Surface Type**. Выдели → **Экспорт COL** → получишь `mybuilding.col` с правильным материалом поверхности.

#### Лимиты формата COL (uint16)
COL2/COL3/COL4 хранит счётчики и индексы как **uint16**, поэтому **на одну модель** действуют жёсткие лимиты:

| Поле | Максимум |
|---|---|
| Вершин | 65 536 |
| Треугольников | 65 535 |
| Сфер / боксов | 65 535 каждых |
| Shadow mesh (вершин/граней) | те же лимиты |
| `model_id` в заголовке | 65 535 |

Если меш крупнее — экспорт сразу вернёт понятную ошибку вида:
```
collision.col: 'collision': 78432 треугольников — COL формат поддерживает максимум 65535.
Разбей меш на части или упрости коллизию (Decimate).
```

**Обхода нет**: лимит зашит в сам формат и в движок RenderWare. Выходы — разбить меш на несколько `model_id` или применить Decimate (для коллизий норма — до 5–10k трисов).

### TXD (Текстуры)

| Кнопка | Оператор | Описание |
|--------|----------|----------|
| Импорт TXD | `gtatools.import_txd` | Извлечение текстур и привязка к материалам |
| Экспорт TXD | `gtatools.export_txd` | Сборка текстур в .txd архив |

**Compression backend:** pure-numpy DXT-энкодер встроен в аддон (`core/dxt.py`) — векторизованный BC1/BC3, ~×7 быстрее старого cluster-fit на текстурах ванильного SA. Никаких внешних бинарников. В Scene properties есть селектор `gtatools_dxt_backend` для экспериментального `bpy.gpu` compute-shader варианта.

**Поддерживаемые форматы:** DXT1 (непрозрачные), DXT3 (резкая альфа), DXT5 (плавная альфа). Автоопределение по альфа-каналу.

> 💡 **Пример — быстрая сборка TXD:** меш с 3 текстурами (кирпич, окно с альфой, логотип) → выдели → **Экспорт TXD** → получишь `.txd` где кирпич DXT1, окно DXT5, логотип DXT3 — формат выбран автоматически по альфа-каналу каждой.

**Дописать в существующий TXD (2.1.0).** В диалоге экспорта (и в Export All) есть галка **«Дописать в существующий»**. Если выбранный `.txd` уже есть — текстуры сцены **добавляются/обновляются** в нём (совпадение по имени, регистронезависимо), а **все остальные текстуры файла (от других моделей) сохраняются байт-в-байт**. Без галки файл перезаписывается целиком.

> ⚠ **Подводный камень — кэш и правки «на месте».** Закодированный DXT кэшируется по `session_uid+размер`, поэтому раньше правка пикселей «на месте» (Image Editor) могла уйти старой версией. Теперь кэш сбрасывается на каждый ручной экспорт — но если правишь текстуру **нодой материала** (Hue/Sat и т.п.), экспорт это **проигнорирует**: он читает сам Image-датаблок, а не результат нод. Запеки/сохрани правку в саму картинку.

> ⚠ **Подводный камень — тёмные/светлые текстуры (битность).** `image.pixels` у **16/32-битных** PNG (и EXR) лежат в scene-linear, у **8-битных** — уже в sRGB. Экспортёр это учитывает (конвертит linear→sRGB только для float-картинок). Если текстура в TXD выглядит не так по яркости — проверь битность исходника и цветовое пространство (sRGB vs Non-Color).

### Экспорт всего (Batch)

| Кнопка | Оператор | Описание |
|--------|----------|----------|
| Экспорт всего (В папку) | `gtatools.export_all` | Массовый экспорт DFF+COL+LOD+TXD |

Выдели модель + её LOD + коллизию (тип определяется автоматически — `LOD` в имени = LOD, `_DFF`/`_COL` разделяют модель и её коллизию), нажми Экспорт всего, выбери папку.

**Переключатели:** DFF / COL / LOD / TXD — включить/выключить каждый формат.

**Pipeline:** None / Building (Day/Night vertex colors) / Reflections (отражения на окнах).

> 💡 **Пример — экспорт здания с LOD и коллизией:** у тебя три меша `hospital_DFF`, `hospital_LOD`, `hospital_COL`. Выдели все три → **В папку** → получишь сразу 4 файла: `hospital.dff` + `hospitalLOD.dff` + `hospital.col` + `hospital.txd`. Готово к заливке в игру.

### Мульти-импорт DFF (2.1.0)

**Меню:** File → Import → **INU Import** *(или View3D → боковая панель (N) → GTA Tools → Экспорт / Импорт → **DFF**)*

Импортёр DFF теперь принимает сразу несколько файлов. Выделите любое число `.dff` через Ctrl/Shift в проводнике — и каждый импортируется как отдельная модель за один проход, с прогресс-баром (нажмите **ESC**, чтобы прервать — уже созданные модели останутся в сцене).

**Пайплайн:**
1. В N-панели откройте **GTA Tools → Экспорт / Импорт**, нажмите **Импорт** и выберите **DFF** — либо сразу пункт **DFF** в поповер-меню.
2. В проводнике выделите через Ctrl/Shift все нужные `.dff`.
3. (Опц.) в боковой панели задайте **Игра** — оставьте **Авто-определение**, чтобы читать RW-версию каждого файла, или принудительно укажите III / Vice City / San Andreas.
4. (Опц.) переключатель **Авто TXD** — см. *умное подцепление TXD* ниже.
5. Нажмите **Import DFF**. Каждый файл парсится и строится по очереди, в статус-баре идёт счётчик `текущий/всего`.

**Что вы получаете автоматически (без лишних кликов):**

| Возможность | Что делает |
| --- | --- |
| Умное подцепление TXD | При включённом **Авто TXD** для каждого DFF ищется подходящий `.txd` рядом: ① `<имя_dff>.txd` в той же папке, ② `.txd` с покрытием ≥50% текстур DFF (берётся максимальное покрытие, при равенстве — меньший по размеру), ③ единственный `.txd` в папке. Декодируются только те текстуры, на которые ссылается DFF, — поэтому модель быстро ложится даже в уже загруженную карту. |
| LOD-именование | Файл, опознанный как LOD (напр. `LODham_orz_str_18`), именуется `ham_orz_str_18_LOD`; обычные модели получают суффикс `_DFF`. Многосоставные DFF сохраняют чистые имена фреймов. |
| Авто-сварка + жёсткие рёбра | Меши карты/террейна (без авторских нормалей) свариваются, а их острые рёбра разрезаются прямо в геометрии — без груды модификаторов EdgeSplit, так что FPS не страдает. |
| Custom split normals | Повершинные нормали DFF возвращаются как custom split normals, поэтому модель затеняется **в точности** как была сделана (жёсткие/мягкие рёбра сохранены). |

> 💡 **Пример — импорт целой папки зданий разом:** Откройте **INU Import**, нажмите Ctrl+A в проводнике, чтобы выделить все `.dff` в папке зданий, и импортируйте. Каждый станет отдельным объектом, подтянет свой `.txd`, LOD-ы получат имена `…_LOD`, авторское затенение сохранится — без повторов для каждого файла.

> Работает и перетаскивание: бросьте один или несколько `.dff` прямо во вьюпорт — они импортируются батчем с тем же авто-подцеплением TXD.

### Диалог импорта — фильтр форматов (2.1.0)

**Меню:** File → Import → **INU Import**

Диалог **INU Import** — чистый диспетчер: импортирует **ровно** отмеченные файлы, каждый по своему типу (по расширению). В шапке боковой панели **Показывать форматы:** шесть кнопок-тумблеров, фильтрующих, какие типы файлов видны в проводнике:

| Тумблер | Расширение |
| --- | --- |
| **DFF** | `*.dff` |
| **COL** | `*.col` |
| **CST** | `*.cst` |
| **TXD** | `*.txd` |
| **IDE** | `*.ide` |
| **IPL** | `*.ipl` |

- Снимите галку формата — эти файлы пропадут из проводника; список перефильтруется сразу.
- Авто-подцепления TXD здесь **нет** — нужны текстуры, отметьте **TXD** и выберите `.txd` в списке. (Авто-TXD живёт в **Import DFF** / drag-drop, не тут.)
- Если `.txd` выбран рядом с `.dff`, TXD грузится первым, и материалы DFF сразу подхватывают его изображения.

> 💡 **Пример — загрузить модель с её текстурами и коллизией за раз:** Откройте **INU Import**, оставьте включёнными **DFF**, **TXD** и **COL**, снимите остальные, выделите `bistro.dff`, `bistro.txd` и `bistro.col` и импортируйте. Всё три загрузятся вместе, текстуры уже привязаны.

### Export DFF — по моделям (2.1.0)

**Панель:** View3D → боковая панель (N) → GTA Tools → Экспорт / Импорт → **DFF** (в поповере **Экспорт**)

Зеркало мульти-импорта: выделите несколько моделей — получите **по одному `.dff` на модель**, имена из имён моделей. Части одной модели (иерархия) уходят в один файл.

**Пайплайн:**
1. Выделите модель(и) во вьюпорте. Верхний блок панели показывает счётчики **DFF / LOD / COL**, чтобы подтвердить размер партии.
2. Откройте поповер **Экспорт** и нажмите **DFF**.
3. В проводнике выберите **папку** назначения. Боковая панель напоминает *«Каждая выделенная модель → свой .dff»* и показывает блок **Pipeline + DFF Flags** (берётся прямо из DFF-флагов объекта в N-панели — отдельного оверрайда экспорта нет).
4. Подтвердите. Каждая группа моделей пишется как `<имя_модели>.dff`.

> 💡 **Пример — экспорт 10 переделанных пропов:** Выделите рамкой 10 меш-пропов, **Экспорт → DFF**, укажите папку `models/`. Получите 10 отдельных `.dff` по именам мешей, каждый со своими DFF-флагами.

### Export All — в папку или в .img (2.1.0)

**Панель:** View3D → боковая панель (N) → GTA Tools → Экспорт / Импорт → **Экспорт** → **All → Папка** или **All → IMG**

**Export All** пишет каждую выделенную группу моделей — DFF + LOD + COL + TXD (+ опц. CST) — за один проход. В диалоге экспорта строка **Что экспортировать:** содержит тумблеры форматов:

| Тумблер | Файл на модель |
| --- | --- |
| **DFF** | `<имя>.dff` |
| **COL** | `<имя>.col` |
| **LOD** | `LOD<имя>.dff` |
| **TXD** | `<имя>.txd` (текстуры из DFF + LOD) |
| **CST** | `<имя>.cst` *(2.1.0 — коллизия в текстовом формате Collision File Editor II, тот же меш, что у .col)* |

Условные опции появляются при включённом формате: тумблер **COL Library** (все коллизии в один multi-entry `.col`), упаковка общего TXD и блок авто-света коллизии (общий для COL и CST).

**Также в IDE / IPL (пути из панели):** тумблер в диалоге — после экспорта дописывает выгруженные модели в IDE/IPL файлы, выбранные в панели **IDE / IPL / IMG**. LOD получает `id + 1` и корректный `lod_index` (та же логика маршрутизации, что и у кнопки **Add**).

**All → IMG:** внизу диалога тумблер **All → IMG** перенаправляет весь экспорт прямо в `.img` архив, путь к которому задан в настройках аддона — выбранная папка при этом игнорируется. Если путь к `.img` не задан, диалог покажет ошибку и экспорт не пойдёт.

**Пайплайн (в папку):**
1. Выделите все модели для экспорта.
2. **Экспорт → All → Папка**.
3. В диалоге отметьте нужные форматы под **Что экспортировать:** (напр. DFF + COL + TXD).
4. Выберите папку назначения и подтвердите. Файлы пишутся по группам моделей, с прогресс-баром.

**Пайплайн (в gta3.img):**
1. Один раз задайте путь к `.img` в настройках аддона.
2. Выделите модели, затем **Экспорт → All → IMG** (или откройте **All → Папка** и включите тумблер **All → IMG**).
3. Подтвердите — каждая модель пакуется прямо в этот архив, папка не нужна.

> 💡 **Пример — экспорт 10 выделенных моделей прямо в gta3.img:** С прописанным в аддоне путём к `gta3.img` выделите 10 готовых зданий и запустите **Экспорт → All → IMG**. Их DFF (а также TXD/COL для отмеченных форматов) запишутся в архив за одну операцию — без промежуточной папки и ручной перепаковки.

## IDE / IPL / IMG

**Панель:** View3D → Sidebar (N) → GTA Tools → IDE / IPL / IMG

### Импорт / Экспорт / Карта — три вкладки

Вверху панели IDE / IPL / IMG — три кнопки-переключателя **Импорт** | **Экспорт** | **Карта** (как во вкладке Ariane). Раньше это были отдельные сворачиваемые под-панели, а полный импорт/экспорт карты жил в Properties → Scene. Кнопка активной вкладки зажата; всё содержимое ниже относится к ней.

**Вкладка «Импорт»** — тянет модели из игры в сцену:
- **Папка с IDE** — корень игры или любая папка с `.ide` (чем уже, тем быстрее поиск).
- **IPL** — мультивыбор: кнопка 📁 поддерживает Ctrl/Shift, выбранные файлы копятся в сворачиваемый список **IPL для импорта**. Импорт сливает все выбранные IPL (со сдвигом `lod_index`).
- **IMG** — путь к основному архиву + тумблеры **LOD / TXD / COL** (ВКЛ = грузить эти данные; раньше это были инвертированные тумблеры «Skip»).
- **Найти IDE** — сканирует папку игры и находит `.ide`, где объявлены модели выбранных IPL (список **IDE с моделями из IPL**).
- **Найти IMG** — сканирует папку игры рекурсивно и находит все `.img`, реально содержащие DFF моделей из IPL (список **IMG с моделями из IPL**). Импорт затем тянет модели из основного IMG **плюс** всех найденных кастомных архивов (например `maps/RESOURCES`). Нужно, когда модели кастомной карты разбросаны по нескольким `.img`.
- **Импорт** — большая кнопка. Импорт из IMG **модальный**: внизу счётчик **«Импорт из IMG: X/Y»**, Blender не виснет, **ESC** отменяет. При импорте заполняются: имя TXD, LOD-напарник (`inu.lod_object` по `lod_index` из IPL), дистанции (LOD → LOD Dist, основная модель → Draw Dist) и связь с IDE (статус «В IDE (файл)», как у IPL).
- **Обновить из IDE/IPL** — подтягивает свежие данные (дистанции / TXD / флаги / координаты) из файлов **в сцену** (направление файл→сцена). Полезно после ручной правки файлов.

**Вкладка «Экспорт»** — запись и синхронизация в файлы:
- Наверху — бокс **«Выделенная модель»**: имя активной модели и по строке её состояния в каждом файле — **IDE** («В IDE (файл)» / «Не в IDE» / «параметры разошлись» / «сменился ID»), **IPL** («В IPL (файл)» / «Не в IPL» / «координаты разошлись» / «копия — добавится новым инстансом») и **IMG** («В IMG (файл)» / «Не в IMG»). Справа в каждой строке — действия: у имени **Check** (проверка) и 🗑 (убрать из IDE+IPL); в строке IDE — **Add** (записать строку в свой IDE) и 🗑; в строке IPL — 🔄 (**вернуть координаты из IPL**), **Add** (обновить координаты в IPL) и 🗑; в строке IMG — 🔄 (найти, в каком IMG лежит DFF), **Export** (экспорт модели в IMG) и 🗑.
- Боксы **IDE** и **IPL** рядом: **Add** / **Del** / **Export** (пишут выделенные модели); под ними статус активного объекта «В IDE (файл)» / «В IPL (файл)» или «параметры/координаты разошлись».
- Сворачиваемые боксы **IPL для экспорта** и **IDE для экспорта** (по умолчанию свёрнуты) — это те же общие списки, что заполняются на вкладке Импорт («Найти IDE/IMG», мультивыбор IPL) — round-trip. В шапке каждого — иконки без подписей: **⬆ Экспорт в свои** · **＋ Добавить** · **📁 Папка** · **🗑 Очистить**.
- **Экспорт в свои IDE** / **Экспорт в свои IPL** (иконка ⬆) — записывают каждую выделенную модель обратно в **её собственный** файл (по `ide_target_file` / `ipl_target_file`, сопоставление по id/имени), игнорируя выбранный одиночный файл. Модели, которых нет ни в одном файле, попадают в отчёт — добавь их через **＋**.
- **Убрать из IDE+IPL** (бывш. «Отвязать») — удаляет строки выделенных моделей **из обоих** файлов (IDE и IPL) и чистит привязку. Отличается от **Del**, который убирает из одного файла.
- **Проверить** — read-only проверка: есть / нет / без ID.
- Кнопка **📄 (открыть в текст-редакторе)** рядом с путями IPL/IDE и в найденных списках открывает файл во внешнем редакторе ОС.
- Ниже — **Дополнительно (IPL)** (секции cull/пути/гаражи + «Заменить Empty») и бокс **IMG** (Экспорт в IMG / Удалить из IMG / Пересобрать IMG).

**Вкладка «Карта»** — полный импорт/экспорт карты, переехавший сюда из Properties → Scene → Import Map. Внутри: **Папка игры**, тумблеры **LOD / 2DFX / TXD / COL** (ВКЛ = грузить), «Группировать по IPL», выбор района, сворачиваемые списки **Бинарные IPL** и **Текстовые IPL** (кнопка Scan), извлечение ресурсов, кнопки Import / Export Map, профайлер и BBox (см. раздел [Импорт карты](#импорт-карты)).

### Добавление моделей в игру — полный пайплайн

Сквозной порядок, как поместить одну или несколько моделей (с LOD и без) в GTA SA. Пример: четыре модели, у каждой основная модель, коллизия, текстуры и LOD:

```
base   →  base.dff   base.col   base.txd   LODbase.dff
base1  →  base1.dff  base1.col  base1.txd  LODbase1.dff
base2  →  base2.dff  base2.col  base2.txd  LODbase2.dff
base3  →  base3.dff  base3.col  base3.txd  LODbase3.dff
```

**Что есть что:** **DFF** — сама модель · **COL** — коллизия · **TXD** — контейнер текстур · **LOD** — упрощённая модель для дальнего плана · **IMG** — большой архив игры с .dff/.txd/.col · **IDE** — «паспорт» модели (ID, имя, TXD, дальность, флаги) · **IPL** — расстановка в мире (координаты, поворот, связь основная↔LOD).

**Порядок, который не сломается: ID → IMG → IDE → IPL → Rebuild IMG.**

**1. Назвать объекты правильно.** Основная → `base`; LOD → `LODbase` (слово/приставка `LOD` помечает её); коллизия → выставить тип COL (или она без текстур). Аддон группирует всё по базовому имени: `base` + `LODbase` + коллизия = одна модель. Явные суффиксы тоже работают как ручной override (`_DFF`/`_dff`, `_LOD`/`_lod`, `_COL`/`_col`, регистр не важен).

**2. Сначала выдать Model ID.** Игра обращается к моделям по числовому ID. ID Manager → Auto-Assign даёт каждой модели и каждому LOD свободный ID, напр. `base`=18000, `LODbase`=18001, `base1`=18002… **Если ID = 0, «Добавить в IDE/IPL» откажет с ошибкой** — строка с ID 0 ломает игру (0 = модель игрока). Всегда выдавай ID до добавления.

**3. Запаковать в IMG.** Выбери свой `.img` → Экспорт в IMG. Кладутся `base.dff`, `LODbase.dff`, `base.col`, `base.txd` (× все модели). **Лимит имени: имя записи ≤ 24 символа с расширением.** Самое длинное — LOD (`LOD`+base+`.dff`); если `base` слишком длинное, экспорт **остановится и попросит укоротить** — обрезанное имя не совпало бы с IDE/IPL, и модель стала бы невидимой. (Коллизия: `base.col` кладётся в IMG; проверь, что твоя сборка реально грузит коллизию оттуда, либо встрой её в .dff.)

**4. Добавить в IDE (объявить модели).** Выбери `.ide` → Добавить в IDE. По строке на модель и на LOD:
```
18000, base,    base,  299, флаги
18001, LODbase, base,  999, флаги     ← LOD: свой ID, тот же TXD, большая дальность
18002, base1,   base1, 299, флаги
...
```
Строки идут в **выбранный файл** (выбранный всегда побеждает — без тихого раскидывания). Флаги, импортированные из другой игры (VC/III), автоматически переводятся под SA.

**5. Добавить в IPL (расставить в мире).** Выбери `.ipl`, поставь объекты, Добавить в IPL. Строка: ID, имя, интерьер, X/Y/Z, поворот и **lod_index** — ссылка на строку LOD в этом же IPL. **Выделяй основную модель и её LOD вместе** — тогда LOD попадёт в тот же файл и связь проставится. Добавление по-отдельности / в разные файлы рвёт связь — аддон теперь пытается восстановить её из файла и предупреждает, если не смог. Координаты/поворот берутся из реального положения объекта в сцене (с учётом привязки и поворота).

**6. Rebuild IMG (компакт).** После экспортов (особенно повторных) жми Пересобрать IMG — каждая перезапись оставляет «мёртвое» место, архив раздувается. Компакт переписывает архив начисто через атомарную замену файла.

**В игре:** IPL говорит «модель 18000 стоит в точке X» → IDE: ID 18000 = `base`, TXD `base`, дальность 299 → стример грузит `base.dff`/`base.txd`/коллизию из IMG → вдалеке подменяет на `LODbase.dff` (18001). То же параллельно для `base1`/`base2`/`base3`.

### Импорт карты

**Панель:** View3D → Sidebar (N) → GTA Tools → IDE / IPL / IMG → вкладка **Карта** *(раньше — Properties → Scene → INU Tools → Import Map)*

**Шаг 1: Настройка**
- Укажите **Game Root** — папку установки GTA SA
- Выберите **Регион** (автоопределение из gta.dat: LA, SF, VEGAS, COUNTRY и т.д.)
- Тумблеры **LOD / 2DFX / TXD / COL** — ВКЛ = грузить эти данные (раньше это были инвертированные «Skip»-тумблеры). Для импорта района держите **2DFX выключенным** (по умолчанию так): иначе каждый фонарь, корона и ped-аттрактор создаст Blender-объект (Light/Empty) — тысячи штук, viewport встанет колом. Включайте 2DFX только когда импортируете одиночный DFF ради 2DFX-эффектов.
- Тумблер **COL** (по умолчанию выключён) — подтягивает коллизии из кеша рядом с геометрией. Нужно для round-trip workflow (импорт части карты → редактирование → экспорт в IMG другой сборки). Выключайте если нужна только геометрия и хочется лёгкую сцену.

**Шаг 2: Извлечение ресурсов**
- Нажмите **Извлечь ресурсы** — извлечёт DFF, COL и текстуры из IMG архивов в папку `.inu_cache/` рядом с вашим .blend файлом (поэтому .blend нужно сначала сохранить)
- Текстуры декодятся в PNG параллельно (4 воркера, numpy DXT). Уже кешированные файлы пропускаются при повторном запуске
- Типичное время: ~8 секунд на один район

**Шаг 3: Импорт карты**
- Нажмите **Импорт карты** — читает DFF, PNG-текстуры и (опционально) COL **только из кеша** `.inu_cache/` (никакого обращения к IMG во время импорта)
- Если кеш пуст, оператор сообщает *«Кеш пуст — сначала запустите «Извлечь ресурсы»»* и отменяется
- DFF парсятся параллельно (4-поточный pool, numpy отпускает GIL) пока главный поток создаёт Blender-объекты — главный поток не простаивает
- COL парсятся в том же пуле. SA хранит коллизии районов в lib-файлах (`LAs.col`, `LAn.col`…) — в каждом сотни ColModel записей, поэтому карта COL ключуется по внутреннему `model_name`, не по имени файла. DFF с именем `building01` автоматически получает свой `building01` ColModel, если он есть где-либо в кешированных .col
- **Без** «Группировать по IPL» (тумблер выключен) объекты сортируются по 4 плоским коллекциям:
  - **Map_DFF_Far** — дальность прорисовки 300+
  - **Map_DFF_Mid** — дальность 100-299
  - **Map_DFF_Near** — дальность <100
  - **Map_LOD** — LOD модели (детекция по имени: `LODfoo`, `foo_LOD`, `foo1LOD`, `modeLODlaett`)
  - **Map_COL** — коллизии (создаётся лениво, только если `Load COL` включён И найдено хотя бы одно совпадение). Каждый COL-объект наследует трансформацию своего DFF-инстанса
- Тумблер **Группировать по IPL** (по умолчанию **ВКЛ**) — вместо 4 плоских баккетов `Map_DFF_*` / `Map_LOD` / `Map_COL` строится дерево коллекций по каждому IPL, названия совпадают с именами исходных IPL-файлов (без префикса `Map_` — round-trip остаётся читаемым, имя родителя совпадает с оригинальным IPL):
  ```
  vegasN/
    vegasN_DFF
    vegasN_LOD
    vegasN_COL
  vegasS/
    vegasS_DFF
    vegasS_LOD
    vegasS_COL
  vegasn_stream0/
    …
  ```
  Родительская коллекция скрыта во время импорта и снова показывается в конце; подколлекции создаются лениво, поэтому IPL без LOD-моделей не получит пустой `_LOD`. Полезно когда хочется:
  - Скрыть весь район одним кликом (глаз родителя — DFF, LOD и коллизии гаснут вместе)
  - Совместное редактирование карты — автор A правит `vegasN`, автор B `vegasS`, без пересечений
  - Оставлять видимым в outliner происхождение каждой модели (из какого IPL она пришла)
  - Round-trip: импорт → правка → реэкспорт через **Map Export → Разбиение: По коллекциям** восстанавливает оригинальную структуру district'ов; имя коллекции переиспользуется как basename district'а
  - Source IPL берётся как basename исходного файла (текстовые IPL — по пути файла, бинарные IPL — по имени entry в IMG архиве)
- Типичное время: ~30 секунд на район размера LA с включённым COL

**Тюнинг производительности (продвинутое):**

Включите галку **Профайлер импорта/извлечения** в *Scene → INU Tools → Performance* — в `.inu_cache/_profile.log` запишется тайминг-отчёт. Удобно посмотреть где уходит время (wall-time по стадиям, per-thread разбивка, самые медленные отдельные вызовы).

Важные стадии отчёта:
- `submit parse jobs` — одноразовая, доли секунды
- `parse wait` — сколько main thread простаивал в ожидании воркера; около нуля = воркеры идут впереди
- `parse COL files` — upfront агрегация всех .col записей в словарь `model_name → ColModel`
- `loop iter` — суммарное время внутри тела генератора (сравните с `Total wall time`; разница — overhead UI Blender'а)
- `build objects` / `build_mesh` — bpy-работа на каждый DFF
- `build COL` / `reuse COL` / `COL transform` — шаги per-model и per-instance для COL
- `reuse (copy)` — `src.copy()` для повторных инстансов
- `TXD cache load` — назначение PNG в material nodes
- `transform apply` — DFF location/rotation + inu properties

### IDE (Определения)

> **Свойства per-object:** Model ID, Draw Distance, LOD Distance, IDE Flags, Interior, LOD index — живут в **Properties → Object → "GTA SA: IDE / IPL"**. Там же показывается **проверка конфликтов ID** — если несколько объектов имеют одинаковый Model ID, аддон подсветит ошибку с именами конфликтующих объектов.

IDE файлы определяют свойства моделей: ID, словарь текстур, дальность прорисовки, флаги.

| Кнопка | Оператор | Описание |
|--------|----------|----------|
| Добавить | `gtatools.upsert_ide` | Добавить/обновить запись в IDE (авто-LOD) |
| Удалить | `gtatools.remove_ide` | Удалить запись по Model ID |
| Экспорт | `gtatools.export_ide` | Записать выделенные объекты в новый IDE файл |

> Кнопки **Add / Del / Export** живут на вкладке **Экспорт**. Отдельной кнопки «Импорт» больше нет: геометрию тянет **Импорт из IMG** (вкладка Импорт), а определения в сцену подтягивает **Обновить из IDE/IPL**.

**Все секции:** objs, tobj, anim, cars, peds, weap, hier, txdp.

**Авто-LOD:** при добавлении пары DFF+LOD автоматически назначаются:
- **Model ID:** LOD = DFF ID + 1 (например DFF ID 3500 → LOD ID 3501)
- **Draw Distance:** LOD = 999 (максимальная видимость). HD модель видна до своей дальности (например 299м), после чего появляется LOD и виден до 999м
- **TXD:** LOD использует тот же словарь текстур что и DFF

> 💡 **Пример — добавить здание в mymap.ide:** выдели `building01_DFF` и `building01_LOD` → в Object Properties → **INU Tools: Model** поставь `Model ID = 3500` на DFF → N → IDE / IPL / IMG → секция IDE → укажи путь к `mymap.ide` → **Добавить**. В файл запишется две строки: `3500, building01, building01, 299` и `3501, LODbuilding01, building01, 999`.

**Флаги IDE** (15 чекбоксов в свойствах объекта):

| DRAW_LAST | 4 | Прозрачный, рисовать последним |

| NO_SHADOWS | 128 | Не получать тени |

### IPL (Размещение)

IPL файлы определяют позиции, повороты и связи LOD объектов на карте.

| Кнопка | Оператор | Описание |
|--------|----------|----------|
| Добавить | `gtatools.upsert_ipl` | Добавить/обновить размещение (авто-LOD привязка) |
| Удалить | `gtatools.remove_ipl` | Удалить по Model ID. При удалении записи из середины файла все LOD индексы остальных объектов автоматически пересчитываются — иначе игра будет ссылаться на неправильные строки и может вылететь |
| Экспорт | `gtatools.export_ipl` | Записать выделенные объекты с мировыми трансформами |

> Импорта отдельной кнопкой в IPL-боксе больше нет — расстановку делает **Импорт из IMG** (вкладка Импорт), а заглушки заменяет «Заменить Empty» в **Дополнительно (IPL)**.

**Конвертация кватернионов:** GTA SA хранит (X,Y,Z,W) сопряжённый, Blender использует (W,X,Y,Z). Конвертация автоматическая.

**Бинарный IPL:** файлы с заголовком `bnry` (внутри IMG архивов) читаются автоматически.

> 💡 **Пример — расставить модель на карте:** импортировал `building01.dff`, назначил ему Model ID 3500. Двигай/поворачивай как хочешь в сцене → IPL → **Экспорт** → выбери `mymap.ipl` → в файл запишется строка `3500, building01, 0, X, Y, Z, QX, QY, QZ, QW, lod` с реальными мировыми координатами.

### IMG Архив

| Кнопка | Оператор | Описание |
|--------|----------|----------|
| Экспорт в IMG | `gtatools.export_to_img` | Упаковать DFF+COL+LOD+TXD в .img архив |

**Тумблеры экспорта (единые с «В папку»):** DFF / COL / LOD / TXD — что упаковывать. И Unified Export панель (N-sidebar), и IDE/IPL/IMG панель пишут в одни и те же scene-свойства, так что видимые тумблеры всегда применяются к тому оператору, который ты нажал.

> **Импорт из IMG** (`gtatools.import_from_img`) и тумблеры **LOD / TXD / COL** (ВКЛ = грузить) переехали на вкладку **Импорт** (модальный, со счётчиком «Импорт из IMG: X/Y», ESC отменяет). В боксе IMG вкладки Экспорт остаются только запись и сервис архива: **Экспорт в IMG**, **Удалить из IMG**, **Пересобрать IMG**.

**Диалог «Экспорт в IMG».** Раньше это был редактируемый список (UIList) имён модель + TXD. Теперь диалог показывает **иерархию по каждой модели**:
- сверху — дропдаун **«IMG архив»** (по умолчанию — родной IMG модели, если она была импортирована из архива; иначе — любой `.img` из папки игры или общий путь) и общий тумблер **«Общий TXD»** (+ имя);
- по строке-боксу на модель: **DFF** (галочка включения + поле имени TXD), под ним с отступом — **LOD** и **COL**, каждая со своей галочкой;
- если LOD в сцене нет — пишется **«LOD: основная модель (заглушка)»** (в архив ляжет копия основной модели как LOD); если нет COL — **«COL: пустая заглушка»** (пустая габаритная коллизия);
- внизу — галочка **«Пересобрать после экспорта»** (компакт архива сразу после записи).

**COL Library режим** (виден когда **COL** включён) — тумблер + поле имени. Все коллизии пакуются в один multi-entry `.col` файл (например `collision.col`) вместо одного `.col` на модель. Каждая запись хранит свой `model_id`; игра сопоставляет COL с DFF по ID. Так ваниль хранит `LAs.col` / `LAn.col` и другие.

**Shared TXD режим** (виден когда **TXD** включён) — тумблер + поле имени, симметрично с COL Library. Пакует **все** текстуры всех экспортируемых DFF/LOD в один общий `.txd` (по умолчанию `textures.txd`). Удобно для районов и сборок где множество моделей делят одни и те же текстуры — уменьшает количество TXD и чище структура IMG.

**Batch writer + параллельное кодирование (большие экспорты):** `Экспорт в IMG` открывает архив **один раз**, дописывает каждый новый байт-блок последовательно, и переписывает директорию **ровно один раз** в конце — а не на каждый файл. Плюс сериализация DFF и COL (`to_bytes()` / `write_col()`) идёт в 4-поточном `ThreadPoolExecutor` (numpy/zlib отпускают GIL). Для полного района это заменяет ~3000 переписываний директории (~2.6 ГБ лишних записей) одним, плюс ~4× ускорение CPU-bound кодирования — суммарно **5–15× end-to-end**.

> 💡 **Пример — пакетный залив в gta3.img:** у тебя 50 домов готовых к экспорту. Выдели дома → **Экспорт в IMG** → в диалоге вверху выбери **IMG архив** (`gta3.img`), при желании включи **Общий TXD**, и по каждой модели отметь галочками DFF / LOD / COL. Нажал OK — все DFF+COL+LOD+TXD закодируются параллельно и запишутся в архив. Включи **«Пересобрать после экспорта»** (или отдельно **Rebuild Archive**), иначе в игре останутся старые версии.

### Определение типа модели (DFF / LOD / COL)

Аддон определяет тип модели **автоматически** — переименовывать сцену не нужно. Старая редактируемая секция «Суффиксы / Префиксы» убрана; суффиксы остаются как **ручной override**.

Порядок определения (сверху вниз — первое совпадение выигрывает):

1. **Явный маркер в имени** — суффикс `_DFF` / `_LOD` / `_COL` / `_SHA` (или префикс) → этот тип. Так задаёшь тип вручную, когда нужно.
2. **Тег объекта `inu.type = COL/SHA`** (его ставит импорт коллизии и кнопка Batch Set Type) → **COL**. Надёжно для всего, что импортировано как `.col`; проверяется до правила LOD, чтобы коллизия со случайным `lod` в имени не стала LOD.
3. **Токен `lod`** в любом месте имени (**регистр не важен** — то же правило, что у импорта карт) → **LOD**. `LODfunc_detail`, `func_LOD`, ванильные строчные `lodxxx` → LOD; базовое имя берётся без `lod` (для сопоставления с HD-моделью).
4. **По текстурам** — есть материал с картинкой → **DFF**; нет материалов или материалы без текстур → **COL**.

> 💡 Для импортированного аддоном тип уже известен (тег при импорте); для внешних мешей (конвертеры карт типа `func_detail` / `LODfunc_detail`) — по имени и текстурам, без переименования.

> ⚠️ **Безтекстурный визуальный DFF** (вершинный цвет / плоская заливка, без картинки) попадёт в COL по правилу текстур (п. 4). Если такая модель должна быть DFF — добавь суффикс `_DFF`.

**Зачем суффиксы остались (override):** в Blender два объекта не могут иметь одинаковое имя, поэтому DFF и его COL с одним базовым именем не уживаются — для пары придётся ставить `_DFF` / `_COL`. Суффикс заодно задаёт базовое имя для сопоставления пар при экспорте.

При экспорте IDE/IPL LOD-модель всегда записывается с префиксом `LOD` перед именем (формат GTA SA).

### Определение LOD

При импорте карт INU Tools определяет, какие модели — LOD, двумя слоями:

**Слой 1 (надёжный) — ссылки IPL.** В каждой строке IPL `inst` есть поле `lod_index`, указывающее номер строки LOD-напарника в том же файле. Любой инстанс, на который кто-то ссылается, помечается как LOD вне зависимости от имени. 100% надёжно для корректно собранных карт.

**Слой 2 (fallback) — по имени.** Когда IPL-контекста нет, имя считается LOD, если оно **содержит `lod` где угодно (регистр не важен)** — префикс `LODfoo` / `lodfoo`, суффикс `foo_LOD` или в середине `des_damlodbit04`. Для реальных имён карт `lod` надёжно означает LOD; редкие английские слова с `lod` (`lodge`, `explode`) как имена моделей не встречаются. Это то же правило `is_lod_name`, что и у **определения типа** (выше) — поэтому импорт и экспорт согласованы.

**Срезка базового имени** (`strip_lod_marker`) убирает маркер, чтобы получить базовое имя для сопоставления пар COL/DFF/LOD:

| Имя | Срезается до |
|---|---|
| `LODbush2b`, `lod_tree` | `bush2b`, `tree` |
| `bush1b_LOD`, `tatar_str_1LOD` | `bush1b`, `tatar_str_1` |
| `modeLODlaett` (в середине) | `modelaett` |
| `barrier1` (нет `lod`) | `barrier1` (без изменений) |

**Где применяется.** При переименовании во время импорта карты, `Replace IPL Placeholders`, распределении по коллекциям и сопоставлении пар COL/DFF — правильное базовое имя отправляет модель в `Map_LOD` вместо `Map_DFF_*` и даёт утилитам парных объектов находить HD-близнеца.

> Реализация: `is_lod_name()` и `strip_lod_marker()` в [core/ipl.py](INU_tools/core/ipl.py); переиспользуется в `classify_model()` в [core/model_classify.py](INU_tools/core/model_classify.py).

### Sync несколько IPL (2.1.0)

**Панель:** вкладка **Импорт** (список **IPL для импорта**, мультивыбор) и вкладка **Экспорт** (список **IPL для экспорта**). Списки общие. Кнопка синхронизации теперь называется **Обновить из IDE/IPL** (`gtatools.link_sync`) на вкладке Импорт — она заменяет прежнюю «Sync».

Район редко умещается в один `.ipl`. В ваниле SA каждый регион разбит на несколько файлов (`LAn.ipl`, `LAs.ipl`, `LAe.ipl`, стримящиеся куски…), а одиночный выбор файла в боксе **IPL** сверху синхронит за клик только один из них. Список **Sync несколько IPL** позволяет зарегистрировать все `.ipl`, из которых собрана карта, и синхронизировать всю сцену против них **за один** проход.

Пока список пуст, **Sync** работает как раньше — по единственному пути из бокса IPL. Как только в списке появляются файлы, **Sync** проходит по каждому из них.

**Пайплайн:**
1. Разверни **Sync несколько IPL** (▸ треугольник, по умолчанию свёрнуто — в строке показывается живой счётчик `(N)` после добавления файлов).
2. **Добавить** → файловый диалог. Поддерживается множественный выбор: зажми **Ctrl/Shift** и выбери сразу несколько `.ipl`. Дубликаты (тот же абсолютный путь) тихо пропускаются; отчёт — **«Добавлено IPL: N»**.
3. Каждая строка — короткая кликабельная метка пути + кнопка **X** (убрать один файл). **Очистить** опустошает весь список.
4. Нажми **Sync** (общая кнопка IDE+IPL под списком).

Что делает один проход Sync, для каждого объекта:
- **Уже связан** (у объекта есть привязка к IPL) → его позиция/поворот подтягивается **из** того IPL, к которому он привязан, обратно в Blender.
- **Ещё не связан** (например, сразу после Импорта карты) → сопоставляется по `(Model ID + мировая позиция)` с файлами; при совпадении линкуется к нужному файлу.

**Пофайловый учёт пропусков.** Каждый объект принадлежит максимум одному IPL из набора, поэтому простая сумма пропусков по файлам сильно завышала бы цифру (объект из `LAs.ipl` — это «нет совпадения» для `LAn.ipl`). Мультифайловый проход вместо этого объединяет **имена** связанных и обновлённых объектов по всем файлам и считает *пропущенными* только реально нетронутый остаток. Объект, уже привязанный к другому файлу набора, не трогается — его не «перехватит» случайное совпадение по содержимому в другом IPL.

Тревожное «ничего не сопоставилось» срабатывает **только** когда не связан и не обновлён ни один объект — `пропущено N` при успешной работе по остальным — это норма (та часть выделения просто лежит в файле, которого нет в списке).

> 💡 **Пример — синк Лос-Сантоса после Импорта карты:** импортировал район LS, есть ~2000 свежих объектов без привязок к IPL. Открой **Sync несколько IPL** → **Добавить** → с Ctrl выбери `LAn.ipl`, `LAs.ipl`, `LAe.ipl`, `LAw.ipl`, `LAhills.ipl` → в строке теперь `Sync несколько IPL (5)`. Сними выделение (тогда Sync пройдёт по всем мешам сцены) → **Sync**. Каждый объект сопоставляется с тем из 5 файлов, где лежит его размещение, и получаешь `Sync IPL: обновлено 0, новых связей 1980, пропущено 20 (5 IPL)` — эти 20 пропусков — пропсы, которые ты добавил руками и которых нет ни в одном ванильном IPL.

### Маршрутизация IDE/IPL при Add + индекс LOD

**Панель:** View3D → Sidebar (N) → GTA Tools → IDE / IPL / IMG → боксы IDE / IPL → **Add**

**Add** (`gtatools.upsert_ide` / `gtatools.upsert_ipl`) пишет в файл, который ты **выбрал** в боксе IDE/IPL — явный выбор всегда в приоритете:

- **Путь выбран** → все выделенные объекты пишутся в **этот** файл. Если объект раньше был привязан к *другому* файлу, он всё равно пишется в выбранный, и ты получаешь предупреждение (*N объектов были привязаны к другому IPL — проверь дубли в старом файле*). Именно это держит DFF и его `LOD…`-напарника в **одном** файле, что нужно для ссылки LOD (см. ниже) — разнесёшь их по файлам, и LOD тихо ломается.
- **Бокс пуст** → каждый объект уходит в **свой** запомненный файл (откуда импортирован или куда добавлялся), по одной записи на файл. Так удобно обновить объекты сразу из нескольких районов одним кликом.

В боксе активного объекта видно, где он лежит: **В IDE ({файл})** / **В IPL ({файл})** с галочкой, либо **…параметры / координаты разошлись**, когда объект отошёл от записанного (повторный **Add** запишет новое состояние).

**Индекс `lod_index` проставляется автоматически.** Поле `lod_index` в SA IPL — это **номер строки** `inst`-записи LOD в **том же** файле (`-1` = нет LOD). Когда выделяешь DFF вместе с его `LOD…`-напарником и жмёшь Add, аддон сначала вписывает строку LOD, затем кладёт её номер в `lod_index` у DFF — это и есть ссылка, благодаря которой LOD реально подменяется в игре. Та же линковка теперь работает и в **INU Export** при upsert IPL (раньше там писался `-1`, и LOD не работал). Удаление записи из середины через **Remove** пересчитывает `lod_index` у остальных, чтобы ссылки оставались верными.

**LOD-напарник подтягивается сам.** Выделять `LOD…`-меш руками не нужно: если у DFF есть LOD-напарник (его `inu.lod_object`), Add в IPL добавит этого напарника в запись, даже когда выделен только DFF. LOD без Model ID получает **ID = DFF + 1**, а координаты/поворот строки LOD копируются с DFF-родителя — так LOD встаёт на реальную позицию модели, а не в `0, 0, 0`. Отчёт при добавлении разбивает результат, например `IPL: обновлено 0, добавлено 2 (DFF 1, LOD 1)`.

**Как задать LOD-напарника — «Поиск LOD».** Всё вышеописанное держится на связи `inu.lod_object` (в боксе выделенной модели это строка **LOD** с редактируемым полем **LOD ID** рядом). Задай её вручную или нажми **Поиск LOD** (`gtatools.auto_find_lod`) возле строки: он ищет в сцене LOD-двойников выделенных моделей по базовому имени (то же определение LOD, что и выше) и заполняет `inu.lod_object` каждому — отчёт читается как `LOD найден: N, не найдено: M`. Сами LOD-меши как источник пропускаются.

> 💡 **Пример — обновить два здания в их же файлах:** `bank01` из `LAn.ipl`, `tower05` из `LAs.ipl`. Подвинул оба, оставь бокс IPL **пустым**, выдели оба → **Add**. Каждый пишется обратно в свой исходный файл (`IPL: обновлено 2, добавлено 0`). Выберешь конкретный IPL — оба уйдут туда, с предупреждением о дубле для того, кто лежал в другом файле.

### Инлайн-выбор пути для IDE / IPL / IMG (2.1.0)

**Панель:** View3D → Sidebar (N) → GTA Tools → IDE / IPL / IMG → шапки боксов IDE / IPL / IMG

В шапке каждого из трёх боксов есть кнопка 📁 **выбора файла**. Кликни — откроется диалог; после выбора бокс показывает путь короткой нередактируемой меткой (последние два сегмента, например `…/data/maps/LA/LAn.ipl`) под шапкой. Если ничего не задано, метка — **Файл не выбран**. Саму метку править инлайн нельзя — чтобы сменить путь, кликни 📁 ещё раз. Все три бокса используют один диалог; фильтр — `*.ipl / *.ide / *.img`.

### Региональный фильтр подтягивает стримящиеся дочерние IPL (2.1.0)

**Панель:** View3D → Sidebar (N) → GTA Tools → IDE / IPL / IMG → Импорт карты (выбор региона)

При импорте одного региона (Map Region ≠ ALL) старое правило по папкам грузило только IPL, физически лежащие в `maps/<регион>/`. Это тихо отбрасывало **стримящиеся / дочерние IPL** — ваниль разбивает крупные районы на базовый файл плюс стримящиеся куски с именами `<база>_<суффикс>` (например `countn2` → `countn2_stream3`), которые обычно лежат **вне** папки региона. Теперь фильтр оставляет кусок, если выполнено **хоть одно** из: его папка — выбранный регион, **или** его имя — `<база>_<суффикс>`, где `<база>` — один из базовых IPL региона. Так выбор сельского региона теперь подтягивает `countn2.ipl` **и** `countn2_stream3.ipl` — район грузится целиком. Защита по `_` не даёт `countn` жадно цеплять несвязанные `countnXYZ`. В системную консоль печатается, какие IPL отброшены фильтром, а какие загружены — недогруженный район можно отследить.

**Импорт карты — «Без 2DFX».** Тогл Импорта карты **Без 2DFX** (по умолчанию ВКЛ) определяет, импортировать ли 2DFX-эффекты (источники света, частицы…) вместе с каждой моделью. Он читается один раз в начале импорта и передаётся в билдер явно — поэтому в массовом/модальном пути он не может тихо переключиться обратно на «грузить 2DFX». Включённым он делает импорт карты легче и быстрее; выключай только когда 2DFX реально нужны в сцене.

**Авто-линк альфы текстур.** Во время Импорта карты при первой встрече каждого материала аддон проверяет его текстуру: если в изображении есть реально прозрачные пиксели (листва, заборы, окна), он связывает *Alpha текстуры → Alpha BSDF* и переводит материал в альфа-тест, чтобы вырезы корректно рисовались; непрозрачные текстуры не трогаются. Проверка идёт один раз на материал (а не на каждый инстанс), поэтому район, переиспользующий одну текстуру забора на сотнях зданий, оплачивает проверку ровно один раз.

## Прелайт (Vertex Colors)

> **Важное в 1.6.3:** запекание теперь учитывает **smooth/flat shading** (использует `loop.normal` вместо `poly.normal`). Также **скрытые лампы** (через 👁 viewport, 📷 render или скрытая коллекция) **пропускаются** при запекании — раньше брались все point lights в сцене.


**Панель:** View3D → Sidebar (N) → GTA Tools → Prelight

> **Панель Lighting — три вкладки.** Вверху панели Lighting — кнопки-переключатели **PreLight** | **Prelight COL** | **Itera** (раньше — отдельные сворачиваемые под-панели; LightMap в этот переключатель не входит). Иконка-планета 🌐 в шапке ведёт на сайт [Itera Tools 3](https://itera.gumroad.com/l/IteraTools3). Блок настроек прилайта показывается **всегда**; без выделенного меша он затемнён (disabled), а не скрыт.

### Запекание

1. Создай в строках атрибутов слой `Day` (и при нужде `Night`) — кнопкой **＋** у имени атрибута.
2. **Свет (8 ламп)** — тумблер-помощник: расставляет/убирает 8 точечных источников вокруг объекта. Опционально — отдельный тумблер **Солнце** (направленный источник, включается независимо от восьмёрки).
3. **Запечь** — быстрое запекание на CPU без теней · **Запечь с тенями** — с raycast-тенями через depsgraph. Пара **Запечь поверх** / **Запечь поверх с тенями** кладёт свет сцены *additive* поверх текущего прилайта, не перезаписывая.

**Источники запекания.** Раньше прелайт брал только свет от «8 ламп» + настройки Ambient / Intensity / Gamma. Теперь под кнопками «Запечь» — строка тумблеров, задающих, что учитывать: **Point / Sun / Spot / Area** (все типы источников света сцены — твои реальные лампы) + **HDRI (World)**. HDRI берётся из «Окружения сцены» вьюпорта (та самая studio-light-HDRI, что выбирается в выпадашке Шейдинга вьюпорта, с учётом её поворота и интенсивности), а при рендер-мире — из `scene.world`; её цвет сэмплится по нормали каждого loop'а и складывается со вкладом ламп. Кнопки «Запечь» учитывают только включённые тумблеры.

> 💡 **Пример — прелайт дома для карты:** выдели меш здания → Prelight → создай атрибут `Day` → включи **Свет (8 ламп)** (либо расставь свои Point/Sun/Spot/Area) → в строке источников оставь нужные типы (напр. Sun + HDRI) → **Запечь с тенями**. Атрибут `Day` заполняется освещённостью с мягкими тенями от реального света сцены. Для `Night` создай отдельный атрибут, приглуши/подсинь лампы и запеки в него.


### Рассеять цвет

**Sub-panel:** Prelight → Инструменты → Рассеять цвет

Заливает выбранный цвет **вокруг** выделенных полигонов (в отличие от *Рассеивания света* которое перераспределяет уже существующий прелайт). Полезно когда нужно мягко затонировать соседнюю геометрию — отражения от неона, акценты под прожекторами, грязь вокруг люка.

**Параметры:**
- *Сила* (0–1) — насыщенность выбранного цвета в центре (1 = полностью заменить vcols в выделенных вершинах).
- *Дальность* (0–1) — радиус как доля половины bbox-диагонали меша. 0 = только выделенные вершины; 1 = falloff покрывает половину диагонали.
- *Цвет* — берётся из активной кисти **Vertex Paint** (workflow покраски остаётся единым). При отсутствии кисти — fallback на scene color picker.

Падение интенсивности линейное по KDTree-расстоянию — чем дальше вершина от любого выделенного полигона, тем меньше она получит цвета.

### Пост-обработка

| Инструмент | Описание |
|-----------|----------|
| Smooth | Сглаживание цветов между соседними вершинами |
| Smooth между объектами | Сглаживание на стыках разных мешей |
| Contrast | Настройка контраста |
| Brightness | Настройка яркости |
| Gamma | Гамма-коррекция |

> 💡 **Пример — стык двух домов:** два соседних здания стоят вплотную. Запёк прелайт на каждом отдельно — видны резкие швы в цвете vertex colors на границе. Выдели оба → **Smooth между объектами** (проходы 2, сила 0.5) → градиент плавно перетекает между мешами, шов исчезает.

### COL Light

**Панель:** View3D → Sidebar (N) → GTA Tools → Prelight COL

Конвертация vertex colors в COL Day/Night Light значения (0-15). Авторазбиение материалов по яркости.

- **Preview** — визуализация значений света на меше
- **Bake** — запись значений в свойства COL материалов
- **Диапазоны Day/Night** — настраиваемые пороги

> 💡 **Пример — свет для коллизии тоннеля:** у тебя COL-меш тоннеля с vertex colors где центр тёмный, края светлее. Открой Prelight COL → **👁 Preview** — меш раскрасится цифрами 0-15. Настрой диапазон Day (min=0, max=6) чтобы центр был 0 (тёмный) а вход 6 (светлее) → **Запечь COL Light** → материалы получают соответствующие Day/Night Light значения. В игре машина при въезде в тоннель будет автоматически затемняться.

### Пресеты

**Шапка** в верху панели Prelight — селектор пресета + 5 кнопок.

Хранятся как `.json` в папке `INU_Preset/`. Один пресет фиксирует всё связанное с прелайтом во всей панели и её sub-панелях:
- **Запекание** — Ambient, Intensity, Gamma, Shadows
- **Modulate Color** — режим (OFF/Day/Night), mix, contrast, gamma
- **Adjust Color** — V-offset
- **Рассеять цвет** — strength, distance
- **Пост-обработка** — smooth iterations/factor, contrast, brightness, gamma
- **Per-object Day/Night** — V-offset для каждого атрибута + флаг auto-create Day/Night атрибутов при Load

| Кнопка | Действие |
|---|---|
| ✓ **Применить** | **Load** — подтягивает значения выбранного пресета в сцену + активный меш (создаёт Day/Night атрибуты, если пресет это требует). Основная кнопка, слева. |
| ✎ | Переименовать выбранный пресет. |
| + | Создать **НОВЫЙ** пресет (открывает диалог имени). |
| − | Удалить выбранный пресет. |
| ⬆ | **Сохранить в выбранный пресет (overwrite)** — перезаписывает текущий пресет текущими значениями сцены. В status bar показывается diff (`old → new`), без диалога имени. Кнопка справа (иконка «отправить вверх в пресет»). |

> 💡 **Workflow на примере:** настроил ночной look — Modulate Color = Night, Day V = +30, Night V = −20 → **+** → имя `my_night`. Поправил Modulate Mix с 0.002 на 0.005 → **⬆** перезаписывает `my_night`, status bar пишет `modulate_mix: 0.002 → 0.005`. Перешёл в другую сцену → выбрал `my_night` → **✓ Применить** → все настройки восстановлены на каком бы меше ты ни работал.

### Настройка цвета (V-offset на атрибут)

В каждом ряду селектора Day/Night атрибутов — свой слайдер V-offset:

```
[Day]    V: +30.0   [-]
[Night]  V: -20.0   [-]
```

Введи значение → нажми Enter → яркость **немедленно** применится к этому атрибуту vertex colors (только на этом объекте). Значение сохраняется per-object и переживает повторное запекание — после нового bake offset автоматически переприменяется к свежим колорам.

### Управление Vertex Colors

| Кнопка | Описание |
|--------|----------|
| Создать Day/Night | Создаёт оба атрибута `Day` и `Night` |
| Day + / Night + | Создать отдельный атрибут |
| Day - / Night - | Удалить отдельный атрибут |
| Превью | Включить/выключить визуализацию Day/Night микса |
| Добавить LightMap | Загрузить текстуру лайтмапа и подключить на UV2 (Multiply) |
| 👁 LightMap | Включить/выключить отображение лайтмапа (mute/unmute) |
| ➖ LightMap | Удалить лайтмап ноды из материалов |
| Анализ | Показать гистограмму vertex colors (min/max/avg) |

**Режимы Edit/Paint:** кнопки переключения между Object, Edit и Vertex Paint режимами.

> 💡 **Пример — скопировать дневной прелайт как ночной (быстрый старт ночного):** ты запёк только `Day` атрибут → **Day → Night** → `Night` создаётся как копия `Day`. Теперь открой Post-Processing → **Brightness** = −0.3 → применить к Night → получил затемнённую версию дневного. Дальше доводишь руками (добавить заливку желтым вокруг фонарей и т.д.).

### Слои Vertex Color (BETA)

**Секция:** Prelight panel → ▸ **Слои Vertex Color (BETA)** (collapsible, между LightMap и Запекание)

Photoshop-стайл **неразрушающее** редактирование vertex colors. Стопка именованных слоёв на каждый scope (Day / Night), у каждого свой opacity / blend mode / brightness / contrast. Композит автоматически пишется в `Day` / `Night` — для live preview во вьюпорте И при экспорте DFF. Сами слои остаются доступны для редактирования в .blend.

**Зачем нужно:**
- Добавить зелёный налёт на стены не пере-запекая освещение
- Накрасить свечение окон поверх Itera-бейка
- Подкрутить только тени в одной зоне, не трогая остальное
- Попробовать вариант цвета, откатить одним слайдером

**Хранение:** каждый слой = `BYTE_COLOR` color attribute на меше, имя `VCL_D_<label>` (Day-стек) или `VCL_N_<label>` (Night-стек). Лимит **10 слоёв на стек**. Видны в списке Color Attributes под секцией «Дополнительные атрибуты» — слои это полноценные данные, рисуются стандартным Blender Vertex Paint mode.

#### Пайплайн (типовой workflow)

1. **Создай `Day` / `Night`** — уже есть из бейка, или через обычные кнопки Day/Night выше
2. **Добавь слой** — клик [+] в «Слои Day» — создаётся `VCL_D_Layer_1`, полностью прозрачный
3. **Покрась слой** — клик **Рисовать** на активной строке слоя → войдёшь в Vertex Paint на `VCL_D_Layer_1`
4. **Подкрути слой** — крути Opacity / Blend Mode / Brightness / Contrast у активного
5. **Включи Live Preview** → атрибут `Day` теперь показывает композицию (база + все видимые Day-слои)
6. **Экспортируй DFF** — композит auto-flatten'ится в `Day` / `Night` на время экспорта; слои в .blend остаются нетронутыми

#### Кнопки

| Кнопка | Описание |
|--------|----------|
| **▸ Слои Vertex Color (BETA)** | Развернуть / свернуть секцию |
| **Live preview** (toggle) | Угнать `Day` / `Night` под композицию. ON: оригиналы бэкапятся в custom-prop, композит пишется в `Day` / `Night` живьём. OFF: оригиналы восстанавливаются |

| Список «Дополнительные атрибуты» | Все color attributes кроме Day/Night (VCL слои, custom прилайт). Radio = активировать, ❌ = удалить |
| **Слои Day** [+] | Создать Day-слой (лимит 10) |
| **Слои Day** [−] | Удалить активный слой и его атрибут |
| **Слои Day** [▲] [▼] | Поменять порядок слоя в стеке (это меняет порядок блендинга) |
| Per-row [☑] | Multi-select для групповых правок |

#### Детали Live Preview

- **ON:** атрибуты `Day` (и `Night`) перезаписываются композицией стека. Оригинал лежит в `mesh["_vcl_backup_day"]` / `mesh["_vcl_backup_night"]` как base64-encoded float-буфер
- **OFF:** оригиналы восстанавливаются из бэкапа; backup custom props удаляются
- Композит пересчитывается при: любом слайдере слоя, ▲/▼ перемещении, add/remove/promote/demote, мазке кистью (depsgraph хук замечает когда active = `VCL_*`)
- Recompose дебаунсится ~100 мс через one-shot `bpy.app.timers` — быстрый драг слайдера = один финальный композит, а не 50

> ⚠ **Не рисуй напрямую на `Day` / `Night` пока Live Preview ON.** Эти атрибуты держат композицию; твой мазок сотрётся на следующем recompose. Рисуй на слое — клик **Рисовать** на строке слоя.

#### Auto-flatten при экспорте

DFF-экспортёр оборачивает `build_dff_clump` в context manager:
1. Снимает snapshot `Day` / `Night` в память
2. Композитит Day-стек в `Day`, Night-стек в `Night`
3. DFF-writer читает композит → пишет в файл
4. Восстанавливает `Day` / `Night` из snapshot

Итог: .blend выглядит ровно как до экспорта, а .dff содержит финальный композит. Без ручного «commit».

> 💡 **Пример — тестим вариант цвета для зелёной крыши:** у тебя здание с запечённым `Day`. Добавляешь Day-слой `green_roof`, красишь крышу зелёным, opacity 0.6, blend Normal. Live Preview ON → видишь композит. Экспорт DFF, тестим в игре. Не нравится — обратно в Blender, opacity до 0.3, re-export. Совсем не нравится — `[−]` удаляет слой; `Day` сам собой остаётся в исходном бейке.

### Солнце для прилайта (2.1.0)

**Кнопка:** панель Прелайт → **Солнце**.

Добавляет одну направленную лампу **SUN** в риг прилайта (тот же цвет #BCBCBC, что и у кольца из 8 точечных, угол сверху-спереди). Запекается вместе с точечными — даёт ровную направленную подсветку поверх локального точечного света. Полезно для плоских крыш / больших фасадов, которые одно кольцо точечных освещает неравномерно.

**Пайплайн:**
1. Выдели меш → **Create Day/Night** (если ещё нет).
2. **Create 8 Lights** (опционально — Солнце работает и без них).
3. **Солнце** → создаётся `Prelight_Sun` (повторное нажатие удаляет).
4. **Запечь** / **Запечь с тенями** — Солнце участвует в бейке как любая лампа.

> 💡 Работает даже без выделенного меша (управляет только лампой). Скрой её 👁 в аутлайнере, чтобы запечь без направленной заливки, как любую другую лампу.

### Запечь поверх (аддитивно)

**Кнопки:** панель Прелайт → **Запечь поверх** / **Запечь поверх с тенями** (высокий ряд над обычным «Запечь»).

Обычное **Запечь** *перезаписывает* активный атрибут Day/Night. **Запечь поверх** вместо этого *добавляет* новый бейк к текущему прилайту (Add, с зажимом до 1.0) — можно наслаивать несколько проходов света.

**Пайплайн:**
1. Запеки базовый свет обычным «Запечь» (перезапись).
2. Добавь/подвинь лампы (например, тёплую лампу у входа).
3. **Запечь поверх** → добавляется вклад только новой лампы — база сохраняется.

> 💡 Обычное **Запечь** всегда печёт заново (с нуля). **Запечь поверх** никогда не сбрасывает — повторяй, чтобы накопить несколько проходов (солнце + лампа + неон).

### Заливка Day/Night

**Под-панель:** Прелайт → Инструменты → **Залить одним цветом**.

Заливает атрибуты `Day` и `Night` из двух color-пикеров в один клик — байт-точно (`color_srgb`), сохраняя вертекс-альфу, и ставит экспорт-флаги Day/Night, чтобы модель ушла как day/night prelit.

**Пайплайн:**
1. Выбери цвета **День** и **Ночь**.
2. Опционально: ☑ **Только выделенные** — зальёт только выделенные грани (в Edit Mode).
3. **Применить**.

> 💡 **Пример — плоская ambient-база:** новое здание без бейка. Залей Day = RGB(0.75,0.75,0.75), Night = RGB(0.3,0.3,0.38) → мгновенная нейтральная day/night база, поверх которой можно «Запечь поверх» или красить руками.

### Прилайт листвы / деревьев (2.1.0)

**Под-панель:** Прелайт → ▸ **Листва / деревья**.

Геометрическая затенёнка кроны + тонировка листвы для деревьев и кустов — **без ламп в сцене**. Считает радиальный градиент от центра кроны наружу (и опционально сверху-вниз), так что листья получают естественный вид «темнее внутри / светлее снаружи». Разбито на две независимые операции, у каждой свой выбор материала:

- **Крона** (затенёнка) — градиент яркости (сам световой вид).
- **Цвет** — градиент тонировки (осень/сезон, затемнение низа).

**Ключевые настройки:**
- *Сфера / Цилиндр* — радиальная метрика (сфера = полный 3D-радиус; цилиндр = игнор высоты, хорошо для высоких деревьев).
- *Внутри / Снаружи* — яркость (или цвет) в центре кроны и на краю.
- *Кривая* — форма спада градиента.
- *Подсветить верх / Высота подсветки* (блок Цвет) — мультипликативная подсветка к верхушке кроны.
- *Разброс* — случайный шум по листьям, чтобы не было однородно.
- *Затемнить низ* — доп. затемнение нижней части кроны.
- *Запечь цвет* / *Сброс* — снимок прилайта до тонировки и откат к нему.

**Пайплайн:**
1. Выдели меш дерева → раскрой **Листва / деревья**.
2. Выбери материал листвы в **Крона**, задай Сфера/Цилиндр + Внутри/Снаружи → **применить** → затенёнка кроны в активном слое.
3. (Опц.) Выбери материал в **Цвет**, задай тон + Подсветить верх + Затемнить низ → **Запечь цвет** (сначала снимок) → применить.
4. Не нравится тон → **Сброс** возвращает прилайт до тонировки.

> 💡 **Двусторонние карты листьев:** дубликаты-плоскости листвы (та же позиция, перевёрнутые нормали) сопоставляются по позиции вершин, так что обе стороны забора/листа получают один цвет даже на триангулированных мешах.

### Резак света — Свет → топология (2.1.0)

**Под-панель:** Прелайт → Инструменты → **Свет → топология**.

Строит геометрию под лампой и запекает в неё плавное радиальное световое пятно — для мягких prelit-кругов света на полу, которые грубый меш не покажет. Видимый **вайр-резак** (концентрические цилиндры-кольца или сфера) позволяет подобрать размер/кольца до нарезки.

**Настройки:**
- *Тип* — Цилиндр (концентрические кольца, для пола) / Сфера.
- *Радиус* / *Сегменты* — общий размер + круглость.
- *Кольца* — список радиусов колец (у каждого свой слайдер); больше колец = плавнее градиент.

**Пайплайн:**
1. Выдели лампу (или поставь 3D-курсор) → задай Тип / Радиус / Сегменты.
2. **Создать резак** → у лампы появляется вайр `INU_LightCutter`. Крути радиус / сегменты / добавляй кольца — он **перестраивается вживую**. Двигай туда, где нужно пятно.
3. Выбери режим:
   - ☑ **Отдельной геометрией** → строит чистый отдельный диск, прижатый к поверхности снизу.
   - ☐ выкл → выбери целевой **пол** → врежет кольца в этот меш.
4. **Нарезать по резаку** → геометрия нарезается, и в `Day` запекается радиальный градиент (яркий центр → тёмный край, × цвет лампы).

> 💡 Резак — обычный вайр-объект: можно зайти в Edit Mode и править его полигоны/кольца вручную; смена слайдера кольца после этого перестроит его.

### Покраска нескольких объектов (Merge / Split)

**Под-панель:** Прелайт → Инструменты — **Объединить для покраски** / **Разъединить**.

Красить Day/Night вертекс-цвета сразу по **многим моделям**. Объединяет выделенные меши в один текстурированный временный прокси, ты красишь по нему кистью, затем цвета копируются обратно в каждый оригинал по диапазону loop'ов.

**Пайплайн:**
1. Выдели все меши, которые хочешь красить вместе.
2. **Объединить для покраски** → создаётся временный объединённый прокси в Vertex Paint (текстуры видны).
3. Крась Day (и/или Night) по всему кластеру как по одному объекту.
4. **Разъединить** → цвета записываются обратно в каждый оригинал; прокси удаляется.

> 💡 **Пример — ряд витрин:** 6 отдельных DFF зданий, которым нужен один непрерывный вечерний градиент. Объединить → покрасить градиент один раз по всем 6 → разъединить. Каждая модель сохраняет свой кусок, градиент течёт по ним бесшовно.

### Превью вертекс-альфы (по сцене)

**Кнопка:** Прелайт (и Текстуры) → **Альфа вершины (сцена)** + 🗑 очистка.

Показывает повертексную прозрачность во вьюпорте, независимо от RGB-превью прилайта. Сканирует сцену, находит только те меши/слоты материалов, у которых альфа Day/Night реально `< 255` (заборы, листва, стекло, края LOD), и заводит их вертекс-альфу в Alpha материала + blended-режим. Сплошную геометрию не трогает.

**Пайплайн:**
1. **Альфа вершины (сцена)** ВКЛ → все «затухающие» модели становятся полупрозрачными по своей вертекс-альфе.
2. Правь / запекай / стирай альфу как нужно.
3. **Альфа вершины (сцена)** ВЫКЛ → ноды превью полностью удаляются (граф чист).
4. 🗑 **(очистка)** — *проверка*: убирает зависшие ноды AlphaView из материалов, где вертекс-альфы уже нет (например, ты стёр её на части мешей), сохраняя их только там, где ещё нужны. Запускается автоматически при включении или в любой момент кнопкой.

> 💡 Заводятся только реально «затухающие» слоты — меш, где смешаны непрозрачный материал стены и прозрачное стекло, получит ноды только на стекле.

> ⚠ **Подводный камень — в игре альфа НЕ появится без IDE-флага.**
> Превью во вьюпорте Blender ≠ рендер в игре. Чтобы повертексная (или текстурная) альфа реально рисовалась в GTA SA, у объекта в **IDE** должен стоять флаг прозрачности:
>
> | Флаг | Имя | Что делает |
> |------|-----|------------|
> | **4** | DRAW_LAST | Объект прозрачный, рисуется после непрозрачных. Базовый альфа-вырез: заборы, листва, простое стекло. |
> | **64** | NO_ZBUFFER_WRITE | Не пишет в Z-буфер → слои прозрачности накладываются друг на друга. |
> | **68** = 4+64 | DRAW_LAST + NO_ZBUFFER_WRITE | Полный диапазон альфы для **вертекс-цвета И текстур** (плавное затухание, мягкое стекло). Цена: без Z-записи возможны артефакты сортировки (объект «просвечивает» сквозь другой). Бери, когда нужен именно плавный вертекс-альфа-градиент. |
>
> Флаг задаётся в **N-панель → IDE/IPL** (поле флагов объекта) и пишется при экспорте IDE. Без него альфа есть в Blender, но в игре модель полностью непрозрачная. Источник: [GTAMods — Item Definition / IDE Flags](https://gtamods.com/wiki/Item_Definition).

## 2DFX Эффекты

**Панель:** View3D → Sidebar (N) → GTA Tools → 2DFX Effects

Создание и настройка 2DFX эффектов, экспортируемых в DFF файлы.

**Типы эффектов:**
- **Light** — уличные фонари, неон, короны
- **Particle** — дым, огонь
- **Ped Attractor** — банкомат, скамейка, остановка
- **Sun Glare** — отражение солнца на поверхности

### Свойства света

| Свойство | Варианты |
|----------|---------|
| Пресеты | Default, OnAllDay, Lamp Post, Lamp Post Coast, BB Pickup, Flashing (3 типа), Train Crossing, Traffic |
| Текстура короны | 34 текстуры (coronastar, coronamoon, headlight и др.) |
| Текстура тени | 13 текстур (shad_exp, shad_car, lamp_shad_64 и др.) |
| Режим показа | Default, Random Flashing, Flash Rain, Only Rain, No Rain |
| Тип бликов | None, Type 1-3 |
| Цвет | RGBA палитра |
| Размер короны | Float |
| Дальность прорисовки | Float |
| Дальность света | Float |
| Размер тени | Float |
| Флаги 1/2 | Integer |

**Привязка к модели:** родительство Empty к мешу. Координаты автоматически пересчитываются при экспорте.

> ⚠ **Подводный камень — текстуры эффектов (короны/тени/вода) в аддон НЕ входят.** Это ассеты GTA SA (Rockstar IP), поэтому для превью они берутся из твоей игры. В заголовке панели 2DFX, в строке **«Create Effect: …»**, показан **реальный источник** текстур — короткий путь к `.txd`, либо **«Не выбран»**, если источника нет. Кнопка-папка справа (📁) выбирает свой `.txd` (например `particle.txd`) — сам выбор подгружает текстуры, отдельной кнопки «Загрузить» больше нет.
>
> Если явный `.txd` не задан, аддон берёт текстуры из **Game Root** по порядку: `models/particle.txd` → `particle2.txd` / `effectsPC.txd` / `misc.txd` → встроенный `gta3.img/particle.txd`. Превью дотягивает их лениво. Без источника корона/тень рисуются плоским плейсхолдером (на экспорт DFF это не влияет — там пишется только имя текстуры).

**Detach All from Mesh:** массовое отвязывание всех 2DFX от выделенного меша. В UI меша показывается только счётчик **«Привязанные 2DFX: N»** и одна кнопка **«Отвязать все»** (прокручиваемого списка с индивидуальными кнопками больше нет).

**Применить настройки:** копирует настройки активного 2DFX (свойства `inu` + custom props `2dfx_*`) на все остальные выделенные Empty'и; их превью автоматически пересобирается. Позволяет настроить целую группу источников света за один клик.

**Связи (пунктир):** чекбокс, включающий/выключающий пунктирный оверлей линий-связей родитель→ребёнок для привязанных 2DFX.

**Превью:** визуализация короны/тени в реальном времени во вьюпорте. Billboard tracking реализован через **draw handler** *(1.6.3)* — стабильно работает при переключении между сценами. Дублирование / копирование / добавление 2DFX Empty (Shift+D / Ctrl+C+V) автоматически пересобирает его превью света/частицы через фоновый таймер (~0.6 с) — так что нативное дублирование Blender просто работает.

> 💡 **Пример — уличный фонарь:** выдели меш столба фонаря → 2DFX → **Create Light** → появится Empty с дефолтной лампой. Переведи Empty на вершину столба → выбери Preset **Lamp Post** → ✓ Apply (проставит жёлтый цвет, текстуру coronastar, дальность 200м). Родительство к мешу автоматическое → Empty.parent = столб. При экспорте DFF координаты 2DFX пишутся относительно меша.

> 💡 **Пример — мигающая красная авария:** Create Light → Preset **Flashing (Maverick1)** → ✓ Apply → Show Mode `1 RANDOM_FLASHING` автоматически. В игре эта корона будет случайно мигать красным — идеально для аварийных сигналов или проблесковых маячков.

### Флаги света 2DFX и корона/тень (2.1.0)

**Панель:** `N-панель ▸ INU ▸ 2DFX Effects` (при выделенном 2DFX Empty типа «свет») ▸ секции **Флаги**, **Свойства света**, **Тень**

В 2.1.0 исправлены флаги видимости день/ночь (раньше они были сдвинуты на единицу, из-за чего «ночные» лампы светились и днём) и уточнена работа короны и тени.

#### Флаги видимости день / ночь

Откройте секцию **Флаги**. Кнопки в группе **Видимость:** — это переключатели: нажатая (подсвеченная) кнопка означает, что бит включён. Наведите курсор на любую кнопку, чтобы увидеть, за что отвечает бит.

| Кнопка | Бит | Значение |
|---|---|---|
| **AT_DAY** | flags1 бит 5 | Источник виден днём (06:00–20:00) |
| **AT_NIGHT** | flags1 бит 6 | Источник виден ночью (20:00–06:00) |
| **Blink 1** / Blinking 1 | flags1 бит 7 | Источник мигает (паттерн 1) |

По умолчанию у нового света включены оба — **AT_DAY** + **AT_NIGHT** (лампа горит всегда).

**Порядок действий — сделать свет видимым ТОЛЬКО ночью:**
1. Выделите 2DFX Empty со светом.
2. Раскройте **Флаги** ▸ **Видимость:**.
3. Включите **AT_NIGHT** (нажмите так, чтобы кнопка осталась подсвеченной).
4. Выключите **AT_DAY** (нажмите так, чтобы кнопка перестала быть подсвеченной).
5. Готово — днём лампа тёмная, ночью светится.

#### Только корона — без пятна на земле и тени

Видимый светящийся спрайт (сам «огонёк») — это **корона**, ей управляет **Размер короны** в секции **Свойства света**. Световое пятно на земле и заливающий свет вокруг лампы задаются полем **Размер пятна** в секции **Тень**.

**Порядок действий — оставить только корону, убрать пятно:**
1. Раскройте секцию **Тень**.
2. Поставьте **Размер пятна** = **0**. Панель подтвердит: *«Размер = 0 → только корона, без пятна»*.
3. Убедитесь, что **Размер короны** в **Свойствах света** больше 0 — это и есть то, что остаётся. (Размер короны = 0 → видимого свечения нет вообще.)

#### Превью-материалы по объекту (несколько ламп с одной текстурой короны)

Раньше несколько ламп, использующих одну текстуру короны (например, все уличные фонари с `coronastar`), сводились к одному общему превью-материалу — и в окне рисовалась только одна корона. Теперь каждый свет получает свой собственный превью-материал, привязанный к объекту, поэтому корону рисует каждая лампа.

- Новые лампы и обновлённые лампы получают это автоматически.
- Если в **уже существующей** сцене по-прежнему видна только одна корона: выделите каждую лампу и нажмите **Обновить превью** вверху панели, чтобы пересобрать её материал.

#### Подсказки при наведении

Наведите курсор (не нажимая) на эти элементы, чтобы прочитать пояснение прямо в панели:

- Пункты **Режим показа** и **Тип бликов** — каждый вариант (DEFAULT, RANDOM_FLASHING, FLASH_RAIN, ONLY_RAIN, NO_RAIN, FLASH_5, типы линзовых бликов) описывает своё поведение.
- Пункты **Имя короны** / **Имя тени** — каждая текстура (`coronastar`, `coronamoon`, `shad_exp`, силуэты машин/пешехода…) описывает свой вид.
- В секции **Тень**: **Дистанция** — на сколько метров вниз проецируется световое пятно; **Множитель** — яркость/насыщенность пятна на земле (0–255).

> 💡 **Пример — ночной уличный фонарь:** Выделите 2DFX Empty со светом ▸ **Флаги** ▸ **Видимость:**: включите **AT_NIGHT**, выключите **AT_DAY**. Оставьте **Размер короны** ~1.0 и **Размер пятна** ~8 — получится светящийся фонарь с мягким пятном на земле, появляющийся только после наступления темноты.

> 💡 **Пример — неон только с короной (без пятна):** В **Свойствах света** задайте **Размер короны** по вкусу и выберите корону в **Имя короны** (например, `coronastar`). В секции **Тень** поставьте **Размер пятна** = **0** — получится парящее свечение без светового круга на земле. Если у вас несколько таких вывесок с одной текстурой короны, нажмите **Обновить превью** на каждой, чтобы все они отрисовались.

## Particle Effects (effects.fxp)

Полноценный редактор GTA SA `effects.fxp` — текстового файла с **82 системами частиц** (огонь, дым, кровь, искры, вода, гильзы и т.д.), которые движок проигрывает когда в зоне видимости появляется объект с `Particle` 2DFX-меткой.

**Расположение файла:** `<game_root>/models/effects.fxp` — резолвится из `gtatools_game_root` Scene property.
**Источник текстур:** `<game_root>/models/particle.txd` — атлас спрайтов, на которые ссылаются эмиттеры через поле `TEXTURE`.

### 1. Настройка сцены

Укажи **Game Root** в **N-sidebar → GTA Tools → Import Map** (раскрывающийся блок). Dropdown доступных эффектов заполняется из `<game_root>/models/effects.fxp`:

- Файл парсится один раз при первом открытии dropdown и кэшируется (ключ = путь + mtime); пере-парсится автоматически при сохранении новой системы.
- Если Game Root пустой или `effects.fxp` отсутствует — dropdown покажет `<Game Root не задан>` / `<effects.fxp не найден>`.
- Используй **Reload effects.fxp** оператор если редактировал файл вручную вне Blender.

### 2. Привязка частицы к модели

Эффект частицы привязывается к мешу через дочерний **Empty** с 2DFX-меткой `Particle`.

1. Открой **N-sidebar → GTA Tools → 2DFX Effects**.
2. **Создать эффект ▾ → Частица** — Empty создаётся в позиции 3D-курсора с `effect_2dfx = 'PARTICLE'`.
3. С выбранным Empty открой **Properties → Object → INU Tools: Model** → найди dropdown **Particle Effect**. Выбери имя системы (`prt_blood`, `prt_fire_med`, `prt_smoke_huge` и т.д.).
4. **Привязать к модели:**
   - Выдели DFF меш к которому хочешь привязать эффект.
   - **Shift-клик по particle Empty** — Empty становится active object (Empty активный + меш в выделении).
   - В 2DFX панели жми **Привязать к модели** (`gtatools.attach_2dfx`).
   - Empty становится child'ом меша, world-позиция сохраняется.

Если позже надо разорвать связь — жми **Отвязать от модели** (один эффект) или **Отвязать все от меша** (batch-unparent всех 2DFX-child'ов выделенного меша).

Empty теперь ссылается на систему в `effects.fxp`. Его локальная трансформа относительно parent-меша = точка спавна + ориентация эмиссии в локальном пространстве модели.

### 3. Редактирование эмиттера

Когда particle Empty активен, **Properties → Object → INU Particle Properties** выставляет полный набор параметров:

**Спрайт и смешивание**

| Свойство | Default | Описание |
|---|---|---|
| `Texture` | от системы | Имя спрайта в `particle.txd` (`sphere`, `smoke3`, `flame`) |
| `SrcBlend` | 4 | D3D9 source blend factor (`4`=SrcAlpha для alpha-blended, `2`=One для чистого additive) |
| `DstBlend` | 5 | D3D9 destination blend factor (`5`=InvSrcAlpha) |

> **Типовые рецепты blend:** SrcAlpha + InvSrcAlpha = alpha-blended спрайт (дым, кровь). One + One = аддитивное смешение (огонь, magic glow). One + InvSrcAlpha = pre-multiplied alpha.

**Цвета по времени жизни**

- `color_start` — RGBA при рождении (time = 0)
- `color_end` — RGBA при смерти (time = 1)
- `color_mid_enabled` + `color_mid` + `color_mid_time` — опциональная третья точка для 3-stop интерполяции (например для огня: жёлтый → красно-оранжевый → чёрный)

**Размер**

- `size_start` — размер частицы при рождении (world units)
- `size_end` — при смерти

**Эмиссия**

| Свойство | Описание |
|---|---|
| `life` | Длительность жизни частицы в секундах (1.5 для дыма, 0.3 для искр) |
| `life_bias` | ± случайное отклонение от base life |
| `rate` | Частиц в секунду |
| `speed` | Начальная скорость (units/sec) |
| `speed_bias` | ± случайное отклонение |
| `direction` | Вектор направления эмиссии (XYZ, нормализованный) |
| `angle_min` / `angle_max` | Угол конуса разброса (радианы, 0 = лазер, π = полная сфера) |
| `volume` (XYZ extents) | Объём спавна вокруг origin |
| `volume_radius` | Радиус сферы спавна (переопределяет box когда > 0) |
| `volume_min` | Внутренний box (annular spawn для эффектов колец) |
| `offset` | Смещение точки спавна от origin эмиттера |
| `rotation_min` / `rotation_max` | Начальное вращение спрайта (радианы) |
| `rotspeed_min` / `rotspeed_max` | Скорость вращения спрайта |

**Физика**

| Свойство | Описание |
|---|---|
| `force` | Постоянный вектор силы (гравитация сюда, например `(0, 0, -9.8)`) |
| `friction` | Демпфирование скорости (1.0 = без трения, 0.5 = сильное сопротивление) |
| `wind` | Множитель ветра движка (0 = без ветра, 1 = полное сцепление) |
| `noise` | Магнитуда Perlin-noise turbulence |
| `jitter` | Per-frame случайное дрожание (отличается от noise — jitter некоррелирован) |
| `ground_bounce` | Отскок от земли (0 = проходит насквозь, 1 = полный отскок) |
| `ground_speedmult` | Множитель скорости после отскока |

**Система (для всего эффекта, не per-emitter)**

| Свойство | Описание |
|---|---|
| `sys_length` | Длительность всей системы в секундах (0 = бесконечно, например для огня) |
| `sys_playmode` | Режим воспроизведения: 0 = once, 1 = loop, 2 = one-shot burst, 3 = continuous-with-fade |
| `sys_culldist` | Дистанция отсечения симуляции (LOD cull) |

### 4. Viewport preview + симуляция

Два режима визуальной обратной связи — **статическое превью** (по умолчанию) и **live симуляция** (опционально).

**Статическое превью** — одна билборд-плоскость, child Empty'а, текстурированная спрайтом первого эмиттера системы и затонированная `color_start`. Нет анимации, нет спавна — просто показывает где живёт эффект и как он выглядит в момент рождения.

- Создаётся автоматически при создании 2DFX Particle или выборе имени эффекта.
- Обновляется при смене текстуры/цвета через кнопку **Обновить превью** (также автоматически после `Switch Emitter` и `Сохранить эффект`).
- Удаляется кнопкой **Удалить превью** (`gtatools.remove_2dfx_preview`).
- Поворот билборда обрабатывается фоновым таймером, выравнивающим quad с камерой активного 3D viewport'а.

**Live симуляция** — реальный GPU-driven симулятор частиц. Глобальный scene-toggle, работает на 30 Hz:

- Переключатель: **N-sidebar → 2DFX панель → Симуляция** чекбокс (иконка `▶` / `⏸` в зависимости от состояния). Scene property `gtatools_particle_sim`.
- При включении регистрирует `bpy.app.timers` tick на `1/30 s` и обходит все PARTICLE Empty в сцене.
- Каждый Empty получает child mesh `<empty_name>_psim` с пулом до **`MAX_PARTICLES_PER_EMITTER = 64`** quad'ов.
- Per-particle state (позиция, скорость, возраст, life) живёт в module-level dict'ах — эфемерный, не сохраняется в `.blend`.
- Quad'ы всегда смотрят на активный 3D viewport (orthonormal basis из `region_3d.view_rotation`).
- За кадром → particles тикают но mesh не обновляется.
- При выключении все `_psim` mesh'и удаляются.

> **Статическое превью** и **симуляция** могут работать одновременно — превью это «как эффект выглядит на скриншоте», симуляция для тюнинга emission/forces в движении. Симуляция гейтится глобально потому что каждый эмиттер потребляет немного CPU per tick (32 эмиттера × 64 частицы × 30 Hz = ~60K vector-операций/сек).

### 5. Кривые (анимация параметров)

Любой per-particle параметр можно сделать **анимированным по времени жизни** через piecewise-linear кривую. Кривые в runtime заменяют статические значения: вместо постоянного размера, движок сэмплирует размер из кривой по нормализованному возрасту каждой частицы.

**Где редактор:** прокрути за статическими свойствами вниз до секции **Particle Curves**.

**Workflow:**

1. Выбери канал кривой из dropdown — `SIZE.SIZEX`, `COLOUR.RED`, `COLOUR.GREEN`, `COLOUR.BLUE`, `COLOUR.ALPHA`, `EMRATE`, `EMSPEED` и т.д.
2. Появляется список ключей с `+` (добавить строку), `−` (удалить), UIList для выбора активной.
3. Каждая строка — пара `(TIME, VAL)`:
   - `TIME` ∈ `[0, 1]` — нормализованный возраст частицы (0 = рождение, 1 = смерть)
   - `VAL` — значение канала в этот момент
4. Ключи сортируются автоматически при записи.
5. Жми **Записать кривую в effects.fxp** для сохранения.

**Пример — рост размера для огня:**

```
SIZE.SIZEX:
  (0.00, 0.5)   ← рождение: маленький уголёк
  (0.30, 2.0)   ← пиковое пламя
  (1.00, 0.1)   ← смерть: рассеялся
```

**Пример — затухание цвета огня:**

```
COLOUR.RED:    (0.0, 1.0) → (1.0, 0.3)
COLOUR.GREEN:  (0.0, 0.8) → (1.0, 0.0)
COLOUR.BLUE:   (0.0, 0.2) → (1.0, 0.0)
COLOUR.ALPHA:  (0.0, 1.0) → (0.7, 0.5) → (1.0, 0.0)
```

> Кривые ПЕРЕОПРЕДЕЛЯЮТ статические `color_start` / `color_end` / `size_start` / `size_end` для своего канала. Чтобы отключить кривую — удали все ключи.

### 6. Системы с несколькими эмиттерами

Многие ванильные системы содержат несколько эмиттеров играющих одновременно. Пример: `prt_cardebris` имеет 4 эмиттера (куски, искры, пыль, дым) для одного эффекта взрыва машины.

- Dropdown **Switch Emitter ▾** в INU Particle Properties переключает между эмиттерами системы.
- У каждого эмиттера свой спрайт, blend, цвета, кривые — они независимы.
- При сохранении эффекта пишутся все эмиттеры.
- При создании нового эффекта через **New Effect** создаётся только **один** эмиттер — добавить ещё можно редактируя `effects.fxp` напрямую или клонируя multi-emitter шаблон.

### 7. Сохранение в effects.fxp

Один основной save-оператор (`gtatools.save_particle_effect`) с двумя режимами через popup-диалог:

| Поле | Что делает |
|---|---|
| `effect_name` | Имя целевой системы. По умолчанию — текущий выбранный эффект (сохраняет на месте); напиши новое имя → текущий эффект **клонируется** под этим именем. |
| `overwrite` | Если включён И таргет-имя уже существует — существующая система перезаписывается. Если выключен И имя есть → оператор выдаёт ошибку (защита от случайной перезаписи). Игнорируется если `effect_name` новое. |

Плюс два связанных оператора:

| Оператор | Что делает |
|---|---|
| **New Particle Effect** (`gtatools.particle_effect_new`) | Создать пустой новый эффект с нуля (не клон). Один эмиттер с текстурой `sphere`, белый цвет с alpha=0 на конце, life=1.0, rate=10. |
| **Delete Particle Effect** (`gtatools.particle_effect_delete`) | Удалить текущий выбранный эффект из `effects.fxp` после диалога подтверждения. |
| **Reload effects.fxp** (`gtatools.reload_effects_fxp`) | Сбросить in-memory FXP-кэш. Полезно если файл правился вне Blender и нужно чтобы dropdown / превью перечитали с диска. |

**Алгоритм Save — что происходит по клику:**

1. Перечитывает `effects.fxp` с диска (не из кэша — избегает stale state).
2. Если `effect_name` **новое** → deep-copy текущей системы, переименование, append.
3. Если `effect_name` **существует** + `overwrite` включён → переиспользует существующую систему на месте.
4. Вызывает `_apply_particle_props_to_emitter` который пишет **только поля которые ОТЛИЧАЮТСЯ** от текущего состояния эмиттера (dirty check):
   - Статичные поля (texture, blend, color, size, life, force и т.д.) сравниваются по одному.
   - Кривые с более чем одним keyframe'ом, статика которых совпадает — **НЕ трогаются** — сохраняет multi-keyframe анимации которые юзер не правил.
   - System header (`LENGTH`, `PLAYMODE`, `CULLDIST`) dirty-чекается отдельно.
5. **No-op early exit:** если не клонируем И ноль полей изменилось → сообщение «Нет изменений — файл не тронут», ничего не пишется.
6. **Auto-backup** при первой реальной записи в сессии — создаёт `effects.fxp.bak` (только если `.bak` ещё нет). Последующие записи бэкап не обновляют, поэтому `.bak` всегда состояние «начало сессии».
7. Запись файла с CRLF line endings, потом `clear_cache()` чтобы следующее открытие dropdown перечитало.

**Сохранение одной кривой** — отдельно — **Write Curve to FXP** (`gtatools.particle_curve_write`) пишет ТОЛЬКО редактируемую кривую (например `COLOUR.RED`), не трогая остальные кривые и скалярные поля. Используй для итеративного тюнинга кривых без полного сохранения системы.

> **Edit buffer:** при переключении dropdown на другой эффект все несохранённые правки сбрасываются до значений новой системы. **Сохраняй ДО переключения**, иначе работа потеряна.

### 8. Экспорт DFF

Привязка частицы хранится на Empty в виде custom property `2dfx_effect_name = '<system_name>'`. DFF экспорт читает это и пишет `PARTICLE` 2DFX entry в 2DFX-чанк DFF: **24-байтовая ASCII zero-padded строка** с именем системы (truncate если длиннее 24 символов).

Больше ничего экспортировать не нужно — параметры частиц живут в `effects.fxp`, не в DFF.

**Путь экспорта:** `File → Export → INU Export` (или N-panel → Export → DFF) → DFF подбирает каждый particle Empty запарентованный к мешу и выпускает по одному 2DFX entry на каждый.

### 9. В игре

1. Замени модель в `gta_sa/models/gta3.img` (используй **IMG Export** для пересборки архива с твоим DFF).
2. Замени `gta_sa/models/effects.fxp` на отредактированный файл.
3. Сделай бэкап ванильных файлов первым делом (всегда).
4. Запусти игру — частицы играют в локальной позиции Empty относительно модели, ориентированы по локальным осям эмиттера.

> Для тестов на **MTA:SA** workflow тот же, но частицы спавнятся только когда MOD-loaded модель с 2DFX-меткой в зоне видимости.

### Troubleshooting

| Симптом | Причина / фикс |
|---|---|
| Dropdown показывает `<Game Root не задан>` | Задай `gtatools_game_root` в Import Map панели |
| Dropdown показывает `<effects.fxp не найден>` | Проверь что `<game_root>/models/effects.fxp` существует |
| Частицы не появляются в viewport | Нажми **Обновить превью** — preview кэш мог устареть |
| Частицы есть но без текстуры | `particle.txd` отсутствует, или имя текстуры не совпадает с записями в TXD — проверь через Texture Browser |

| В игре правки не видны | `effects.fxp` не скопирован в папку игры, ИЛИ кэш движка: удали `gta_sa.set` для принудительного re-read |

### Масштаб островов

**Бокс:** UV Editor → Sidebar (N) → GTA Tools → **Масштаб островов** (под Рандомизатором UV сетки).

Два способа привести масштаб UV-островов к норме. Поля: **Текстура** (128…4096, по умолч. 512) и **Значение**.

- **В сетку** — равномерно масштабирует каждый остров так, чтобы его **высота** (когда задан **Ряды**) или **ширина** (когда задан **Колонки**) в UV стала = `Значение / Размер текстуры`. Пропорции сохраняются, 3D-размер не учитывается (чистая доля UV). Работает **только** когда задан один из параметров — Ряды **ИЛИ** Колонки (не оба); строка-подсказка показывает активную ось.
- **Тексель** — настоящая плотность текселя (px на юнит), по площади UV↔3D, как в TexTools. Учитывает реальный размер геометрии, поэтому детализация выравнивается между островами. Считает по локальной геометрии — применяй масштаб объекта.

> 💡 **Пример — единый тексель по зданиям:** выдели все полигоны в Edit Mode → **Текстура** 1024, **Значение** 256 → **Тексель** → каждый остров масштабируется к 256 px/юнит, текстура везде одной плотности.

### Очистка материалов — подробно

Кнопка ищет датаблоки с суффиксом `.001`, `.002` и т.д. и объединяет их с оригиналом за один проход — отдельно материалы и отдельно текстуры (изображения).

**Материалы:**
- Все слоты `material_slots` у мешей, ссылающиеся на дубликат, переключаются на оригинал.
- Если оригинала с базовым именем нет — первый дубликат переименовывается в базовое имя и становится оригиналом.
- Неиспользуемые дубликаты (`users == 0`) удаляются из `bpy.data.materials`.

**Текстуры (безопасный режим):**
- Замена ссылки на изображение происходит в нодах `Image Texture` всех материалов **и** в node groups (shader/geometry/compositor).
- Дубликат объединяется с оригиналом **только если совпадает абсолютный путь к файлу** (`bpy.path.abspath` с учётом библиотеки). Это защита от ложных слияний для GTA SA, где одинаково названные текстуры часто приходят из разных TXD.
- Для packed/generated изображений (без filepath) используется слабый ключ `source + size`.
- Текстуры с разными путями **не объединяются** и попадают в счётчик «Пропущено».

**Отчёт в статус-баре:**
```
Материалов: 12/3 | Текстур: 8/2 | Пропущено (разные пути): 1
```
Формат — `объединено_слотов/удалено_дубликатов`.

### Скан файлов

**Sub-panel:** View3D → Sidebar (N) → GTA Tools → Проверка → Скан файлов

Линтит `.dff`, `.col`, `.txd` файлы **на диске** на crash-prone байтовые паттерны — без импорта в Blender. Полезно когда:
- собрал модели из разных источников и хочешь проверить перед паковкой в IMG;
- свежесобранная карта крашит игру и нужно найти виновника;
- аудитишь конвертированные/портированные модели (gmod → SA и т.п.).

**Workflow:**
1. Выбери папку через file picker.
2. Включи нужные форматы (DFF / COL / TXD).
3. По желанию включи «Включая подпапки». **Default off** — защита от случайного сканирования `gta_sa\models\`.
4. Жми **Сканировать**. Прогресс в status bar.
5. Результаты в скроллируемом списке: `severity_icon  filename: short message`. Клик на строку — полное описание, путь к файлу, кнопка «Открыть в Проводнике».
6. Фильтр «Только ERROR» (default on) скрывает WARN/INFO чтобы видны были только реальные крэши.

**Что проверяется:**

*COL — collision-формат*
- Magic + filesize header consistency
- Bounding sphere/box NaN/Inf или инвертированный (`min > max`)
- Sphere-collider radius validity, координаты вершин в `(−256, 256)` (int16/128.0)
- Индексы граней внутри vertex count
- Surface ID диапазон: vanilla ≤ 178, FLA ≤ 254
- Shadow mesh offset overflow (Manu-class crash `0x415D47`)
- Face-groups count в пределах 1024 (документированный лимит)

*DFF — RenderWare-модель*
- RW chunk integrity, RW version sanity (vanilla SA = `0x36003`)
- Atomic indices в frame/geometry массивах
- Frame parent-tree (без циклов и forward-refs)
- Per-geometry лимиты vertex/triangle/material (u16 hard + soft warnings)
- Кол-во UV-слоёв vs flag bits
- Skin PLG: bone count u8, max_weights ≤ 4, валидность bone-индексов
- Triangle.material в диапазоне
- NaN/Inf в позициях вершин, bounding sphere
- `GEOM_NATIVE` флаг (PS2/Xbox-only данные на PC engine)
- 2DFX entry count

*TXD — texture dictionary*
- `platform_id` (8 = D3D8, 9 = D3D9 — другое не загрузится на PC SA)
- Bit depth в `{4, 8, 16, 24, 32}`
- Power-of-two размеры (vanilla D3D8 path требует POT — известные крэши `0x004C9691` / `0x00732924` / `0x00749B7B`)
- DXT block alignment (×4)
- AUTO_MIPMAP флаг взаимно исключающий с `num_levels > 1`
- PAL + DXT взаимно исключающие
- Mipmap count vs `log2(max(w,h))`
- Пустые / дублирующиеся / слишком длинные имена текстур

Каждый код имеет развёрнутое объяснение в панели («Что это значит:») с описанием root cause и как чинить.

**Сохранение отчёта:**
Три варианта:
- 🟢 **Рядом с .blend** — default; warning если scene не сохранён.
- 🟡 **В папке скана**.
- 🟠 **Своя папка** — file picker.

Файл: `inu_lint_<timestamp>.txt` со сгруппированным результатом.

### Lint-профили

**Sub-panel:** View3D → Sidebar (N) → GTA Tools → Проверка → Lint Profile

Единый EnumProperty `gtatools_lint_profile` переключает набор thresholds/severity для **Сканера файлов** и **Анализатора карты**.

| Профиль | Что делает |
|---|---|
| **STANDARD** | По умолчанию — пороги откалиброваны против ванильных SA-ассетов (ноль false positives на reference-set `F:\AllDFF`) |
| **FLA** | Считает что установлен [Fastman92 Limit Adjuster](https://fastman92.com/) — глушит FLA-required warnings (Model ID > 19999, surface ID > 178 и т.п.) |
| **STRICT** | Жёсткие пороги (например material limit 50 вместо 100), для QA-прогона перед публикацией мода |
| **LENIENT** | Скрывает все INFO-уровень — полезно при аудите legacy-проектов где мелкие warnings — шум |

Активный профиль применяется и к **on-disk** (Сканер файлов), и к **cross-file** (Анализатор карты) проверкам. Переключение профиля пересчитывает результаты текущего скана — повторять не нужно.

### Анализатор карты (Game Validator)

**Sub-panel:** View3D → Sidebar (N) → GTA Tools → Проверка → Анализ карты

Кросс-проверка **IDE** файлов (определения) против **IPL** файлов (размещения) — ловит несовместимости которые приводят к крашу в игре.

**Режимы источника** (один из трёх):
1. **Из игры** — использует `gtatools_game_root` + резолвинг через `gta.dat` чтобы собрать все активные IDE/IPL пары.
2. **Из папки** — picker папки; рекурсивный обход на `.ide` и `.ipl`.
3. **Ручные списки** — UIList IDE-файлов + UIList IPL-файлов; кнопка «Добавить файл» для каждого.

**Опциональная IMG-проверка** — если передан список файлов в архиве, IDE entries проверяются против реального наличия DFF/TXD.

**Проверки:**
- **Висячие placements** — `INST` строка ссылается на model_id который ни в одном IDE не определён
- **Неиспользуемые ID** — IDE entry никогда не размещён в IPL (не крашит, но забивает stream slots)
- **Дубликаты ID** — один model_id определён в двух разных IDE
- **NaN координаты** — position/rotation содержит NaN или Inf
- **Interior range** — `inst.interior_id` вне `[0, 256]`
- **Draw distance sanity** — `drawdist` в IDE ≤ 0 или абсурдно большой
- **Отсутствующий TXD** — IDE ссылается на TXD которого нет в IMG (только в IMG-verify режиме)
- **Несоответствие полей** — IPL строка имеет неверное число comma-separated токенов

**Результаты** в UIList сгруппированы по severity (Critical / Warning / Info) с `LintIssue` shape общим со Сканером файлов. Клик по строке → полное описание + кнопка «Открыть IDE/IPL файл».

**Сохранение отчёта** — тот же 3-direction picker что у Сканера файлов.

## Texture Browser

**Sub-panel:** View3D → Sidebar (N) → GTA Tools → Texture Browser

Инвентарный инструмент для просмотра всех текстур из выбранного источника без импорта. Полезно когда:
- ищешь конкретную текстуру по имени среди множества TXD'ов;
- нужно понять «в каком TXD лежит `roof_tile_03`?»;
- проверяешь cross-ref что и где используется перед экспортом TXD-батча.

**Источники** (radio-селектор):
1. **Из IMG** — берёт каждый `.txd` внутри выбранного `.img` архива.
2. **Из папки** — рекурсивно обходит папку на `.txd` файлы.
3. **Из IDE-списка** — читает столбец `txd` в IDE-файлах и резолвит через `gtatools_game_root`.

**Строка UIList**: превью · `имя_текстуры` · `WxH` · формат · исходный `.txd`. Клик по строке загружает текстуру в превью-панель. Поиск-поле фильтрует по подстроке имени.

**Cross-reference** (toggle «used by»): для выбранной текстуры сканирует все материалы в текущем `.blend` и показывает какие объекты её используют. Клик по имени объекта — jump-select во вьюпорте.

Декодирование ленивое — заголовки текстур (имя + размер + формат) читаются upfront, пиксельные данные только при выборе строки. ~1000 текстур обычно сканируется меньше секунды.

## Запекание текстур `(2.1.0)`

INU Tools включает послойную систему запекания текстур (как слои в Photoshop, только каждый слой — это запечённая карта). Вы складываете карты вроде AO, Diffuse и Bevel, смешиваете их прямо на модели в реальном времени, а затем сводите стек в одну готовую для GTA diffuse-текстуру. Свет для AO/Shadow/Diffuse-Lit подсистема генерирует сама — лампы в сцене не нужны. Запекание идёт через **Cycles** (он должен быть включён в аддонах Blender); если в настройках Blender включено GPU-устройство Cycles, оно используется автоматически.

**Панель:** `3D-вьюпорт → Боковая панель (N) → GTA Tools → Texture Bake`
(запечённая текстура автоматически показывается в Image-редакторе)

### Размер, Padding и сглаживание

Настройки в верхней части панели применяются ко всем картам:

| Настройка | Описание |
|---|---|
| **Размер** | Квадратный пресет степени двойки (32 … 8192). Задаёт X и Y разом. |
| **X / Y** | Независимые ширина/высота; каждое привязывается к ближайшей степени двойки. |
| **Padding** | Залив за края UV-островов, в пикселях (по умолчанию 8). |
| **АА** | Суперсэмплинг: печь во внутреннем бóльшем разрешении и ужимать — убирает лесенки/полосы (как в TexTools). `Выкл`, `2×` (по умолчанию), `4×` (чище, медленнее). Внутреннее разрешение ограничено 4096, а сэмплы Cycles снижаются в АА² раз — поэтому АА на шумных картах почти «бесплатно». |

> 💡 Имя выходной текстуры берётся автоматически из имени модели (срезаются известные префиксы `_DFF` / `_LOD` / `_COL` и суффиксы `_hi` / `_low`) — поля для имени нет.

### Режимы запекания

**Подпанель:** `Texture Bake` → строка **Режим** (три кнопки **UV → UV** / **Hi → Low** / **Камера** показываются сразу — прежний сворачиваемый заголовок «Запекание» убран из UI)

| Режим | Что делает |
|---|---|
| **UV → UV** | Печёт объект сам в себя. Источник = рендер-UV (слой 📷 `active_render`); цель = **выделенная** UV-карта. Для trim-развёрток: текстуры остаются на trim-UV, а свет/AO печём в отдельную чистую UV. |
| **Hi → Low** | Переносит деталь с хайполи на выделенный лоуполи. Пара ищется по суффиксам имени `_hi` / `_low` (например, `wheel_hi` ↔ `wheel_low`). У лоуполи должна быть UV-развёртка. Cage / Max Ray — в **Дополнительно**. |
| **Камера** | Рендерит объект ортокамерой в текстуру с прозрачностью. Для billboard-деревьев/импостеров: ничего не обрезается, силуэт растягивается на весь кадр, альфа берётся из силуэта. |

Когда меш выделен, под строкой режима показывается живая информация (источник/цель UV, найденная пара Hi/Low или кадрирование камеры).

**Особенности режима Камера:**
- Если у выделенной модели есть пара `_hi` / `_low`, **рендерится хайполи**, а результат кладётся на **billboard-плоскость (лоуполи)**; камера ориентируется **по нормали плоскости**, и UV плоскости перепроецируется из того же ракурса — текстура ложится точь-в-точь.
- Если пары нет, объект рендерится сам по мировой оси, которую вы выбираете в **Ракурс**: `Спереди −Y` / `Сзади +Y` / `Справа +X` / `Слева −X` / `Сверху +Z`.
- **Отступ** — запас вокруг силуэта, чтобы крона не упиралась в края текстуры.
- Режим Камера рендерит на EEVEE (как Material Preview), даёт чистый **стандартный материал** (Principled) с alpha-clip и **не** собирает композит слоёв.

> 💡 **Пример — billboard дерева через режим Камера:**
> 1. Сделайте детальное дерево как `tree_hi` и плоский billboard-квад как `tree_low`, и развёрткой `tree_low`.
> 2. Выделите пару, откройте **Texture Bake**, задайте **Размер** 512, **АА** `2×`.
> 3. Поставьте **Режим** → **Камера**. Панель подтвердит `Рендер: tree_hi`, `На модель: tree_low`, `Ракурс: по нормали плоскости`.
> 4. Добавьте один слой **Diffuse** и нажмите **Bake**.
> 5. На billboard теперь стандартный материал с отрендеренным деревом и чистым силуэтом-альфой. Сохраните его кнопкой **Сохранить как**.

### Стек слоёв

**Подпанель:** `Texture Bake → Добавить слой` и список слоёв под ним

Стек читается как в Photoshop: **нижний** слой — база, слои выше смешиваются на неё. Новые слои добавляются **сверху**.

> Стек слоёв теперь **per-model**: у каждой модели свой набор слоёв (хранится на объекте, `obj.inu`), а не общий на всю сцену. Переключил активную модель — увидел её собственный стек.

**Добавить слой:** в боксе **Добавить слой** выберите карту в выпадающем списке → **Добавить**. Слой появится вверху списка с режимом смешивания и прозрачностью по умолчанию для этой карты. (Normal Map добавляется с уже включённым **Обесцветить**.)

**Управление в строке слоя:**

| Элемент | Описание |
|---|---|
| Глазик | Включить/выключить слой в композите и при сведении. |
| Имя слоя | Клик — **выбрать** слой (его запечённая карта показывается в Image-редакторе, а параметры — в боксе **Выбранный слой**). |
| **Bake** | Печёт **только карту этого слоя** в свою картинку. |
| Иконка сохранения (✓) | Сохраняет одну эту карту в файл (доступна после запекания карты). |
| **X / ▲ / ▼** | Удалить / поднять / опустить выбранный слой. Порядок = порядок смешивания. |

**Параметры выбранного слоя** (бокс **Выбранный слой**):
- **Режим** — как этот слой смешивается с нижними (18 режимов, ниже).
- **Прозрачность** — 0…1, подмешивает результат смешивания этого слоя поверх нижних.
- **Контраст** / **Гамма** — тоновая правка слоя, в реальном времени в превью и при финальном сведении.
- **Обесцветить** — *только для слоёв Normal Map*; сводит слой в серое, убирая синий tangent-space оттенок (как при сведении нормал-мапы в Фотошопе).

### Доступные карты

| Карта | Режим по умолч. | Примечание |
|---|---|---|
| **AO** | Multiply | Ambient occlusion. Шумная → использует Samples. |
| **Diffuse** | Normal | Плоский альбедо (базовый цвет без света). |
| **Diffuse Lit** | Normal | Альбедо, освещённое **светом сцены** (тумблер «Свет от сцены» ВКЛ по умолчанию) либо внутренним ригом из 5 солнц (купол), когда тумблер выключен. |
| **Shadow** | Multiply | Тень (без альбедо) от **света сцены** (по умолчанию) либо от одного внутреннего key-солнца, когда «Свет от сцены» выключен. |
| **Bevel** | Overlay | Маска кромок (через Bevel-нормаль): рёбра светлее. |
| **Normal Map** | Normal | Нормали в tangent-space. Добавляется с включённым Обесцветить. |
| **Emission** | Normal | Собственное свечение материала. |
| **Emission Light (GI)** | Add | Непрямой свет *от* излучающих граней на соседние. Шумная → использует Samples. |
| **LightMap** | Multiply | Полный GI от **реального света сцены** (лампы, солнце, world + отражённый). В отличие от Shadow / Diffuse Lit **не** использует внутренний риг и **не** изолирует сцену — печёт ваши настоящие лампы. Очень шумная → высокие Samples + опц. OIDN-денойз. См. ниже. |

### LightMap — GI от реального света сцены

В отличие от Shadow / Diffuse Lit (внутренний свет-риг, сцена изолирована), **LightMap**
печёт **настоящие лампы, солнце и world** сцены с глобальным освещением (прямой + непрямой,
без альбедо → чистый множитель освещения). Подвинете лампу — запечка изменится: это ваш
реальный свет, как в *The Lightmapper*.

- **Денойз** (Дополнительно → **Денойз**): чистит шум на всех шумных картах
  (AO / Shadow / Diffuse-Lit / Emission-GI / LightMap). На Blender 4.x — встроенный
  **OIDN** (по альбедо/нормали, feature-guided, без внешнего бинаря); на 5.x / headless —
  fallback на numpy-билатераль. По умолчанию включён.
- **Сэмплы LightMap** (Дополнительно): отдельный, более высокий бюджет сэмплов (GI шумнее AO).
- **Применить как** (Дополнительно → **Применить как**) + кнопка **Применить LightMap** —
  выбор, как использовать запечённый LightMap в GTA SA (в SA нет нативного lightmap-UV):

| Режим | Что делает | Цель в GTA SA |
|---|---|---|
| **Слой в стеке** | Оставляет MULTIPLY-слоем — сводите/сохраняете сами | Любая (вручную) |
| **Впечь в диффуз** | `LightMap × <base>_DIFFUSE` → одна текстура (нужен запечённый Diffuse) | Ванилла, без шейдеров |
| **В vertex prelight** | Сэмплирует LightMap по-лупно в prelight-атрибут **Day** | Ванильное статик-освещение |
| **Отдельная текстура + 2 UV** | Сохраняет `LP_<base>` и вешает 2-м UV-каналом Multiply-шейдером (при **Авто lightmap-UV** авто-разворачивает непересекающийся UV «LightMap») | Кастомный MTA-шейдер |

> 💡 **Пример — запечь LightMap от света сцены в vertex prelight:**
> 1. Осветите сцену (солнце + лампы + world/небо). Выделите меш здания.
> 2. **Texture Bake** → **Добавить слой** → **LightMap** → **Добавить**.
> 3. **Дополнительно** → оставьте **Денойз**, **Применить как** → **В vertex prelight**.
> 4. Нажмите **Bake** (карта снимет реальный свет + отскок, с денойзом).
> 5. Нажмите **Применить LightMap** → освещение ложится в vcol **Day**; экспортируйте DFF как обычно.

### Режимы смешивания (18)

Выпадающий список **Режим** каждого слоя совпадает с узлом Mix в Blender / Photoshop и даёт одинаковый результат в живом превью и при сведении:
Normal, Darken, Multiply, Color Burn, Lighten, Screen, Color Dodge, Add, Overlay, Soft Light, Linear Light, Difference, Subtract, Divide, Hue, Saturation, Color, Value.

### Дополнительно

**Подпанель:** `Texture Bake → Дополнительно` (по умолчанию свёрнута). Фильтруется по карте **выбранного** слоя — показываются только подходящие:
- **Samples** — сэмплы Cycles для шумных карт (AO / свет / GI).
- **Свет от сцены** (только Shadow / Diffuse Lit, по умолчанию **ВКЛ**): печёт эти карты от **реальных источников света сцены** (твои лампы / солнце / world), как LightMap. Выключено — внутренний калиброванный SUN-риг (работает даже без ламп), и тогда доступен ползунок **Свет (экспозиция)** — множитель энергии этого рига.
- **Изолировать объект** (общая, по умолчанию **ВКЛ**): на время бейка прячет прочие МЕШ-объекты сцены (лампы не трогаются). Чинит чёрный AO среди объектов карты (соседи больше не затеняют модель) и ускоряет бейк (Cycles строит BVH только по цели). Выключено — запекать с тенями от соседей.
- **Bevel радиус** / **Bevel samples** / **Только выделенные полигоны** — только для карты Bevel. «Только выделенные» применяется именно к Bevel; при нескольких слоях Bevel у каждого своя картинка.
- **Прозрачный фон** (общая, по умолчанию ВЫКЛ): выключено — фон запечённых карт вне развёртки заливается **средним цветом текстуры** (альфа 1), чтобы на швах/мипах не лезла чернота; включено — фон прозрачный (альфа 0). Не влияет на карту **ALPHA**, слои-декали и режим **Камера** — там альфа значима.
- Только карта **LightMap** (см. раздел LightMap): **Качество** (пресет сэмплов Черновик→Продакшн, либо Своё→**Сэмплы LightMap**), **Режим света** (Полный / только Отражённый / только Прямой), **Денойз** + **Денойз по albedo/normal** (feature-guided), **Интенсивность** (экспозиция) + **Смягчение** (Gaussian blur), **Применить как**, **Авто lightmap-UV**. Интенсивность/Смягчение применяются заново БЕЗ пере-запекания кнопкой **Пост-обработка**.
- **Cage** / **Max Ray** — только в режиме **Hi → Low** (Max Ray 0 = авто).

### Превью и сохранение

После запекания внизу панели появляются два действия:

| Кнопка | Описание |
|---|---|
| **Показать текстуру** / **Скрыть текстуру** | Включает flat-эмиссия-превью запечённого результата прямо на модели (видно при любом освещении). Для стека слоёв показывает живой нодовый композит — правка прозрачности/режима/контраста/гаммы обновляет его мгновенно. Повторный клик возвращает исходные материалы и рендер-UV. |
| **Сохранить как** | Сводит включённые слои в одну текстуру (numpy-композит, sRGB) и сохраняет в файл, с опцией уменьшения **Размер**: `Оригинал` / `½` / `¼` / `⅛` (аккуратное box-усреднение — чище, чем печь сразу мелкое). |
| **Показать поверх базы (UV2)** | Превью-тумблер: строит нодовый материал, где **базовая текстура (через свою UV1)** умножается на **запечённый композит стека (через UV запекания, UV2)** — т.е. `TexUV1 × TexUV2`, эмуляция двухканального UV-вида в игре. Нужно, когда печёшь AO/LightMap в отдельную UV2 и хочешь видеть их поверх диффуза. Per-материал (у каждого слота своя база). Снять — **Скрыть текстуру**. |

> ℹ **Линейное пространство и сэмплы.** Композит теперь считается в линейном пространстве, поэтому **«Сохранить как»** и живое превью совпадают с тем, что видно в игре. Во время запекания отключается adaptive sampling — ползунок **Samples** реально влияет на результат (не обрубается ранней остановкой).

> 💡 **Пример — запечь AO + Diffuse и свести в текстуру для TXD:**
> 1. Выделите меш здания; убедитесь, что рабочая UV текстуры — это рендер-UV (📷). Откройте **Texture Bake**, задайте **Размер** 1024, **АА** `2×`, **Режим** → **UV → UV**.
> 2. **Добавить слой** → **Diffuse** → **Добавить** (базовый слой).
> 3. **AO** → **Добавить** (ляжет сверху с Multiply).
> 4. (Опц.) выберите слой AO и снизьте **Прозрачность**, чтобы смягчить затенение.
> 5. Нажмите **Bake** — на модели появится живой композит; осмотрите через **Показать текстуру**.
> 6. **Сохранить как** → `Оригинал` (или `½` для 512) → сохраните PNG.
> 7. Импортируйте этот PNG в свой TXD инструментами текстур/TXD как diffuse модели.

## Персонажи (Skinned DFF)

Импорт/экспорт моделей персонажей GTA SA со скелетом и анимациями.

> Это раздел про **скелетную анимацию персонажей/педов** (вкладка «Персонаж» в панели «Анимации»). Анимация статичных объектов с подвижными частями (мельницы, краны) — в разделе [Анимация объектов (Animated Map Objects)](#анимация-объектов-animated-map-objects).

**Импорт:**
- Armature с иерархией костей
- Vertex weights (скин)
- Bone matrices (Skin PLG)
- Совместимость с Kams Script и оригинальными моделями

**Экспорт:**
- Round-trip с побайтовой точностью
- Корректные material indices в BinMesh PLG

**Настройки экспорта для персонажей:** в свойствах объекта (`obj.inu`) рекомендуется включить **Normals** и отключить **Vertex Colors** — персонажи GTA SA используют нормали для динамического освещения движком, а не запечённые vertex colors как у зданий

> 💡 **Пример — импорт CJ и кастомизация:** File → Import → GTA SA DFF → `cj.dff`. Импортируется armature + mesh со скином. Отредактируй mesh (добавь шляпу, измени форму) → проверь weights → **Экспорт DFF** → получишь `cj_custom.dff` с тем же armature-скелетом, но изменённой геометрией. Анимации из `ped.ifp` применяются без переработки — скелет тот же.

### IFP Анимации

| Кнопка | Оператор | Описание |
|--------|----------|----------|
| Импорт IFP | `gtatools.import_ifp` | Загрузка анимаций (294+ в ped.ifp) |
| Экспорт IFP | `gtatools.export_ifp` | Сохранение Actions в IFP |
| Применить | `gtatools.apply_ifp` | Назначить анимацию скелету |

Список анимаций с поиском в панели.

> 💡 **Пример — просмотр анимации ходьбы:** импортировал `cj.dff` с armature → **Импорт IFP** → выбери `ped.ifp` → в список загрузились 294 анимации (WALK_civi, RUN_civi, IDLE_stance и т.д.). В поиске набери `walk` → выбери `WALK_civi` → **Применить анимацию** → на armature CJ применяется цикл ходьбы, жмёшь Play в Timeline — персонаж ходит.

> 💡 **Пример — batch-импорт папки анимаций:** 50 .ifp файлов в папке → Animations panel → **Batch папка…** → укажи папку → все IFP загружаются как отдельные Actions. Каждая анимация доступна через обычный Action Editor.

#### Экспорт: одна анимация или весь пак

По умолчанию **«Экспорт IFP»** собирает в файл **все** Actions, помеченные `ifp_source` (т.е. импортированные из `ped.ifp`), **плюс** активную. Это удобно для пересборки целого пака, но если нужна **ровно одна** анимация (своя новая ИЛИ уже существующая из импортнутого пака):

| Хочу | Кнопка | Опция |
|------|--------|-------|
| Одну анимацию **в новый .ifp** | **Экспорт IFP** | галка **«Только активную анимацию»** |
| Одну анимацию **дописать/заменить в существующем паке** (`ped.ifp`) | **Добавить в IFP** (`gtatools.merge_ifp`) | галка **«Только текущая анимация»** (вкл. по умолчанию) |

Обе берут **активную Action арматуры** (та, что назначена в Action Editor) и экспортируют только её — будь то ваша новая анимация или одна из 294 импортнутых. При merge остальные анимации пака сохраняются байт-в-байт (замена по имени, case-insensitive).

> 💡 **Пример — поправить одну ванильную анимацию:** Импорт IFP `ped.ifp` → в Action Editor выбери `WALK_civi` → правь ключи → **Добавить в IFP** → укажи тот же `ped.ifp` → с галкой «Только текущая» в пак запишется только обновлённый `WALK_civi`, остальные 293 не тронуты.

## Анимация объектов (Animated Map Objects)

**Панель:** View3D → Sidebar (N) → GTA Tools → **Анимации** → вкладка **Объект**

Штатный способ GTA SA анимировать **статичные объекты карты с подвижной частью** — мельницы, краны, флюгеры, ворота, пропеллеры, вентиляторы. INU Tools использует подход **Empty-риг** (как скрипт Kams для 3ds Max), а не armature — это обходит баг `rest_quat` костяного пути, из-за которого геометрию «дёргало».

> Это раздел про **анимацию объектов** (вкладка «Объект»). Скелетная анимация персонажей/педов — в разделе [Персонажи (Skinned DFF)](#персонажи-skinned-dff).

**Как собрать риг:**
1. Выдели **меш-основание** (статичная часть — станет корнем `root`).
2. **Пипеткой** (в боксе «Animated Map Object») выбери **подвижную часть** — создаётся риг: основание → `root` (статика), выбранная часть → новый pivot (анимируемый Empty).
3. Крути/двигай **pivot-Empty** по ключевым кадрам — это и есть анимация.
4. **Multi-part:** для нескольких подвижных частей повторяй пипетку (радио «В существующий риг»).
5. **Validate** — проверка структуры рига перед экспортом.

| Кнопка | Оператор | Описание |
|--------|----------|----------|
| DFF+IFP+IDE | `gtatools.animobj_export` | Записать разом все три артефакта анимированного объекта (главное действие вкладки) |
| Экспорт | `gtatools.export_ifp` | Сохранить только `.ifp` |
| Добавить | `gtatools.merge_ifp` | Дописать/заменить анимацию в существующем `.ifp` |
| Validate | `gtatools.animobj_validate` | Проверить риг (корень-статика + pivot'ы) |

**Обязательные артефакты:** `.dff` (модель с фреймами root+pivot), `.ifp` (анимация), строка в `.ide` секции **`anim`** (НЕ `objs`).

**Критичные правила:**
- Имя модели короткое — длинное имя ломает загрузку (крэш HAnim).
- В `.ide` объект должен быть в секции **`anim`**, иначе анимация не проиграется.
- В IMG должен лежать `<base>.ifp` — движок ищет анимацию по имени модели.

> 💡 **Пример — мельница:** выдели корпус (основание) → пипеткой ткни лопасти → покрути pivot по кадрам (0°→360°) → **Validate** → **DFF+IFP+IDE** → в игре лопасти крутятся. Пошаговый рецепт: [Рецепт: Animated Map Object](#рецепт-animated-map-object-мельница-кран-пропеллер).

## Зоны карты (map.zon)

**Панель:** View3D → Sidebar (N) → GTA Tools → map.zon

Зоны из `data/map.zon` и `data/info.zon` — прямоугольные области карты: `map.zon` держит зоны карты (тип 3), `info.zon` — навигационные зоны с названиями из GXT (тип 0). Тотальные конверсии добавляют свои типы (например 4 — погодные зоны). Формат строки один на оба файла:

```
имя, тип, x1, y1, z1, x2, y2, z2, уровень, GXT-ключ
LA01, 3, 480.0, -3000.0, -500.0, 3000.0, -850.0, 500.0, 1, UNUSED
```

| Кнопка | Описание |
|--------|----------|
| Импорт | Загрузить `.zon` — каждая зона становится каркасным боксом в коллекции `ZON_<имя файла>`. Повторный импорт того же файла заменяет старые боксы |
| Экспорт | Записать зоны обратно в `.zon`. Пишутся выделенные боксы, а если ничего не выделено — вся коллекция файла. Старый файл один раз копируется рядом как `.bak` |
| Новая зона | Бокс 100×100×100 в позиции 3D-курсора, тип 3 (зона карты) |
| Строки в буфер | Сгенерировать готовые строки для выделенных объектов и положить в буфер обмена (и в текстовый блок `INU_map_zon` в Text Editor) — вставляй руками в `map.zon`. Для обычного меша зона считается по его габаритам, так что можно выделить здание и сразу получить строку под него |

**Параметры зоны** (правятся в панели при выделенном боксе): имя, тип, уровень (остров/регион: 0 — общий, 1 — LS, 2 — SF, 3 — LV; моды расширяют), GXT-ключ (`UNUSED`, если названия нет). Координаты берутся из габаритов бокса — двигай и масштабируй его обычными средствами Blender.

**Что важно знать:**
- Порядок строк сохраняется: движок возвращает **первую** подходящую зону, поэтому перестановка меняет поведение. Новые зоны дописываются в конец.
- Зоны, которых не касались, пишутся исходной строкой символ в символ — импорт + экспорт без правок оставляет файл неизменным (комментарии, шапка и переносы строк тоже сохраняются).
- Перевёрнутый bbox (`x1 > x2` и т.п.) движок не найдёт никогда — такие зоны показываются в отчёте импорта, но молча не «чинятся».
- Движок режет строку по запятым **и пробелам**, так что лишний пробел внутри числа сдвигает все следующие колонки. Аддон читает так же, как игра, и сообщает о таких строках (см. системную консоль).

| Кнопка | Описание |
|--------|----------|
| Импорт NODES.dat | Загрузка бинарных нод (поддержка нескольких файлов одновременно) |
| Экспорт NODES.dat | Сохранение скомпилированных нод в выбранную папку |

**Импорт:** можно выбрать несколько файлов (nodes0.dat, nodes1.dat, ...) за раз. При импорте каждый объект получает свойство `nodes_filename` с именем исходного файла.

**Экспорт** работает в двух режимах:

> **Сетка зон:** карта GTA SA: от -3000 до +3000 по X и Y. Зоны нумеруются слева направо, сверху вниз (zone = gy × 8 + gx).

## Машины

**Панель:** View3D → Sidebar (N) → GTA Tools → **Машины**

Инструменты рабочего процесса с транспортом: быстрый экспорт одной модели, равномерное масштабирование всей иерархии машины и управление парами повреждений `_ok` / `_dam`.

| Кнопка | Оператор | Описание |
|--------|----------|----------|
| Экспорт машины (один DFF)… | `gtatools.quick_single_export` | Включает режим «Один DFF» и сразу открывает диалог экспорта — вся машина (с коллизией и сферами) уходит в один `.dff` |
| Масштаб машины… | `gtatools.vehicle_scale` | Пропорционально масштабирует всю иерархию (корневой Empty + меши + думми), запекая масштаб в данные меша. Опции: `factor` (множитель), `dummies_only` (двигать только думми) |
| Создать _dam | `gtatools.vehicle_add_damage_variant` | Повреждённый дубликат (`_dam`) активного меша (исходник при необходимости переименуется в `_ok`). `_dam` скрыт во вьюпорте, но всё равно экспортируется в DFF |
| Показать: OK / Dam / Оба | `gtatools.vehicle_show_damage` | Переключает видимость во вьюпорте: целый / повреждённый / оба. Только превью — на экспорт не влияет |
| Проверить пары | `gtatools.vehicle_pair_report` | Ищет пары `_ok`/`_dam`, сообщает о непарных мешах (их движок пропускает при повреждении). Детали — в системной консоли |

### Иерархия фреймов

Свёрнутая подпанель под «Машины» — дерево фреймов активного объекта с переподчинением по строкам, плюс проверка и зеркалирование L/R. Имена фреймов пишутся в DFF как есть, поэтому точность важна.

| Кнопка | Оператор | Описание |
|--------|----------|----------|
| Validate Vehicle | `gtatools.frame_validate` | Сверяет имена думми с ванильным шаблоном SA, показывает недостающие обязательные и подозрительные имена колёс (без `_lf/_rf/_lb/_rb`) |
| Зеркало L↔R | `gtatools.frame_mirror_lr` | Для выделенных фреймов с `_lf`/`_lb` создаёт зеркального близнеца (`_rf`/`_rb`) с отражённым по X положением |
| ⤴ (в строке) | `gtatools.frame_reparent` | Сделать этот фрейм родителем активного (мировая позиция сохраняется, `matrix_parent_inverse` сбрасывается — требование DFF) |
| ⛓ (в строке) | `gtatools.frame_reparent` | Отвязать фрейм (сделать корневым) |
| Имя фрейма | `gtatools.frame_select` | Клик делает фрейм активным. **F2** — переименовать активный фрейм |

> 💡 **Типичный порядок:** масштабировать при необходимости → выделить меш и «Создать _dam» для каждого повреждённого двойника → отредактировать `_dam` → превью OK/Dam/Оба → «Проверить пары» → «Экспорт машины (один DFF)».

## Тайм-циклы (timecyc.dat)

**Панель:** View3D → Sidebar (N) → GTA Tools → **Тайм-циклы**

Читает `data/timecyc.dat` (и `timecycp.dat`), превращает погоду + час в
настоящее освещение Blender и пишет правки обратно в файл.

В файле по блоку на каждую погоду (в ванильной SA их 23), внутри каждого —
ровно **8 временны́х срезов**: 00:00, 05:00, 06:00, 07:00, 12:00, 19:00,
20:00, 22:00. Игра линейно интерполирует между соседними срезами (22:00 →
00:00 идёт через полночь), панель делает то же самое: слайдер часа
непрерывный, но правится всегда **срез**, а не произвольный час.

| Кнопка | Описание |
|--------|----------|
| Импорт | Загрузить `timecyc.dat`, применить к сцене и перевести вьюпорты в Material Preview |
| Экспорт | Записать файл обратно. Нетронутые строки уходят байт-в-байт (с комментариями, табами и CRLF), рядом остаётся `.bak` прежнего файла |
| **Тайм-цикл вкл/выкл** | Мастер-тумблер сверху панели: **ВКЛ** — применить весь цикл к сцене (свет, туман, игровой вид прилайта на моделях) и включить живое превью; **ВЫКЛ** — полный сброс (материалы обратно в PBR, мир и композитор чистые) |
| Откатить срез | Вернуть текущий срез к значениям на диске |
| Перечитать файл | Перечитать с диска, отбросив несохранённые правки |
| Во все срезы погоды | Скопировать текущий срез во все 8 срезов этой погоды |

**Живое превью — всегда.** Пока цикл включён, любое изменение часа/погоды/полей среза сразу пересобирает сцену — отдельных кнопок «Живое превью» и «Применить» больше нет, вьюпорт переводится в Material Preview автоматически. Слайдер часа тянет за собой **срез**: тащишь час к 21:00 → «Правка среза» переключается на ближайший срез (20:00) и снизу видно его поля; выбор среза в дропдауне, наоборот, ставит час на время этого среза.

**Что во что ложится**

| timecyc | Blender |
|---------|---------|
| Sky top / Sky bot | Градиент мира — цвет зенита ↔ горизонта, крутизна задаётся «Резкость горизонта» |
| Amb / Amb_Obj | Ambient-фон (какой из двух брать — тумблер в настройках превью) |
| Dir + DirectionalMult | Цвет и сила лампы-солнца `INU_Timecyc_Sun` |
| SunSz | Угловой размер солнца |
| FarClp | Плотность тумана и, по желанию, clip end вьюпорта |
| WaterRGBA | Базовый цвет и альфа материала импортированной воды (`waterclear256`) |
| PostFX 1 / 2 | Цветофильтр кадра — **всегда включён** при активном цикле (отдельного тумблера нет, без него картинка не совпадает с игрой). Игра рисует его полноэкранным квадом с текстурой кадра, блендом `SRCALPHA/ONE`, то есть `out = in*(1 + rgb1*a1 + rgb2*a2)` (SkyGfx `postfx.cpp`, PC-путь). Для ванильного `EXTRASUNNY_LA` в полдень это множитель **1.91 / 1.76 / 1.42** — ровно поэтому кадр игры светлее и бирюзовее сырого неба из timecyc. Накладывается **экранной** стадией в композиторе, сразу после тумана и на весь кадр — небо включительно, — умножением в gamma-пространстве, ровно там же, где его накладывает игра |

**Совпадение с освещением игры**

SA — не PBR, поэтому превью не освещает сцену так, как это сделал бы Blender по умолчанию. Что движок делает на самом деле (по реверснутым пайплайнам):

```
prelight = day*dayparam + night*nightparam
color    = (prelight*surfDiff + ambient*surfAmb) * matCol      // ambient ПРИБАВЛЯЕТСЯ
final    = color * texture
```

(SkyGfx `shaders/vs/xboxBuildingVS.hlsl` / `ps2BuildingVS.hlsl`; регистр ambient заполняется из `CTimeCycle::GetAmbient* × CCoronas::LightsMult`.) Здания **не** получают directional и **не** отбрасывают теней — всё их освещение запечено в вершинные цвета. Directional и более яркий `Amb_Obj` достаются машинам, педам и объектам (`MTACalcGTAVehicleDiffuse`: `saturate(TotalDiffuse + TotalAmbient + emissive)`).

Панель повторяет это:

| Тумблер | Что делает |
|---------|------------|
| **Как в игре (unlit)** (по умолчанию вкл) | Цвет прилайта уходит прямо в Emission, мимо PBR — ни теней, ни бликов, ни синевы от неба. Именно это делает вьюпорт похожим на игровой скриншот. |
| **Применить к моделям сцены** | Включает превью прилайта на всех мешах с вершинными цветами и подвязывает их к текущему режиму — быстрый способ привести в порядок всю импортированную карту. |
| **Туман** (по умолчанию вкл) | Угасание в цвет горизонта по расстоянию — **экранная** стадия в композиторе, по пассу глубины, ровно как fixed-function fog в игре. Поэтому он ложится на весь кадр, включая объекты, куда превью прилайта не заглядывало. `FogSt` и `FarClp` берутся из среза в метрах (`TimeCycle.cpp` хранит их как есть; far clip подтягивается к 1000, когда камера выше 200). Ручки: **Кривая тумана** (1 — честная линейка RW, больше — дымка уходит ближе к горизонту) и **Дальность тумана ×** (на кадр в игре влияет ещё и ползунок дальности прорисовки, которого в timecyc нет). Порог неба зашит как **0.819 × клип вьюпорта**: небо (на дальности клипа) остаётся без тумана — градиент цел, — а вся геометрия ближе клипа попадает в туман. Раньше на больших картах туман «обрезался» на краю (дальняя геометрия торчала чёткой) или, наоборот, заливал небо — теперь порог сам едет за реальным клипом. |

Ambient (`Amb`) прибавляется к прилайту внутри общей нод-группы и затем обрезается по 1.0 (`saturate`) — ровно как в движке. Поэтому в полдень он в панели почти чёрный: всю дневную яркость даёт запечённый prelight, а не ambient.

Отсюда же и то, что **погода меняет силу прилайта**. Отдельного множителя прилайта по погоде в движке нет: `CCoronas::LightsMult`, который масштабирует регистр ambient, — это всего лишь фейд-ин к 1.0 после загрузки (`LightsMult = min(TimeStep*0.03 + LightsMult, 1)`), а не погодная величина. Отличается сам `Amb`: у ясного среза он почти чёрный, и запечённый prelight виден во всём контрасте; у пасмурного или дождливого `Amb` заметно светлее — он поднимает тени и «замывает» прилайт. Сравни свотч `Amb` у двух погод в редакторе среза — весь эффект там.

Туман и PostFX — **экранные** стадии: они живут в композиторе сцены (ноды `INU_TC_*`) и требуют включённого Compositor в шейдинге вьюпорта — аддон включает его автоматически при включении цикла (Импорт / мастер-тумблер). Blender считает вьюпортный композитор на EEVEE, а превью и так на нём. Свои композиторные ноды не трогаются: то, что питало `Composite` до нас, запоминается и возвращается, когда оба тумблера выключены. В Solid-режиме композитора нет, там обоих эффектов не будет.

Объекты **без** превью прилайта остаются на обычном PBR: их освещает мир (по умолчанию ambient `Amb_Obj`, небо при этом только фон для камеры), и нодового тумана у них нет.

**Прилайт по времени суток (Day ↔ Night)**

SA держит ночные вершинные цвета отдельной секцией DFF (Extra Vert Colour), а движок пишет в сам прилайт смесь:

```
preLit = day * (1 - dnParam) + night * dnParam
```

(`CCustomBuildingDNPipeline::SetPrelitColors`; в игре смена дня на ночь приходится на 20:00 → 21:00 — те же часы, когда зажигаются фонари и фары.)

**Прилайт по времени суток** повторяется нодами и **всегда включён** при активном цикле (отдельного тумблера в UI нет): одна общая группа `INU_Timecyc_DayNight` читает атрибуты `Day` и `Night` и микширует их по единственному внутреннему Value. Слайдер часа меняет это одно число, поэтому карта обновляется целиком, не трогая сотни материалов.

- Режим цепляется к материалам, где уже включено **превью прилайта** — если таких нет, панель об этом говорит (нажми «Применить к моделям сцены»).
- Часы заката и рассвета зашиты: 20:00 → 21:00 (из движка) и 05:00 → 06:00 (по срезам timecyc). Раньше их можно было править в UI — блок убран, значения фиксированы.
- Меши без атрибута `Night` остаются на дневных цветах: группа смотрит на альфу ночного атрибута, а у отсутствующего она нулевая — ночью ничего не чернеет.

**Что стоит знать:**
- Ширина строки определяется по файлу: ваниль SA — 51 значение (`Dir` RGB есть, `DirectionalMult` нет), в некоторых сборках 52. Укороченные строки — в ванилле такая есть в блоке `UNDERWATER` — сохраняют свою ширину при экспорте, колонка не добавляется и не теряется.
- Если строка короче схемы, панель об этом говорит: её поля читаются со сдвигом — ровно так, как их читает парсер игры.
- Туман — **экранная** стадия композитора (не World volume), по умолчанию включён вместе с циклом; на полной карте он стоит реальных кадров вьюпорта, так что при просадках выключи тумблер **Туман**.
- Это совпадение атмосферы, а не пикселей. SA не PBR — там `текстура × (prelight vcol × ambient + directional)` — так что панель для подбора света и скриншотов, а не для предсказания игрового кадра один в один.

**Панель:** View3D → Sidebar (N) → GTA Tools → Itera Tools 3

| Кнопка | Описание |

**Порядок работы:**
1. Нажмите **Vertex Lit Linear** — на модель наложится материал для просмотра освещения
2. Нажмите **Quickstart** — появится модификатор и коллекция с лампами
3. Расставьте и настройте освещение как нужно
4. В модификаторе модели выставьте **Output Type / Bake → Цвета вершин**
5. В поле **Export Vertex Color** впишите имя вашего атрибута цвета — `Day` или `Night`
6. Когда освещение готово — **примените модификатор**

Панель видна только когда Itera Tools 3 установлена в Asset Libraries.

### LightMap (beta_MTA)

**Панель:** View3D → Sidebar (N) → GTA Tools → Lightmap Generator (beta)

Генерация Lua кода для MTA SA скриптов лайтмапов. MTA скрипт в рантайме заменяет шейдеры на моделях, добавляя второй UV слой с лайтмапом поверх основных текстур.

**Полный порядок работы:**

1. **Создайте UV1** — основная развёртка для текстур модели (кирпичи, крыша и т.д.)
2. **Создайте UV2** — вторая развёртка специально для лайтмапа. Каждый полигон должен занимать уникальное место, без перекрытий. В Blender: UV Editor → UV → Smart UV Project или вручную
3. **Запеките освещение в текстуру по UV2** — используйте любой удобный способ запекания (Blender Bake, Cycles, сторонние аддоны). Главное — результат должен быть записан в текстуру по развёртке UV2
4. **Сохраните лайтмап** как PNG файл (например `lightmaps/building01.png`)
5. **Экспортируйте DFF** — убедитесь что в свойствах объекта включены оба UV слоя (`uv_map1` и `uv_map2`). Аддон запишет оба UV в DFF файл
6. **Генерируйте код:**
   - Выделите объект
   - Укажите **путь к лайтмапу** (относительный, как в ресурсах MTA)
   - Укажите **Model ID**
   - Нажмите **Генерировать**
7. **Скопируйте** результат в MTA Lua скрипт

| Кнопка | Оператор | Описание |
|--------|----------|----------|
| Загрузить лайтмап | `gtatools.load_lightmap` | Загрузить изображение лайтмапа для превью |
| Удалить лайтмап | `gtatools.remove_lightmap` | Удалить загруженный лайтмап |
| Генерировать | `gtatools.lightmap_generate` | Генерировать Lua код из текстур объекта |
| Копировать | `gtatools.lightmap_copy` | Копировать результат в буфер обмена |
| Очистить | `gtatools.lightmap_clear` | Очистить код |

**Результат:** Lua таблица с именами текстур и ссылками на лайтмап:
```lua
{
    textures = {
        "brick_wall",
        "roof_tile",
    },
    lightmap = "lightmaps/building01.png",
    models = {3500}
},
```

> **ВАЖНО:** UV2 обязателен — без второго UV слоя лайтмап наложится по координатам UV1 и будет выглядеть неправильно.

Сам MTA скрипт для лайтмапов доступен в разделе [Issues](../../issues) репозитория.

### Pipeline

Выбор рендер-пайплайна определяет как движок GTA SA обрабатывает модель:
- **None** — без пайплайна. Подходит для большинства объектов: мебель, заборы, растения, персонажи
- **Building** (0x53F2009A) — Day/Night vertex colors. Обязателен для зданий и объектов карты у которых есть vertex colors — без этого пайплайна цвета дня/ночи не будут переключаться при смене времени суток в игре
- **Reflections** (0x53F20098) — отражения на окнах. Только для моделей окон, которые должны отражать окружение. Окна должны быть отдельной моделью от здания

> 💡 **Пример:** дом `house01` должен иметь день/ночь освещение → Object Properties → INU Tools: Model → Pipeline = **Day/Night**. Окна этого дома вынеси в отдельный меш `house01_windows` → его Pipeline = **Reflections** чтобы они отражали улицу. Забор перед домом `house01_fence` → Pipeline = **None**.

### Normals

Переключатель **Normals** управляет экспортом нормалей вершин в DFF:
- **Включено** — модель получает динамическое освещение от движка GTA SA. Нужно для: персонажей, транспорта, оружия, интерактивных объектов
- **Выключено** — модель освещается только запечёнными vertex colors. Используется для: зданий, дорог, объектов карты

> 💡 **Пример:** CJ (персонаж) — ☑ Normals (его освещает движок в зависимости от солнца и фонарей). Здание на карте с запечёнными vertex colors — ☐ Normals (иначе движок сверху наложит своё освещение и картинка испортится).

### Мост Ariane

Живая двусторонняя связь редактора карт **Ariane** и Blender — кликаешь модель в Ariane, и она прилетает в блендер готовой к правке; обратно — одной кнопкой.

**Панель:** N → GTA Tools → **Экспорт / Импорт** → вкладка **Ariane**. Сверху — общий **блок выделения** (Выделено / DFF / LOD / COL); ниже сгруппированы контролы моста.

| Контрол | Что делает |
|---------|-----------|
| 📁 папка игры | Путь к игре — мост обменивается файлами через `<игра>\ariane\bridge`. **Задай первым**; строка красная, пока не указан. |
| **Ручной импорт** | Забрать то, что Ariane положил в inbox, один раз. |
| **⟳ Авто** | Включить watcher — авто-импорт моделей по мере отправки из Ariane. |
| **Экспорт → Ariane** | Отправить выделенные меши обратно в Ariane (DFF + TXD + прикреплённые **2DFX**-пустышки — прямые дети меша, как в обычном экспорте: короны, частицы и т.п. улетают вместе с DFF). |
| **COL / LOD / Позиция** | Включать в этот экспорт коллизию / дальний LOD / позицию. |
| **Live-синхронизация** | Двусторонний живой синк позиции, выделения и камеры Blender ↔ Ariane (нужен включённый watcher ⟳). |
| **Ещё** ▸ | Редкое/продвинутое: **Синхр. удаления** (удаление в блендере мягко удаляет инстанс в Ariane), **Создать модель** (зарегистрировать новую модель), **Очистить кэш**. |

**Пайплайн:**
1. Укажи **папку игры** (📁).
2. В Ariane нажми **Export to Blender** на модели → она появится в блендере (включи **⟳ Авто**, чтобы авто-импортировать всё выделение по мере поступления).
3. Правь / прелайти модель в блендере.
4. **Экспорт → Ariane** → она пересобирается в игре.
5. Для живой правки включи **Live-синхронизацию** — двигаешь/выделяешь в любом из приложений, второе повторяет.

## Asset Library

**Панель:** View3D → Sidebar (N) → **GTA Library** (отдельная вкладка N-панели, `bl_category='GTA Library'` — не внутри вкладки GTA Tools) → Asset Library

Собирает Blender Asset Library из любого набора IDE/IPL/IMG — vanilla SA, кастомной карты или мод-архива. Каждый проп становится mark-as-asset с превьюшкой, которую можно дропнуть в сцену из **Asset Browser** Blender'а.

**Workflow:**
1. **Сохрани .blend** — обязательно (билдеру нужна рабочая папка).
2. **Укажи Game Root + Регион** (в Setup-панели) — путь к папке с `gta_sa.exe`; регион сужает парсинг IDE/IPL.
3. **Извлечь ресурсы** — распаковывает кеш DFF/TXD/COL один раз. Повтор пропустит уже распакованное.
4. **Укажи папку Output** — пустая папка где будут лежать `.blend` библиотеки и превьюшки.
5. Жми **Собрать Asset Library**. Status text показывает фазу (cache scan → IDE read → preview gen → finalise).
6. **Edit → Preferences → File Paths → Asset Libraries → Add → твоя Output папка**.

После этого в Asset Browser появятся все ванильные пропы как drag-and-drop превьюшки.

**Опции:**
- *Размер превью (px)* — разрешение thumbnails (default 256, больше = медленнее но чётче).
- *Без превьюшек* — самый быстрый режим, использует Blender placeholder-иконки. Подходит для быстрых итераций.
- *Пропускать готовые .blend* — инкрементальная пересборка; обработаются только новые модели.
- *Перегенерировать превью* — повторный thumbnail-проход без перераспаковки.

> 💡 **Первая сборка медленная** (~15–30 мин для полной vanilla карты при 256 px; кастомные карты обычно собираются за минуты), пересборки — тоже минуты благодаря тоглу «Пропускать готовые .blend».

### Map Export

Единый экспорт района сцены одной кнопкой: DFF + COL + TXD + IDE + IPL в одну папку.

**Где:** View3D → Сайдбар (N) → GTA Tools → панель *Map Export* → кнопка **Export Map…**

**Workflow:**
1. Выдели объекты, формирующие район (DFF меши, их LOD и COL — определяется по суффиксу/префиксу).
2. Жми *Export Map…*, выбери целевую папку.
3. Переключи что писать (DFF / COL / TXD / IDE / IPL) и опционально *Binary IPL*.
4. Задай *Base Name* (используется как имя общего TXD/IDE/IPL) и *ID Pool Start* (первый авто-присваиваемый Model ID для DFF с `model_id == 0`).

**Что делает:**
- Группирует объекты по базовому имени через `get_model_type()` — один DFF + опционально LOD + ноль-или-больше COL на группу
- Авто-присваивает Model ID из диапазона `[id_pool_start, 19999]` тем DFF у которых `inu.model_id == 0`, записывая обратно в объект
- Экспортирует per-group `*.dff` и `*.col` существующими экспортёрами
- **TXD: один `.txd` на каждое уникальное `inu.txd_name`** — DFF с одинаковым `txd_name` (например `vegas01.txd` шарится 50 зданиями) баккетятся в один общий TXD; DFF с собственным TXD (`cj.txd`) получают свой файл. Пустой `txd_name` фолбэчится на имя модели. Сохраняет ванильный SA-лейаут точно при импорте с IDE-заполненными `txd_name`
- **COL: одна `.col` библиотека на каждое уникальное `inu.col_name`** (при включённом тумблере `col_library`) — тот же паттерн что у TXD. `col_name` автоматически заполняется при Map Import именем исходного `.col` файла (`vegasN`, `LAs`, `LAn`, …). Round-trip восстанавливает оригинальный библиотечный файл со всеми моделями. Пустой `col_name` → fallback на `txd_name`, потом на имя модели. Если `col_library` выключен — вместо этого пишется отдельный `<base>.col` на каждую DFF
- Пишет один `{base_name}.ide` (секция objs) и один `{base_name}.ipl` (секция inst), покрывающие всю выборку
- Оператор работает как **модальный генератор** с window-manager таймером: статус-бар показывает текущую группу / TXD-бакет / IPL-стадию (`vegasN: TXD vegas02 (12 моделей)`), viewport остаётся отзывчивым, **ESC** отменяет экспорт.

Источник: [`tools/map_export.py`](INU_tools/tools/map_export.py).

#### Режимы разбиения (auto-split на районы)

Дропдаун **Разбиение** в сайдбаре диалога Map Export управляет тем, как выделение режется на отдельные district'ы при экспорте. Три режима:

| Режим | Имена district'ов | Когда использовать |
|---|---|---|
| **Без разбиения** (по умолчанию) | Один district с именем `base_name` | Маленькие хэндкрафтед карты, явное именование |
| **XY-сетка** | `<base>_x<cx>_y<cy>` на каждую непустую ячейку | Очень большие сцены (50k+ DFF), стриминго-чувствительные моды, совместное авторство по пространственным регионам |
| **По коллекциям** | Имя верхней коллекции на каждый бакет | Round-trip с Group-by-IPL импортом — `vegasn_stream0` в Blender → `vegasn_stream0.ipl` на выходе |

##### XY-сетка

Координата world-origin `(x, y)` каждой DFF делится на `cell_size` и округляется вниз (floor) — получается индекс ячейки `(cx, cy)`. LOD/COL-сиблинги едут вместе со своим DFF; принадлежность к ячейке решается только по DFF. Каждая непустая ячейка становится подпапкой `<base>_x<cx>_y<cy>` внутри target_dir (отрицательные индексы получают префикс `m`, например `district_xm3_y1` — чтобы имя папки никогда не начиналось с минуса). Если разбиение даёт ровно одну ячейку, оператор тихо откатывается к *Без разбиения* — поэтому держать режим включённым на маленькой сцене безопасно.

**Гайд по cell_size:** 256 м соответствует ванильному радиусу стриминга SA (модель в ячейке N становится видимой игроку примерно при заходе в ячейки N±1). 128 м для очень плотных интерьеров; 512 м или 1024 м когда большинство моделей — крупные террейн-меши (хайвэи, реки).

##### По коллекциям

Биннит DFF по имени верхней пользовательской коллекции (той, что лежит прямо под scene root'ом). Имя коллекции становится именем district'а — то есть коллекция `vegasn_stream0` в outliner произведёт `vegasn_stream0.ipl`, `vegasn_stream0.ide`, `vegasn_stream0.col`, `vegasn_stream0.txd` внутри `target_dir/vegasn_stream0/`. Это естественный round-trip для *Map Import → Group by IPL → правка → реэкспорт*: оператор Map Import именует родительские коллекции под имена исходных IPL, а реэкспорт в режиме *По коллекциям* восстанавливает оригинальную структуру district'ов.

DFF, лежащие только в scene root коллекции (или вообще без коллекции), попадают в бакет `unsorted/`. Если только один бакет содержит DFF, оператор откатывается к *Без разбиения* — поэтому этот режим тоже безопасно держать включённым на маленькой curated-сцене.

Источник: [`tools/map_export.py`](INU_tools/tools/map_export.py) → `compute_grid_cells`, `compute_collection_cells`, `format_cell_name`, `_build_top_collection_lookup`, `export_map(..., split_mode='GRID' | 'COLLECTION', cell_size=...)`.

### Binary IPL Write

Добавляет запись в формате `bnry` в IPL-экспортёр (чтение уже было).

**Где:** File → Export → *Export IPL* → чекбокс **Binary (bnry)**.

**Формат:** 76-байтный заголовок (магия `bnry` + 6 uint32 счётчиков + 12 uint32 смещений), потом массивы `inst` (40 байт на запись: 7 float + 3 int) и `cars` (48 байт: 4 float + 8 int). Другие секции (`cull`, `grge`, `zone`, …) **не** пишутся — бинарные IPL от Rockstar содержат только `inst` и `cars`.

Источник: [`core/ipl.py`](INU_tools/core/ipl.py) → `_write_binary_ipl`, `write_binary_ipl`, `write_ipl(..., binary=True)`.

### UV-анимация `(2.1.0)`

UV-анимация GTA SA (чанки `0x2B` — словарь UV-анимаций + `0x135` — плагин материала, раскладка Kam's `UVanim_tool`) задаётся на **материале** и проигрывается прямо во вьюпорте. В v2.1.0 она разбита на два режима — постоянная **Прокрутка** и покадровые **Ключевые кадры** на ноде Mapping — плюс живой предпросмотр по Пробелу.

**Панель материала:** Properties → Material → *GTA Material* → блок **UV Анимация**.

**Пайплайн (общая настройка):**
1. Сделай материал с нодой **Image Texture**, идущей в *Base Color* BSDF (для прокрутки — тайлящаяся текстура).
2. Включи ☑ **UV Анимация**. Это и помечает материал на экспорт, и строит в шейдере связку предпросмотра (`UVMap → Mapping → Vector текстуры`, ноды `INU_UVAnim_*`).
3. Задай **Имя анимации** — имя UVAnim в DFF (по умолчанию имя материала, до 31 символа).
4. Выбери режим ниже (**Прокрутка** / **Ключевые кадры**), задай значения и нажми **Пробел** во вьюпорте, чтобы увидеть движение текстуры (режим Material Preview или Rendered).

> Если тумблер **выключить**, ноды предпросмотра удаляются, а входы Vector текстур освобождаются — меш возвращается к статичным UV. Предпросмотр цепляется только к текстурам с *несвязанным* входом Vector, поэтому твой собственный маппинг не ломается.

#### Режим «Прокрутка» (постоянная скорость)

**Панель материала:** *GTA Material* → **UV Анимация** → **Прокрутка**.

Постоянная линейная прокрутка. Предпросмотр вешает на *Location* ноды Mapping драйверы (`speed × frame / fps`), поэтому вьюпорт едет ровно с той скоростью, что уйдёт в экспорт.

**Настройки:**
- **Speed U** — единиц/сек по U. `+` — вправо, `−` — влево.
- **Speed V** — единиц/сек по V. `+` — вниз, `−` — вверх.
- **Длительность** — длина цикла в секундах.

При экспорте пишутся два ключа: t=0 (identity) и t=Длительность со сдвигом = `speed × duration`.

**Подбор скорости и длительности:** для бесшовного цикла `Speed × Длительность` должно быть **целым числом UV-единиц** (1, 2, 3…). Дробное произведение (например 0.7) даёт рывок на каждом обороте цикла.

| Эффект | Speed U | Speed V | Длительность | Сдвиг за цикл |
|---|---|---|---|---|
| Медленный конвейер (вниз) | 0 | 0.5 | 2.0 | 1 ед. V |
| Быстрая лента влево | −2.0 | 0 | 1.0 | 2 ед. U |
| Бегущий неон вправо | 1.0 | 0 | 4.0 | 4 ед. U |
| Вода (диагональ) | 0.2 | 0.1 | 5.0 | 1 ед. U + 0.5 V |

> 💡 **Пример — текущая вода / конвейер:** сделай тайлящуюся полосатую текстуру, включи **UV Анимация** → **Прокрутка**, задай **Speed V = 0.5**, **Длительность = 2.0** (= 1 ед. V за цикл, бесшовно). Нажми Пробел — поверхность течёт во вьюпорте, и то же движение уходит в DFF.

#### Режим «Ключевые кадры» (своя анимация) `(2.1.0)`

**Панель материала:** *GTA Material* → **UV Анимация** → **Ключевые кадры**.
**UV Editor → N → GTA Tools → UV Анимация:** вставка/очистка ключей здесь.

Вместо фиксированной прокрутки ты сам расставляешь ключи на **Location** (сдвиг UV) и **Scale** ноды Mapping предпросмотра. Экспортёр читает эти ключи и пишет их как реальные кадры UVAnim — несколько шагов, задержки, скачки, пульсация масштаба. В этом режиме драйверы не ставятся, поэтому ключи свободны для редактирования.

В режиме **Ключевые кадры** панель материала просто отсылает в UV-редактор. Открой **UV Editor** (в панели GTA Tools есть кнопка, чтобы отделить его), нажми **N** и открой панель **GTA Tools → UV Анимация**. Там:
- **Кадр** — текущий кадр таймлайна.
- **Сдвиг UV** — *Location* X/Y ноды Mapping на этом кадре.
- **Масштаб** — *Scale* ноды Mapping на этом кадре.
- **Вставить ключ** — ставит ключ на Location и Scale на текущем кадре (если связка не создана — создаёт её).
- **Очистить** — удаляет все ключи UV-анимации этого материала.

**Пайплайн:**
1. Панель материала → включи **UV Анимация**, выбери **Ключевые кадры**.
2. UV Editor → N → **GTA Tools → UV Анимация**.
3. Перейди на кадр, задай **Сдвиг UV** / **Масштаб**, нажми **Вставить ключ** (подсказка панели: «Меняй Сдвиг/Кадр → Вставить ключ»).
4. Сдвинь таймлайн, поменяй значения, снова **Вставить ключ**. Повтори на каждый шаг.
5. **Пробел** — предпросмотр; экспортируй, когда устроит. Первый ключ становится t=0; времена кадров переводятся в секунды по FPS сцены, последний ключ задаёт длительность.

> Каждый ключ хранит Location (сдвиг UV) и Scale. Если панель пишет «Нода не создана (нет текстуры?)», значит у материала нет Image Texture со свободным входом Vector — добавь/подключи. Если переключиться в режим ключей, но **не** поставить ни одного ключа, экспорт тихо откатится к Прокрутке (Speed U/V).

> 💡 **Пример — переключающаяся вывеска на 4 кадра:** разверни грань вывески на колонку 1 текстурного атласа из 4 колонок. Кадр 1: **Сдвиг UV = (0, 0)** → **Вставить ключ**. Кадр 13: **(0.25, 0)** → ключ. Кадр 25: **(0.5, 0)** → ключ. Кадр 37: **(0.75, 0)** → ключ. С constant-интерполяцией получишь жёсткое переключение между 4 состояниями; с линейной — плавную бегущую строку.

#### Экспорт и поддержка движком

Любой путь экспорта DFF (одиночный DFF, Export All, Export в IMG) автоматически подхватывает флаг **UV Анимация** материала и пишет словарь `0x2B` + плагин материала `0x135` — флаг в IDE не нужен. После замены DFF в IMG сделай **Rebuild Archive**, чтобы игра сбросила кэш старой версии.

> ⚠️ **Главная причина «анимации нет в сингле» — ночные вершинные цвета.** Если на модели есть ночные vertex colors (флаг **Night** в DFF Flags, либо пайплайн **Day/Night**, который пишет в DFF `extra_colors`), ретейл-движок GTA SA **не проигрывает** UV-анимацию: цвет на модели появится, а движения не будет. Это проверено в игре и описано в туториалах по SA. **Просмотрщики на librw** и **euryopa** ночные цвета игнорируют, поэтому у них анимация идёт — из-за этого кажется, что виноват экспорт/DFF, хотя это не так. **Решение:** сними флаг **Night** / убери ночной слой на анимируемой модели (дневной prelight можно оставить, чтобы модель не была чёрной). Аддон сам подсвечивает конфликт — строка **Night** в DFF Flags краснеет, а «Проверка перед экспортом» выдаёт предупреждение, если на меше есть одновременно UV-аним материал и ночные цвета.

Ещё два условия из туториалов: анимируемый **материал не должен быть общим** с другими частями модели (текстуру шарить можно); на **скинах и машинах** UV-аним в сингле не отображается — только на статичных моделях карты (с **Breakable** совместимо).

**Прочее про движок:** помимо ночных цветов рендер ретейл-сингла в целом избирателен к UV-анимации. **Просмотрщики на librw** и **MTA:SA с шейдером** (см. воркфлоу про MTA-шейдер) анимируют её корректно. Если движения нет и ночных цветов на модели точно нет — проверь, переимпортировав DFF (round-trip восстановит **Speed U/V + Длительность** режима Прокрутки) или открыв файл в librw-вьювере.

### Breakable Objects

Помечает меш как разрушаемый физическим движком GTA SA через чанк `0x253F2FD`.

**Где:** Properties → Object → панель *GTA SA: IDE / IPL* → блок **Разрушаемый (Breakable)** (чекбокс) + **Break Force**.

**Что пишется:** 32-байтный breakable-чанк в geometry extension с размерами буферов vertex/face/material/UV, взятыми из экспортируемого меша, плюс сила разрушения. Дефолты повторяют то, что пишет `brakableobjects.ms` от Kams.

Источник: [`core/dff.py`](INU_tools/core/dff.py) → `BreakableData`, `CHUNK_BREAKABLE`; [`ops/dff_export.py`](INU_tools/ops/dff_export.py) → breakable-блок внутри `_process_mesh`.

### Фрагменты (раскол меша)

Раскалывает выделенный меш на отдельные объекты-осколки — заготовки для breakable-объектов и эффектов разрушения. Порт `object_explode.ms`.

**Где:** View3D → Sidebar (N) → GTA Tools → **Проверка** → кнопка **Фрагментация меша** (диалог).

**Режимы:**
- **Сетка (шаг X/Y)** — нарезка по прямоугольной сетке с заданным шагом.
- **Кластеры (N семян)** — группировка граней по ближайшему из N случайных семян (грубая voronoi-разбивка без новых резов — существующие грани лишь делятся на группы).

Осколки — полные копии объекта с удалёнными «чужими» гранями, поэтому UV, vertex-color и материалы сохраняются как есть. Опции: **Имя осколков**, **Seed**, **Удалить оригинал** (по умолчанию ВКЛ). Новые резы не добавляются — для настоящего геометрического фрактуринга используйте встроенный Blender **Cell Fracture**.

Источник: [`ops/fragment_ops.py`](INU_tools/ops/fragment_ops.py) → `GTATOOLS_OT_fragment_mesh`.

### IFP Batch Import

Импорт папки с `.ifp` файлами и укладка всех анимаций на один NLA-трек активного armature.

**Где:** View3D → Сайдбар (N) → GTA Tools → панель *Анимации* → кнопка **Batch папка…**.

**Опции:**
- **Name Prefix** — применять только анимации с именем, начинающимся с этого префикса (регистронезависимо). Пусто = все.
- **Режим: NLA Sequential** — укладка клипов на один NLA-трек с зазором
- **Режим: Actions Only** — просто создать Actions, без NLA
- **Gap Between Clips** — кадров между соседними strip'ами (только для NLA)

**Юзкейс:** прокрутить все 294 анимации из `ped.ifp` подряд, не импортируя каждую руками.

Источник: [`ops/ifp_import.py`](INU_tools/ops/ifp_import.py) → `enumerate_animations`, `batch_apply_sequential`, `GTATOOLS_OT_ifp_batch_import`.

### Камеры (катсцена .dat)

Импорт/экспорт траектории катсцен-камеры GTA — текстовый `.dat` (как MaxScript `SetCamera.ms`): ключи FOV, позиция камеры и позиция цели.

**Где:** View3D → Sidebar (N) → GTA Tools → **Анимации** (вкладка Персонаж) → бокс **Камера (катсцена .dat)** → **Импорт** / **Экспорт**.

- **Импорт** строит связку **Camera + Empty («…​.Target»)** со связью Track To и вставляет ключи позиции/цели/FOV (FOV пишется в `data.angle`, вертикальный sensor_fit). Есть опция **Z-offset −1.0** (обход Z-бага движка, как в оригинальном скрипте).
- **Экспорт** требует камеру с целью (Track To / Empty с суффиксом `.Target`), **fps = 30** и ≥2 ключей позиции у камеры и у цели. Пишет 4 блока (FOV / Roll-заглушка / позиция / цель), добивает хвост нулями до кратности 2048.

Источник: [`ops/camera_io.py`](INU_tools/ops/camera_io.py) → `import_camera_dat`, `export_camera_dat`.

### Handsign / ghands.ifp

Авторинг жестов банды GTA SA. Знак банды = **три** отдельных скелета/анимации в одном `ghands.ifp`: поза рук на скелете игрока (`gsignN` / `gsignNlh`), пальцы левой кисти `shandl` (`lhgsignN`) и правой `shandr` (`rhgsignN`).

**Где:** View3D → Sidebar (N) → GTA Tools → **Анимации** (вкладка Персонаж) → бокс **Handsign Tools**. Строка статуса показывает найденные скелеты (ped · L · R).

- **Прицепить кисти** — вешает Copy Transforms на кости кистей (предплечье/запястье кисти следуют за костями игрока), чтобы кисти ездили за рукой во вьюпорте при анимации. Кисти остаются отдельными armature; пальцы не связаны — их анимируешь сам.
- **Отцепить** — снимает все привязки Handsign (ничего не удаляет).
- **Экспорт жеста → ghands.ifp** — берёт активную Action каждого из трёх скелетов и вливает блоки в `ghands.ifp` одним merge (совпавшие по имени блоки заменяются, вся ваниль остаётся байт-в-байт). Имя Action = имя блока в IFP (`gsign6` / `lhgsign6` / …). Формат по умолчанию **ANP3** (родной SA), вне SA — ANPK; бэкфилл каноничных `bone_id` по имени кости.

Источник: [`ops/handsign_ops.py`](INU_tools/ops/handsign_ops.py) → `GTATOOLS_OT_handsign_attach`, `GTATOOLS_OT_handsign_export`.

### Панель GTA Material

**Где:** Properties → Material → панель *GTA Material*.

**Пресеты (4 кнопки):**

### Alpha-материалы (массовая прозрачность)

Карты GTA содержат сотни alpha-cutout материалов (заборы, листва, окна). Править им режим прозрачности по одному в родной панели материала утомительно — этот инструмент сканирует сцену (или выделение), собирает альфа-материалы в список и меняет режим прозрачности **сразу у всех** + выделяет объекты, которые их используют.

**Где:** Properties → Material → панель *GTA Material* → вкладка **Альфа**.

- **Область** — вся сцена / только выделенные.
- **Режим фильтра** — что считать альфа-материалом (некоторые альфа-текстуры не должны быть прозрачными, поэтому это выбор, а не догадка): **NODE** (вход Alpha у Principled реально подключён, по умолч.) · **CHANNEL** (у базовой текстуры значимый альфа-канал) · **TRANSPARENT** (режим смешивания уже не Opaque) · **ALL** (любое из).
- **Обновить** — пересобрать список; у каждой строки — свой дропдаун режима (Opaque / Clip / Hashed / Blend).
- **Режим для всех** + **Применить ко всем** — задать один режим сразу всем материалам списка. Любой прозрачный режим также выключает «Перекрытие прозрачности» — это единый стандарт прозрачности проекта. Пишутся оба свойства (`blend_method` и `surface_render_method` 4.2+), так что применяется и на EEVEE Legacy, и на EEVEE Next.
- **Выделить объекты** — выделить меши, использующие материалы из списка.

Источник: [`ops/alpha_tools.py`](INU_tools/ops/alpha_tools.py) → `draw_alpha_tools`, `GTATOOLS_OT_alpha_scan`, `GTATOOLS_OT_alpha_apply_all`.

### Менеджер текстур (Bitmaps Manager)

Утилиты управления текстурами и материалами в одной панели: поиск недостающих файлов, resolve из папки, batch-копирование, дубликаты, очистка неиспользуемого, плюс операции над материалами (check/cleanup/sort).

**Где:** View3D → Сайдбар (N) → GTA Tools → панель *Менеджер текстур*.

**Layout:** компактные 3 строки:

| Строка | Содержимое |
|---|---|
| **Сканировать** + бейдж `Пропущено: N` | главный entry-point — статус «сколько файлов не находится» |
| **Текстуры ▾** + бейдж `Неисп: I/M` | dropdown с 5 операциями (см. ниже). Бейдж `I/M` = unused images / unused materials |
| **Материалы ▾** | dropdown с 3 операциями над материалами |

**Дропдаун «Текстуры»:**
- **Найти в папке…** — рекурсивно обходит папку, матчит по basename (с расширением или без), патчит `image.filepath` и делает reload.
- **Скопировать в папку…** — копирует все используемые хотя бы одним материалом текстуры в целевую папку. Опция **Subfolder per TXD** создаёт `target/{txd_name}/texture.png` (обходит мешей и читает `obj.inu.txd_name`).
- **Найти дубликаты** — MD5-хэширует каждый файл текстуры, выводит группы идентичных файлов в System Console.
- **Найти неиспользуемые** — сканирует `bpy.data.images` и `bpy.data.materials` на orphan'ы (нет users в сцене). Бейдж `Неисп: I/M` обновляется.
- **Удалить неиспользуемые…** — destructive action: удаляет ранее найденные orphan'ы (popup с подтверждением).

**Дропдаун «Материалы»:**
- **Проверка материалов** — лог в System Console: материалы без текстуры, с дублями, конфликтами эффектов.
- **Очистка материалов** — удаляет orphan slots, мерджит дубли, нормализует имена.
- **Сортировка материалов** — алфавитная сортировка material slots в активном объекте (для предсказуемого порядка в DFF).

Источник: [`tools/bitmaps_manager.py`](INU_tools/tools/bitmaps_manager.py).

### CST IO

Текстовая сериализация данных COL-коллизии, совместимая по духу со Steve's COL Editor. Альтернатива бинарному `.col` для ручного редактирования или diff'а.

**Где:** CST работает только через галочку **CST** в диалогах Импорт/Экспорт (пишется/читается вместе с моделью) и через перетаскивание `.cst`-файла во вьюпорт (drag&drop). Отдельных операторов импорта/экспорта CST больше нет.

**Формат:** построчный, одна директива на структуру. Поддерживается несколько MODEL-блоков в файле.
```
MODEL my_col
ID 1234
VERSION 3
BOUNDS 0 0 0 5.0 -2 -2 -2 2 2 2
SPHERE 0 0 1 0.5  0 0 0 0
BOX -1 -1 0 1 1 2  0 0 0 0
VERTEX 1.0 2.0 0.0
FACE 0 1 2  0 0 0 0
SHADOW_VERTEX 0 0 0
SHADOW_FACE 0 1 2  0 0 0 0
END
```

Каждый `SPHERE` / `BOX` / `FACE` заканчивается 4 токенами поверхности: `material flags brightness light`. Всё после `#` — комментарий.

Источник: [`core/cst.py`](INU_tools/core/cst.py), [`ops/cst_import.py`](INU_tools/ops/cst_import.py), [`ops/cst_export.py`](INU_tools/ops/cst_export.py).

### Vehicle Scale Helper

Пропорциональное масштабирование всей иерархии машины (Empty-корень + меши + дамми-дети) с сохранением структуры для DFF-экспорта.

**Где:** View3D → Сайдбар (N) → GTA Tools → панель *Машины* → кнопка **Масштаб машины…** (также доступен как оператор `gtatools.vehicle_scale` для скриптов).

**Опции:**
- **Factor** — множитель равномерного масштаба
- **Dummies Only** — если включено, двигаются только дамми-Empty, вершины мешей остаются в прежнем размере

**Что делает:** обходит иерархию DFS, умножает `obj.location` каждого объекта на factor, сбрасывает `matrix_parent_inverse` в identity, применяет `Matrix.Scale(factor)` к данным меша (копирует shared-меши) и Armature, сбрасывает `scale` в `(1,1,1)` на каждом объекте. Empty display size тоже масштабируется.

Источник: [`tools/vehicle_scale.py`](INU_tools/tools/vehicle_scale.py).

### Vehicle Damage Variants

Управление парами `_ok` / `_dam` атомиков кузова машины. Движок GTA SA автоматически переключает видимый меш между двумя вариантами при повреждении панели — единственный контракт это naming convention: атомик с суффиксом `_ok` и атомик с суффиксом `_dam` (с одинаковым префиксом) образуют пару, например `bonnet_ok` ↔ `bonnet_dam`, `door_lf_ok` ↔ `door_lf_dam`.

**Где:** View3D → Сайдбар (N) → GTA Tools → панель *Машины* → блок **Damage variants**.

**Операторы:**

| Кнопка | Что делает |
|---|---|
| **Создать _dam** (`gtatools.vehicle_add_damage_variant`) | Дублирует данные активного меша в новый объект `<base>_dam`, парентит к тому же Empty что у источника. Если у источника нет суффикса `_ok` / `_dam`, он автоматически переименовывается в `<имя>_ok`. Новый `_dam` получает `hide_viewport=True`, чтобы по умолчанию пользователь видел OK-состояние — DFF-экспорт обходит всю иерархию независимо от viewport-флага, поэтому вариант всё равно попадает в `.dff`. |
| **Показать OK / Dam / Оба** (`gtatools.vehicle_show_damage`) | Переключает `hide_viewport` для каждого `_ok` и `_dam` меша в иерархии активного объекта (или по всей сцене если активного нет). `OK` показывает `_ok`, скрывает `_dam`. `Dam` показывает `_dam`, скрывает `_ok`. `Оба` показывает всё (полезно для дебага). Влияет только на viewport — DFF-экспорт не трогает. |
| **Проверить пары** (`gtatools.vehicle_pair_report`) | Обходит активную иерархию и пишет в системную консоль: парные `_ok+_dam` меши, одиночные `_ok` (без пары `_dam`), одиночные `_dam` (без пары `_ok`). В статус-баре отчитывается сводкой; если есть одиночные — уровень `WARNING`. У одиночных частей не будет повреждённого варианта в игре (движок ищет пару при загрузке). |

**Туториал — повреждение капота:**

1. Смоделируй целый капот, назови меш `bonnet_ok`. Поставь его под Empty `bonnet_dummy` для трансформа петли.
2. Выдели `bonnet_ok` → нажми **Создать _dam**. Появится новый меш `bonnet_dam` той же формы, скрытый во viewport.
3. Нажми **Показать Dam** → OK-меш скрывается, повреждённый становится видимым. Отредактируй меш (придави вершины внутрь, добавь вмятины).
4. **Показать OK** для быстрого сравнения. **Показать Оба** если хочешь видеть оба меша одновременно (удобно сохранять консистентный силуэт).
5. Запусти **Проверить пары** — должно отчитаться `1 пара, 0 одиночных`. Добавь `door_lf_ok`/`_dam`, `boot_ok`/`_dam`, повтори.
6. Экспортируй DFF как обычно — оба варианта поедут в `.dff`. В игре движок переключает их по здоровью компонента.

**Заметки:**
- Hide-on-create действует только на viewport (`hide_viewport`). Render-флаг не трогается, поэтому коллекционные экспортёры (Map Export, Export to IMG) не теряют вариант.
- Используй **Показать OK** перед экспортом, если нужен чистый превью-скриншот DFF — `_dam` меши обычно косметически уродуют кадр.
- `wheel_*` и `*_dummy` Empty в ванильном SA не имеют damage-варианта — только крашенные кузовные части (chassis, двери, капот, бамперы, лобовое стекло, mudguards, багажник) идут с парами `_ok` / `_dam`.

Источник: [`tools/vehicle_scale.py`](INU_tools/tools/vehicle_scale.py) → `_strip_damage_suffix`, `find_damage_pairs`, `GTATOOLS_OT_vehicle_add_damage_variant`, `GTATOOLS_OT_vehicle_show_damage`, `GTATOOLS_OT_vehicle_pair_report`.

### Train Station Markers

### Roadblocks & Traffic Lights

**Где:** Edit Curve mode на кривой с `path_type == 'path_ipl'` → оператор `gtatools.path_node_flag` с действиями:

Работает на отфильтрованных точках сплайна, но пишет в оригинальные IDProp-слоты (которые включают empty-padding ноды из формата 12-на-группу в IPL).

### FLA4 Path Format

Расширенный формат `nodes*.dat` от Fastman Limit Adjuster 4. Добавляет 12 байт на path-ноду (spawn probability, speed limit в км/ч, lane count override) поверх ванильной 28-байтной структуры, итого 40 байт на ноду.

**Детекция:** файл считается FLA4 если начинается с ASCII-магии `FLA4`. Layout счётчиков и смещений в остальном идентичен ванильному.

**Где:** File → Export → *Export Path Nodes* → чекбокс **FLA4 Format**. Импорт определяет автоматически.

Источник: [`core/paths.py`](INU_tools/core/paths.py) → `FLA4_MAGIC`, `FLA4_PATH_NODE_SIZE`, FLA4-ветки в `read_nodes` / `write_nodes`; [`ops/path_export.py`](INU_tools/ops/path_export.py) → `export_nodes(..., fla4=True)`.

### Модули ядра

#### dff.py — RenderWare DFF
Чтение/запись бинарных RW потоков. Поддерживает: Clump, Frame List, Geometry List, Geometry (вершины, нормали, UV, vertex colors), Material List, Material, Texture, Atomic, **Skin PLG** (веса костей), **2DFX PLG** (Light / Particle / Ped Attractor / Sun Glare), **BinMesh PLG**, **MatFX PLG** (env map / bump / reflections), **UV Animation Dictionary** (chunk 0x2B), **Native Data PLG** (mobile геометрия), **HAnim PLG** (bone hierarchy), **breakable objects** (chunk 0x253F2FD). Round-trip сохраняет не-Clump первые чанки.

#### col.py — Формат коллизий
Поддержка COL1, COL2, COL3 (стандарт GTA SA), COL4. Чтение/запись: полигоны, вершины, группы, **сферы**, **боксы** (через empties с `display_type='CUBE'`), свойства поверхностей (материал, флаги, яркость, day/night light nibbles).

#### txd.py + dxt.py — Текстуры
Pure-numpy DXT1/BC3 энкодер/декодер (~7× быстрее старого энкодера). Форматы: DXT1, DXT3, DXT5, RASTER_8888, RASTER_888 (32-bit BGRX), RASTER_565, RASTER_1555, RASTER_4444, PAL8. Платформа: D3D8/D3D9. Опциональный `dxt_gpu.py` для compute-shader пути.

#### txd_mobile.py — Mobile TXD контейнер
Детект 4-файлового мобильного контейнера (`.pvr` / `.etc` / `.dxt` + `.txt` / `.toc` / `.dat` / `.tmb`). Pixel-декодирование делегировано TxdGen (нет in-tree PVRTC/ETC1 кодека).

#### ide.py + ide_flag_translate.py — Item Definition
Все секции: objs (статика), tobj (time-based), anim (анимированные), cars (транспорт), peds (пешеходы), weap (оружие), hier (иерархия), txdp (TXD-родители). Per-game перевод бит флагов в `ide_flag_translate.py` — один логический флаг (например "drawlast") имеет разные битовые позиции в III/VC/SA.

#### ipl.py — Item Placement
Все секции: inst (экземпляры), cull (zones), grge (гаражи), enex (input/exit), pick (pickups), cars (припаркованные), auzo (audio zones), jump (трюковые прыжки), occl (occlusion), tcyc (time cycle), zone (zones). Поддерживает **текстовый** и **бинарный** IPL (`bnry`). FLA `real_interior` (12-я колонка) опционально.

#### img.py — IMG архивы
v2 (GTA SA) и v1 (GTA III/VC). Context manager `ImgReader` для быстрого sequential чтения. Функции: `read_directory`, `extract_file`, `replace_or_add`, `remove_file`, `create_img`. Sector-aligned (2048 байт).

#### ifp.py — Анимации
Три суб-формата: **ANP3** (SA), **ANPK** (III/VC), **ANP2** (custom). `source_format` сохраняется при round-trip. KF time канонически в **секундах**; импортёр конвертирует.

#### paths.py — Данные путей
- `paths.ipl` — vehicle/pedestrian path текстовый формат
- `tracks.dat` — ж/д пути
- `nodes*.dat` — скомпилированные бинарные path nodes (vehicle / ped / navi) с FLA4 расширением и структурированным `navi_links` / `link_lengths` / `path_intersections` post-link tail

#### fxp.py — Particle Effects File
Pure-text effects.fxp парсер. Иерархия dataclass: `FXFile → FXSystem → FXEmitter → FXInfoBlock`. Кривые хранятся как `FXCurve` с piecewise-linear `sample(t)`. CRLF output сохраняется. `load_cached(path)` с invalidation по mtime.

#### water.py — water.dat
Quad-определения с per-vertex flow speed (X/Y/Z) и water type (0–3). MTA round-trip совместим.

#### gta_dat.py — Game Data
Парсинг `gta.dat`, `gta_int.dat`, `default.dat`. Извлекает пути IDE/IPL/IMG в порядке объявления. `extract_regions()` возвращает имена папок из MAPS для динамического region filtering.

#### game_versions.py — Multi-game детект
Детектит III / VC / SA по сигнатурам контента (RW версия, IPL header markers, IDE column counts). `game_of_scene(scene)` возвращает активную игру; `game_of_file(path)` для stand-alone детекта.

#### file_lint.py + lint_profile.py + map_lint.py — Линтинг
- `file_lint.py` — on-disk DFF/COL/TXD сканер; выдаёт `LintIssue(code, severity, file, message)` записи.
- `lint_profile.py` — STANDARD / FLA / STRICT / LENIENT профили переопределяют дефолтные пороги + post-filter issues по code/severity.
- `map_lint.py` — cross-file IDE↔IPL валидатор (висячие ссылки, дубликаты ID, IMG cross-verify).

#### vc_layers.py — Vertex Color Layers
Pure-logic naming и composite math (Photoshop-style layers). `recompose_stack(mesh, scope)` блендит `VCL_<scope>_*` слои в `Day` / `Night` базовые атрибуты.

#### rwbinary.py — RenderWare Chunk Helpers
Low-level утилиты для dff/txd/col writer'ов: chunk header pack/unpack, выравнивание, RW version encoding.

#### validate.py — Pre-export Sanity Checks
Нормализация кватернионов, проверка paintjob `_ok ↔ _dam` пар, конфликт UV-аним × ночные vcol (ночные цвета отключают UV-анимацию в ретейл SA), детект дубликатов model_id.
